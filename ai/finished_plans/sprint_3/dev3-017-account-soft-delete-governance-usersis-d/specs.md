## 1. Executive Summary & Problem Statement

- **Feature**: Complete Workflow 05 §5 ("Soft Delete Governance" — the four-state account lifecycle `Active ⇄ Suspended / Blocked / Soft_Deleted`). The Admin gains two audited, fail-closed, single-statement governance transitions — **suspend with a period window** (`suspended`/`suspended_at`/`suspended_period_days`) and **block** (`is_blocked`/`blocked_at`) — layered onto the ALREADY-SHIPPED soft-delete/reactivate surface; the platform's auth boundaries (login, token refresh, SSR page guards) become **suspension-window-honest**: an ACTIVE suspension denies access, a lapsed suspension restores it (read-only evaluation, zero writes on the auth path), and a blocked or soft-deleted account never regains access except through an audited admin action. Every transition appends exactly ONE in-transaction `audit_logs` row; every denial appends ZERO.
- **Problem from user perspective**:
  - **Super Admin (platform orchestrator)**: needs the FULL governance surface Workflow 05 §5 promises — today he can delete/reactivate (shipped) but CANNOT suspend a misbehaving account for N days or hard-block a violator; the state machine's two middle states have no writer. He also needs each action justified in the immutable trail (A.5 / FR-10.5).
  - **Suspended Student/Teacher**: suspension is a TIME-BOXED disciplinary hold (`suspended_period_days`); when the window lapses he MUST regain access (Workflow 05 §5.2: `Suspended → Active` on expiry) — without this ticket's window-honest auth, the current fail-closed-on-`suspended=true` login (`auth.service.ts:91-98`, documented as stricter-than-contract in `docs/auth/jwt-authentication-service.md` §5.3) would leave a lapsed-suspension user locked out forever absent admin intervention.
  - **Blocked user**: severe-violation hold with NO expiry semantics — denied until an admin unblocks (INV-U3 reads access denial for the platform).
  - **Soft-deleted user**: historical data (sessions, reports, financial rows) is preserved and access stays denied (INV-U1/INV-U4/INV-U5) — SHIPPED by DEV3-016; this ticket LOCKS, never re-opens it.
  - **Non-admin roles (Student/Teacher/Parent)**: must NEVER hold a governance write path (BFLA).
  - **Observer Admin / audit consumer (DEV3-020)**: every transition is visible in the trail with honest actor attribution.
- **Business value**: ships the M3 DoD row "Admin can soft-delete accounts" AND Workflow 05 §5's complete four-state governance lifecycle; makes the pre-provisioned `AuditActionType.Suspend` member real; closes the documented jwt-auth deferral ("assertNotSuspended active-window calculation") at the AUTH layer without touching session-creation gating; the suspension window stops being a write-only decoration.
- **Actors involved**: **Super Admin A** (caller — `ctx.user.id` is the ONLY actor source); **target user S** (governed; observes via login/access); **observer Admin B** (reads trail + detail); **non-admin denial probes**; **downstream consumers** (session-creation gating will consume the shared predicate — forward pointer only; DEV3-020's audit browser reads the rows).

### 2.2 Core Feature Logic / Happy Paths

- **REQ-010 (Suspend Transition — Guarded, Windowed, Audited)**: WHEN an active admin suspends a target via the new surface THEN the system SHALL, inside ONE transaction: (a) execute a SINGLE guarded `UPDATE users SET suspended = true, suspended_at = now(), suspended_period_days = <periodDays>, updated_at = now() WHERE id = $1 AND (suspended = false OR suspended IS NULL) AND (is_deleted = false OR is_deleted IS NULL) RETURNING <SAFE_USER_SELECT>`; (b) append EXACTLY ONE `audit_logs` row via `AuditService.createAuditLog({ actorId, actionType: AuditActionType.Suspend, entityType: "user", entityId: <targetId>, details }, tx)` where `details` carries field NAMES + metadata only (e.g. `{ changedFields: ["suspended","suspendedAt","suspendedPeriodDays"], suspended: true, suspendedPeriodDays }` — NEVER PII); (c) return the post-write admin detail via the EXISTING `getUserDetail` composition inside the same tx. `periodDays` SHALL be mandatory on the suspend direction: a positive integer in `1..3650`, else `ValidationError` with `fields[]` naming `periodDays` BEFORE any DB access.
- **REQ-011 (Unsuspend Transition + Block/Unblock Transitions — One Audit-Vocabulary Mapping, Zero Enum Drift)**: WHEN an admin UNSUSPENDS a target THEN the guarded update SHALL require `suspended = true` and SHALL clear ALL THREE columns (`suspended = false`, `suspended_at = NULL`, `suspended_period_days = NULL`) and append ONE `AuditActionType.Reactivate` row (`details: { changedFields: …, suspended: false }`). WHEN an admin BLOCKS or UNBLOCKS a target THEN the guarded update SHALL set/clear `is_blocked` + `blocked_at` under the analogous predicate, and the audit row SHALL use `AuditActionType.Suspend` for the BLOCK direction and `AuditActionType.Reactivate` for the UNBLOCK direction with `details` naming the exact fields (`{ changedFields: ["isBlocked","blockedAt"], blocked: true|false }`). RATIONALE (recorded, binding): the `audit_action_type` pgEnum has NO `block` member and this ticket ships ZERO schema drift; governance-HOLD directions map to `Suspend` and RELEASE directions map to `Reactivate`, with `details.changedFields` carrying the honest field identity so DEV3-020's audit browser can distinguish them — a future audit-vocabulary widening is a separate governed decision, never a silent patch.
- **REQ-012 (Self-Protection)**: WHEN the target id equals the acting admin's id (`id === actorId`) on EITHER direction of EITHER mutation THEN the system SHALL reject BEFORE any write with `ConflictError("USER_SELF_SUSPENSION_FORBIDDEN", …)` / `ConflictError("USER_SELF_BLOCK_FORBIDDEN", …)` respectively — zero rows mutated, ZERO audit rows (mirrors the DEV3-016 `USER_SELF_DEACTIVATION_FORBIDDEN` pattern at `user-management.service.ts:988-996`).
- **REQ-013 (State-Conflict Classifier — Zero-Row Disambiguation)**: WHEN a guarded update returns ZERO rows THEN the service SHALL disambiguate via ONE in-tx governance probe read (`GovernanceProbeRowType | null` — the REQ-003 five-column projection): probe `null` → `NotFoundError("USER", …)` (`USER_NOT_FOUND` — the admin-surface-only oracle ruling, `docs/admin/user-management.md` §4; the doc forbids copying it to non-admin surfaces); probe `isDeleted = true` → `ConflictError("USER_ALREADY_DELETED", …)` (uniform rule: governance holds are placed ONLY on live accounts — a soft-deleted record is read-only for governance until reactivated); target-axis already in the requested state → `ConflictError("USER_ALREADY_SUSPENDED" | "USER_NOT_SUSPENDED" | "USER_ALREADY_BLOCKED" | "USER_NOT_BLOCKED", …)` per direction. SELECT-then-UPDATE is PROHIBITED; the classifier is the only read after the guarded write.
- **REQ-014 (Deleted-Target Uniformity / Axis Independence)**: WHEN blocking an already-suspended target OR suspending an already-blocked target THEN the operation SHALL succeed (the suspension and block axes are INDEPENDENT per A.7's column model and Workflow 05 §5.3's per-state field map); WHEN soft-deleting a suspended or blocked target THEN the EXISTING DEV3-016 path SHALL keep working unchanged; WHEN suspending OR blocking (either direction) a soft-deleted target THEN the ONLY answer SHALL be `USER_ALREADY_DELETED` (REQ-013).
- **REQ-015 (Minimal Writable Footprint / Cross-Role Containment)**: WHEN any of the four transitions commits THEN it SHALL write ONLY its axis columns on `users` (+ `updated_at`) + ONE `audit_logs` row — NEVER touching email/role/passwordHash, NEVER touching `students`/`applicants`/`teacher`/`parents` rows, balances, subscriptions, payments, sessions, evaluations, or parent links (INV-U1/INV-U5 preservation; REQ-035 cross-role containment per `docs/admin/user-management.md`) — proven by byte-identical fixture-immutability probes.
- **REQ-016 (No Silent Extension)**: WHEN an admin suspends an already-suspended target THEN the answer SHALL be `USER_ALREADY_SUSPENDED` — a period EXTENSION is expressible ONLY as an explicit audited unsuspend + re-suspend pair (two auditable steps, never a silent in-place extension).
- **REQ-017 (Shared Suspension-Window Predicate — Fail-Closed, Extracted)**: WHEN suspension liveness is evaluated THEN it SHALL flow through ONE shared pure predicate — NEW `backend/lib/auth/suspension-window.ts` exporting `isSuspensionActive(state: { suspended: boolean | null; suspendedAt: Date | null; suspendedPeriodDays: number | null }, now: Date): boolean` with EXACTLY these semantics (extracted from `isGovernanceExcludedFromDiscovery`, `backend/services/students/student-handshake.helpers.ts:39-59`): `suspended` falsy → `false`; `suspendedAt` missing OR `suspendedPeriodDays` missing OR `≤ 0` → `true` (fail-CLOSED — corrupt window data never widens access); otherwise active IFF `suspendedAt + suspendedPeriodDays × 86_400_000 > now` (STRICT `>` — a window ending exactly at `now` has LAPSED).
