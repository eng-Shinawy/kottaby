## 1. DEVIATION NOTE (CRITICAL — read before Phase 2.2)

The plan's `tasks.md` (Task 1.4, lines 113–120) and `plan.md` (§2 i18n section, lines 117–127) specify adding a **NESTED** `studentTrial: { trialAlreadyGranted: string }` grouping to the `ErrorsLabels` interface, accessed via `errorsTranslations.studentTrial.trialAlreadyGranted`.

**This is structurally incompatible with the actual codebase.** The real `ErrorsLabels` interface in `shared/locale/types/errors/index.ts` is **FLAT** — every field is top-level (e.g., `unauthorized`, `conflict`, `duplicateRequest`, `applicantNotFound`, `applicantCooldownActive`, `applicantStatusCorrupt`). No nested groupings exist anywhere in the interface. The existing `errorsEn`/`errorsAr` objects mirror this flat structure exactly.

**The CORRECT approach (executed here)** is to add a **flat top-level field** `trialAlreadyGranted: string` directly on `ErrorsLabels`, matching the existing flat convention. This preserves the semantic intent of the plan (a localized error message accessible via property access on the `errorsTranslations` object) while complying with the codebase's actual structural contract.

**Rationale**:
- Structural compatibility — the existing interface would not compile with a nested object literal unless `errorsEn`/`errorsAr` were also re-shaped; that re-shape would break every existing property-access site and is out of scope for this task.
- Convention parity — all other domain-specific keys (`applicantNotFound`, `applicantCooldownActive`, `applicantStatusCorrupt`) are flat fields with domain-behavior JSDoc. The new field follows the same pattern.
- Type-safety preserved — the field is still type-checked at compile time, property access still resolves, and the locale-contract parity between `errorsEn` and `errorsAr` is enforced by the single `ErrorsLabels` interface.
- No namespace registration needed — the `errors` namespace already exists on the `Translations` interface as `errorsTranslations: ErrorsLabels` (in `shared/locale/types/message.ts`); the new flat field is automatically included.

## 7. Carry-Forward Knowledge for Phase 2.2 (Service Code)

**CRITICAL**: The service code shown in `plan.md` §4 (lines 180–182) is **WRONG**. The plan shows:

```ts
// ❌ WRONG — plan.md text
const tErrors = await getServerTranslations(locale, "errors");
throw new ConflictError(tErrors.studentTrial.trialAlreadyGranted);
```

This is incorrect on three counts:
1. `getServerTranslations` takes a **single argument** (`locale`), not two — see `shared/locale/server-graphql.ts`.
2. `getServerTranslations` is **synchronous** (returns `Translations`, not `Promise<Translations>`) — `await` is unnecessary (harmless but misleading).
3. `tErrors.studentTrial.trialAlreadyGranted` assumes a NESTED `studentTrial` grouping that does **NOT** exist on the flat `ErrorsLabels` interface.

**The CORRECT service code** (use this exact pattern in Phase 2.2 — `backend/services/students/student-trial.service.ts`):

```ts
// ✅ CORRECT — use this in Phase 2.2
import { getServerTranslations } from "@/shared/locale/server-graphql";
import { ConflictError } from "@/backend/lib/errors";

// inside StudentTrialService.grantFreeTrial:
if (!granted) {
  const translations = getServerTranslations(locale);
  throw new ConflictError(translations.errorsTranslations.trialAlreadyGranted);
}
```

Key facts for Phase 2.2:
- `getServerTranslations(locale: string): Translations` — single-arg, synchronous.
- Access pattern: `translations.errorsTranslations.trialAlreadyGranted` (property access; no function call; no nested `studentTrial` group).
- Field name on `Translations`: `errorsTranslations` (NOT `errors`).
- `ConflictError` is imported from `@/backend/lib/errors` (the flat `errors.ts` module that resolves OVER the same-named `errors/` directory — see Phase 0.2 outcome §1.4).
- The `ConflictError` subclass automatically sets `extensions.code = "CONFLICT"` (verified in Phase 0.2 outcome).
- Per REQ-052, the service MUST also call `logger.logDomainError` from `@/backend/lib/logger` BEFORE throwing (with entity=`students`, entityId, attempt context); `console.*` is prohibited.
