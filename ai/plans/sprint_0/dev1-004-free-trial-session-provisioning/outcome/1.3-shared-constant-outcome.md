```ts
/**
 * Free trial session provisioning sizing constant.
 *
 * Number of free trial sessions granted once to each newly registered student.
```

### 7.1 Import paths (both verified working — probe §3.4)

Phase 2.2 service code (`backend/services/students/student-trial.service.ts`) should use the deep-import form. Phase 2.1 repo method (`backend/db/repo/students/student.repository.ts`) should **NOT** import the constant directly — the service passes it as a `trialCount` parameter (per `plan.md` §4 signature: `grantFreeTrialOnce(studentId, trialCount, tx?)`). This preserves the "single source of truth + single provisioning implementation" intent (REQ-017).

### 7.2 Value and type facts

- **Compile-time value**: `1` (integer literal — TypeScript narrows the inferred type to the literal `1`, widened to `number` at use sites).
- **Runtime value**: `1` (number) — verified by the importability probe (§3.4).
- **SQL-safety**: the value is safe to inline directly inside Drizzle `sql\`\`` template arithmetic expressions, because it is a stable compile-time integer with no env var lookup and no `Date`/object identity concerns. Phase 2.1's repo method will use the pattern:
  ```ts
  balanceTrial: sql`${students.balanceTrial} + ${trialCount}`,
  ```
  where `trialCount` is the parameter bound to `FREE_TRIAL_SESSION_COUNT`. The bound parameter is the integer `1` at the call site — Drizzle renders this as a `$1` placeholder, NOT an inlined literal. Safe from SQL injection (it is a server-derived integer constant, never client input — BOPLA/REQ-031 compliant).

### 7.3 Anti-pattern reminders (BOPLA / REQ-031)

- The constant is **compile-time only** — there is NO env var lookup, NO admin-secret surface, NO client-overridable path. Phase 2.2 service code MUST NOT add a fallback like `process.env.TRIAL_COUNT ?? FREE_TRIAL_SESSION_COUNT` — the shared constant is the single source of truth.
- Phase 2.2 service code MUST NOT accept a `trialCount` parameter from any caller — the constant is read directly inside the service (the service is the single canonical provisioning entry point per REQ-017).
- Phase 2.1 repo method MUST accept `trialCount` as a parameter (so the repo remains policy-free and reusable for future flows that may pass different counts — e.g., admin mercy grants in a future ticket). The repo must NOT import the constant directly.

### 7.4 Test assertions (for Phase 2.2.TE role-matrix suite)

The role-matrix test (REQ-072) will assert:
