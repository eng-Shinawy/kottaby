### 7.5 BFLA verdict

Low-privilege tokens (anonymous / student / parent / teacher) have **no function path** to mint trial credits:

1. **Schema layer**: there is no Query or Mutation field that grants, tops up, or manipulates `balance_trial`. The only mutation that touches a student record at all is `registerUser`, and its mutation contract returns the unchanged `User` shape (no balance fields surfaced) per REQ-023/REQ-060.
2. **Service layer**: the grant is invoked ONLY inside `RegistrationService.registerUser` for `role = student`, via `StudentTrialService.grantFreeTrial(userId, locale, tx)`. The grant is unconditional inside that one call site; there is no parameter by which the caller can influence the grant amount (`FREE_TRIAL_SESSION_COUNT` is a shared constant), the target identity (`studentId` is derived from the freshly inserted `users.id` per REQ-032 — never client-supplied), or the trigger condition (role dispatch happens server-side; the `RegisterPublicRole` enum excludes `admin`).
3. **Repository layer**: `StudentRepository.grantFreeTrialOnce` is a single guarded `UPDATE … WHERE id = $1 AND trial_granted_at IS NULL` — the only mutation primitive (REQ-012/REQ-042). There is no admin-facing repo method that re-grants, top-ups, or resets the trial.

REQ-030 PASS — BFLA holds structurally.

## 8. Step 8 — Forward-Exposure Contract Note (REQ-062, recorded verbatim)

> **Any future exposure of `balanceTrial`/`trialGrantedAt` MUST land on the canonical `StudentPothosObject` with an `id` field for Apollo cache normalization, use `t.loadable()`/batch service methods per `docs/graphql/dataloader-batching.md`, and import server types from `@/backend/types` — never a local Pothos type.**

### 8.1 Normative references that the future UI/exposure ticket MUST honour

- `backend/graphql/AGENTS.md` §"Single Canonical Object Type Pattern" — one canonical object per entity, `objectRef<{Entity}ReturnType>("<Entity>")`, no local type definitions.
- `backend/graphql/AGENTS.md` §"Cache Updates" — `id` fields MUST always be exposed on GraphQL objects for Apollo auto-normalization.
- `docs/graphql/dataloader-batching.md` — `t.loadable()` pattern + batch service methods (e.g., `StudentRepository.findByIds(ids): Promise<Map<id, StudentSelectType>>`) to avoid N+1 resolution when student lists expose `balanceTrial`.
- `backend/graphql/AGENTS.md` §"Pothos Enum Registration Pattern" — if a `TrialState` enum is introduced (e.g., `GRANTED | CONSUMED | NONE`), it MUST be defined as a real TypeScript enum in `backend/enum/` and registered once in `backend/graphql/pothos/shared/enum.pothos.ts`; no inline literal arrays.
- `@/backend/types` — server entity types (`StudentSelectType`, `StudentReturnType`) flow through `$inferSelect`/`$inferInsert`; the two new columns (`balance_trial`, `trial_granted_at`) are already auto-flowed by Phase 1.1, so a future `StudentPothosObject` would expose them with no `.types.ts` change required.

### 8.2 Non-normative implementation guidance for the future exposure ticket

- The `id` field on `StudentPothosObject` SHOULD be the `users.id` foreign key on the `students` row (the `students.id` integer primary key is also acceptable, but using `users.id` keeps Apollo cache keys consistent with the existing `User` type's `id` field — Apollo cache normalization works best with a single `id` namespace per entity).
- The `balanceTrial` field SHOULD be non-nullable `Int!` (CHECK constraint `students_balance_trial_check` enforces `>= 0`, and the column is `NOT NULL DEFAULT 0`).
- The `trialGrantedAt` field SHOULD be nullable `DateTime` (the column is `TIMESTAMP NULL` — students who haven't been granted yet have `NULL`).
- Authorization: any field exposing `balanceTrial` / `trialGrantedAt` MUST require `authenticated` at minimum, AND the resolver MUST enforce BOLA — a student should only see their own trial balance; a parent should only see their children's; a teacher/supervisor/super_admin should see students they're authorized to view. (The exact auth-scope matrix is owned by the future ticket; this note records the contract only.)
- The exposure ticket MUST register the new operation(s) in `PUBLIC_OPERATION_NAMES` ONLY IF they are designed to be anonymous — otherwise they default to `authenticated` and are NOT added to the public allowlist (per `backend/graphql/AGENTS.md` §"Gateway route & registration contract").
