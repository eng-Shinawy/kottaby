## 1. API CORRECTION NOTE (CRITICAL — read before Phase 2.3)

The plan's `plan.md` §4 (lines 180–182) shows the service error path as:

```ts
// ❌ WRONG — plan.md text
const tErrors = await getServerTranslations(locale, "errors");
throw new ConflictError(tErrors.studentTrial.trialAlreadyGranted);
```

This is incorrect on three counts (verified in Phase 0.2 outcome §5.1 and Phase 1.4 outcome §7):
1. `getServerTranslations` takes a **single argument** (`locale`), not two — see `shared/locale/server-graphql.ts`.
2. `getServerTranslations` is **synchronous** (returns `Translations`, not `Promise<Translations>`) — `await` is unnecessary.
3. `tErrors.studentTrial.trialAlreadyGranted` assumes a NESTED `studentTrial` grouping that does **NOT** exist on the flat `ErrorsLabels` interface (verified by reading `shared/locale/types/errors/index.ts`).

**The CORRECT service code** (used in this task):

```ts
// ✅ CORRECT — used in `backend/services/students/student-trial.service.ts`
const translations = getServerTranslations(locale);
throw new ConflictError(translations.errorsTranslations.trialAlreadyGranted);
```

Key facts:
- `getServerTranslations(locale: string): Translations` — single-arg, synchronous (Phase 0.2 outcome §5.1).
- Access pattern: `translations.errorsTranslations.trialAlreadyGranted` (FLAT — not nested under any `studentTrial` group; Phase 1.4 outcome §1 deviation note documents why the flat field was chosen over the plan's nested shape).
- The `Translations` interface has property `errorsTranslations: ErrorsLabels` (NOT `errors`) — verified by reading `shared/locale/types/message.ts`.
- The `ErrorsLabels` interface is FLAT (no nested groupings); `trialAlreadyGranted` is a top-level `readonly string` field (Phase 1.4 outcome §3.1).
- The `ConflictError` subclass auto-sets `extensions.code = "CONFLICT"` via its constructor (`backend/lib/errors.ts` line 159–163) — no manual extensions assignment needed.

## 3. Implementation Details

### 3.1 Full content of the new service file — `backend/services/students/student-trial.service.ts`

```ts
import type { DBTransaction } from "@/backend/types";
import { ConflictError } from "@/backend/lib/errors";
import { logger } from "@/backend/lib/logger";
import { StudentRepository } from "@/backend/db/repo";
import { FREE_TRIAL_SESSION_COUNT } from "@/shared/constants/free-trial.constants";
import { getServerTranslations } from "@/shared/locale/server-graphql";

/**
 * Student trial provisioning domain service.
 *
 * Owns the one-time free-trial grant: invokes the atomic guarded UPDATE on the
 * students table, logs re-grant attempts as domain errors, and surfaces a
 * localized ConflictError when the grant-once marker is already set. This is
 * the single entry point used by registration today and by downstream student
 * creation flows (failed-applicant conversion, direct admin onboarding) in the
 * future — never call the repository method directly from outside this service.
 */
export namespace StudentTrialService {
  /**
   * Grants the free trial session credit to a student exactly once.
   *
   * The grant is atomic at the SQL level (single conditional UPDATE gated by
   * the trial_granted_at marker). On the happy path this method resolves
   * silently; on a re-grant attempt it logs structured context and throws a
   * localized ConflictError. The caller is responsible for ensuring the
   * studentId is server-derived (the primary key of a freshly inserted
   * students row inside the surrounding transaction).
   */
  export async function grantFreeTrial(
    studentId: number,
    locale: string,
    tx?: DBTransaction,
  ): Promise<void> {
    const granted = await StudentRepository.grantFreeTrialOnce(
      studentId,
      FREE_TRIAL_SESSION_COUNT,
      tx,
    );
    if (!granted) {
      logger.logDomainError("Trial grant rejected: already granted", {
        code: "TRIAL_ALREADY_GRANTED",
        entity: "students",
        entityId: studentId,
        attempt: "1",
      });
      const translations = getServerTranslations(locale);
      throw new ConflictError(translations.errorsTranslations.trialAlreadyGranted);
    }
  }
}
```

### 3.2 Design notes

- **Namespacing**: `export namespace StudentTrialService { ... }` — matches the project's service-layer convention (`ApplicantLifecycleService`, `PermissionsService`, etc.). The single exported method `grantFreeTrial` is the only member. Per `backend/services/AGENTS.md` "Domain-Driven Architecture" + "NO Monolithic Services" rules.
- **Single entry point (REQ-017)**: every flow that creates a `students` row (registration today; DEV2-009 conversion; DEV3-019 direct onboarding in future) MUST route through this method — never call `StudentRepository.grantFreeTrialOnce` directly. The service's JSDoc states this contract explicitly.
- **`tx` propagation (REQ-041)**: the optional `tx?: DBTransaction` parameter is forwarded VERBATIM to `StudentRepository.grantFreeTrialOnce`. The repo's `tx ?? db` fallback handles the no-tx case. The service does NOT introduce its own transaction wrapper — it inherits the caller's transaction (the registration flow's `withTransaction(outerTx)` SAVEPOINT-aware pattern).
- **`FREE_TRIAL_SESSION_COUNT` constant (REQ-014)**: imported from `@/shared/constants/free-trial.constants` (deep import per `shared/AGENTS.md` "Prefer deep imports over barrel files"). The constant is NOT hardcoded in the service. NO env-var fallback (`process.env.TRIAL_COUNT ?? FREE_TRIAL_SESSION_COUNT`) — the shared constant is the single source of truth (Phase 1.3 outcome §7.3 anti-pattern reminder).
- **`ConflictError` extensions.code (REQ-050)**: the `ConflictError` subclass constructor auto-sets `extensions.code = "CONFLICT"` via `super("CONFLICT", message, options)` in `backend/lib/errors.ts` line 161. No manual extensions assignment needed.
- **Localized message (REQ-051)**: `translations.errorsTranslations.trialAlreadyGranted` — property access on the synchronous `Translations` object returned by `getServerTranslations(locale)`. FLAT field name (no nested `studentTrial` group — see §1 API correction note). Never `t("trialAlreadyGranted")` function-call form.
- **Logging contract (REQ-052)**: `logger.logDomainError(message, ctx)` from `@/backend/lib/logger`. Structured context: `{ code: "TRIAL_ALREADY_GRANTED", entity: "students", entityId: studentId, attempt: "1" }`. Mirrors the `createStudentWithHandshakeRetry` log shape (registration.service.ts lines 354–360 — `{ code, entity, entityId, attempt/attempts }`). NEVER `console.*`.
- **Silent-path prohibition (REQ-053)**: NO `try/catch` swallowing on the happy path. The grant is a first-class step — the happy path returns `Promise<void>` (resolves silently); the failure path throws (no silent no-op). The `if (!granted)` branch is reachable ONLY via a re-grant attempt; the happy path logs nothing.
- **DomainError-only throws (REQ-050)**: the service throws only `ConflictError` (a `DomainError` subclass). No `new Error(...)` or `new GraphQLError(...)`. The `logger.logDomainError` call happens BEFORE the throw (so a debugger sees the structured context even if the throw is later caught upstream).
- **No permission gates**: provisioning is system-internal; authorization is enforced at the caller boundary (`registerUser` is the only public entry that triggers the grant; REQ-030/031/032 — BFLA/BOLA/BOPLA defenses are upstream). The service JSDoc does not mention permissions.

### 4.5 Avoided pitfall: unsafe type assertion

The original test for the "undefined locale" case used `undefined as unknown as string` to bypass the service's `string` parameter type. Oxlint's `no-unsafe-type-assertion` rule flagged this. The fix: use empty string `""` (a real `string`) — the harness's `isAppLocale("")` returns false and triggers the same fallback path. This both satisfies the linter AND is more faithful to the production contract (callers always pass a `string`).

### 4.6 Avoided pitfall: super-linear regex

The original "no console.*" test used the regex `/\bconsole\.\w+\s*\(/`. The `sonarjs/super-linear-regex` lint rule flagged it due to potential backtracking on the `\w+\s*` quantifier combination. The fix: simplify to `/\bconsole\./` (word-boundary + literal `console` + literal dot, NO quantifier) — catches all `console.METHOD(...)` calls without any backtracking risk. The comment-stripping regexes were also removed (the service file contains zero `console.*` references in any comment, so a raw source scan is sufficient).
