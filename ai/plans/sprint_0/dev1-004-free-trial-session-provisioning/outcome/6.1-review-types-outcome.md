### 3.4 `StudentSelectType.balanceTrial: number` (not nullable) — inference probe (REQ-003 / REQ-010)

The Drizzle schema column definition (verified by reading `backend/db/schema/students/students.ts:27`):

```ts
balanceTrial: integer("balance_trial").notNull().default(0),
```

`.notNull()` on the Drizzle column builder produces a non-nullable TypeScript type via `$inferSelect`. Since `StudentSelectType = typeof students.$inferSelect`, the inferred field type is:

```ts
type StudentSelectType = {
  // ...
  balanceTrial: number;      // NOT number | null
  trialGrantedAt: Date | null;  // nullable — no .notNull() on the column
  // ...
}
```

Confirmed by the runtime reads in tests:
- `backend/db/repo/students/__tests__/student-grant-free-trial-once.test.ts` — `expect(persisted?.balanceTrial).toBe(1)` (numeric equality, no `null` coalescing)
- `backend/services/auth/__tests__/registration-trial-provisioning.test.ts` — `expect(studentRow.balanceTrial).toBe(FREE_TRIAL_SESSION_COUNT)` (numeric equality)

If `balanceTrial` were nullable, TypeScript would have flagged `toBe(1)` against `number | null` and `bun tsgo` would fail. **`bun tsgo` returns zero project-source errors** (see §3.5) — this is the structural proof that the inferred type is `number`, not `number | null`.
