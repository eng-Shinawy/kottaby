## Contract notes

- **One scaffold, two modes (REQ-012/013 UX)**: `PlanFormDialog` is a shared create/edit scaffold — `plan == null` ⇒ CREATE (blank fields), `plan != null` ⇒ EDIT (prefilled canonical row). The five fields: title, sessionCount, price (decimal **string**), currency, intervalDays.
- **Partial-patch handling (`avoidOptionals` nuance, REQ-013)**: codegen emits `input?: T | null` slots. Edit patches only include keys the admin actually touched, and untouched optionals are **omitted entirely (never sent as `null`)** — server-side the defined-and-non-null partial-patch builder would otherwise read an explicit `null` as a patch value. Create always sends all five required fields.
- **Submit discipline (REQ-063)**: form submits via `React.SubmitEvent`/`SyntheticEvent<HTMLFormElement>` (no `FormEvent`); styling inside `sx`; `*Outlined` icons; theme-callback colors; submit button disabled while the mutation is in flight.
- **Error-contract mapping (Ruling B + REQ-050)**:
  - top-level `extensions.code === "VALIDATION"` **with usable `extensions.fields[]`** (`{field, code, message}`) → per-field localized errors under the matching input (`aria-invalid` + helper text); NO alert;
  - `VALIDATION` **without** usable `fields[]` → inline Alert (`errors.validation`);
  - `PLAN_NOT_FOUND` → inline Alert on the edit/status flow;
  - `PLAN_ALREADY_ACTIVE` / `PLAN_ALREADY_INACTIVE` (custom `extensions.code` overriding `CONFLICT`) → inline Alert on the status flow;
  - `UNAUTHORIZED` / `FORBIDDEN` → surfaced via the app-wide error surface host;
  - unknown wire path → generic failure toast (`toastActionFailed`).
  - `fields[].message` is **server-localized** and rendered verbatim; fallback copy (no usable `fields[]`) resolves through the `errors` namespace by machine code with the **client** locale.
- **REQ-043 double-submit**: server tolerates duplicate plan rows (no natural unique key — documented ruling); UI mitigation = submit button disabled during flight (proven in unit suite + browser cell d).
