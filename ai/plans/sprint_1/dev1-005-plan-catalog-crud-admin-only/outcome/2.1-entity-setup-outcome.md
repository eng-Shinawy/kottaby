### `createTestPlan`

```ts
export async function createTestPlan(
  tx: DBTransaction,
  overrides: Partial<PlanSelectType> = {}
): Promise<PlanSelectType>
```

Defaults (CHECK-safe against `plans_session_count_check` / `plans_price_check` /
`plans_interval_days_check`):

| Column         | Default                          |
| -------------- | -------------------------------- |
| `title`        | `` `Test Plan ${randomUUID().slice(0, 8)}` `` (unique per row) |
| `sessionCount` | `5` (≥ 1)                        |
| `price`        | `"10.00"` (decimal string, ≥ 0)  |
| `currency`     | `"EGP"`                          |
| `intervalDays` | `30` (≥ 1)                       |
| `isActive`     | `true`                           |
| `deactivatedAt`| `null`                           |

Returns the full `$inferSelect` row (`PlanSelectType`): includes `id`, `isActive`,
`deactivatedAt`, `createdAt`, `updatedAt`. `createdAt`/`updatedAt` stay server-defaulted
(not part of the values object). Overrides intentionally allow violating CHECK columns —
violating inputs surface the raw `23514` check-violation for constraint probes (mirrors
`plan-catalog-schema.test.ts`); they also allow arranging pre-deactivated catalog states
(`{ isActive: false, deactivatedAt: someDate }`).

### `createTestPlanWithSubscription` (linkage fixture)

```ts
export async function createTestPlanWithSubscription(
  tx: DBTransaction,
  overrides: {
    plan?: Partial<PlanSelectType>;
    user?: Partial<UserSelectType>;
    student?: Partial<StudentSelectType>;
    subscription?: Partial<SubscriptionSelectType>;
  } = {}
): Promise<{
  plan: PlanSelectType;
  user: UserSelectType;
  student: StudentSelectType;
  subscription: SubscriptionSelectType;
  studentSubscription: StudentSubscriptionSelectType;
}>
```

Composes the existing factories instead of duplicating them: `createTestPlan` →
`createTestUser` → `createTestStudent(tx, user.id)` → direct `tx.insert(subscriptions)`
(`userId`, `planId`, `status: "active"`, `startDate: new Date()`, `endDate`/payment
columns `null`) → direct `tx.insert(studentSubscriptions)` (`studentId`,
`subscriptionId`; `enrolledAt` server-defaulted). The returned `student` row carries the
per-student balance lanes (`balanceHifz`/`balanceTajweed`/`balanceReviews`, defaulted 0)
so the REQ-075 byte-identical preservation proof can snapshot balances before/after plan
mutations and assert the `subscriptions` row still references the same `planId`.

Notes for consumers:

- `price` is a decimal **string** end-to-end (`"10.00"`) — overrides must pass strings.
- Overrides are typed `Partial<PlanSelectType>` — a `title` override MUST be unique per
  test or you reintroduce 23505 collisions; default titles are always unique.
- Inside `runInRollback`, always pass `tx` onward to repo/service calls; the helpers
  already ride `tx`, so rollback also cleans their subscription/junction rows.
- Do not rely on the row returned by a helper AFTER its wrapping `runInRollback`
  completes — it is rolled-back state (the wrapper discards results by design).
