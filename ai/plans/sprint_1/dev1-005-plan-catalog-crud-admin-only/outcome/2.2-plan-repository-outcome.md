## Guarded-UPDATE SQL sketch (2.2.3)

```ts
.set({ isActive: target, deactivatedAt: target ? null : new Date(), updatedAt: new Date() })
.where(and(eq(plans.id, id), eq(plans.isActive, !target)))
.returning()
```

Executed as ONE statement on `tx` (or global `db` when omitted) — no `sql` template, full Drizzle parameterization, no SELECT-then-UPDATE; the predicate evaluates under the row write lock → TOCTOU window = 0. The literal `is_active = true` appears exactly once in the file (`LIST_ACTIVE_SQL` non-tx branch of `listActive`; the tx branch's `eq(plans.isActive, true)` is in the same method — grep-verified count 1 for the literal).

## Read-path shape (2.2.6)

`if (tx)` → Drizzle select on the supplied transaction; else raw parameterized SQL via `queryDb` from `@/backend/db` (Neon-HTTP-eligible), mirroring `ApplicantRepository.findByUserId`. Static SQL constants only — no concatenation of caller input; `existsById` passes `id` via `$1`. Column aliases mirror `$inferSelect` camelCase so both paths return `PlanSelectType`-shaped rows. No prepared statements (queryDb pattern chosen per amended text; module-level prepared statements: none to remove). No `inArray`.
