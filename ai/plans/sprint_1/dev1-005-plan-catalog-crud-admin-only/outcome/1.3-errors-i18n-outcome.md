## Design note — flat realization of the `planCatalog` group

The amended task text names a "`planCatalog` interface group". It is realized as the **flat, uniformly `plan*`-prefixed key family on `ErrorsLabels`** (not a nested `planCatalog` object), because:

1. The namespace contract (`shared/locale/types/errors/index.ts` header) pins "Keys are lowercase camelCase of the SCREAMING_SNAKE_CASE codes" — `PLAN_NOT_FOUND → planNotFound` — matching the existing `applicantNotFound` precedent.
2. The existing `shared/locale/errors-namespace.parity.test.ts` sweeps **every top-level key of both locale maps as a non-empty string** and its route-emitter scanner matches flat `errorsTranslations.<key>` consumption in `app/api/graphql/route.ts`; a nested object value would break both, and that suite is outside this task's file scope.
3. Compile-time parity (the 1.3.1 gate) is unchanged: both leaf consts are typed `ErrorsLabels`, so a missing key fails `bun tsgo`. A nested group would also have forced an edit to `shared/locale/types/message.ts` for reachability — a file concurrently owned by Task 1.4.
