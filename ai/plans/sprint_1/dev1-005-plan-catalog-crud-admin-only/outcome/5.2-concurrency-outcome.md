## 3. SEC audit (5.2.SEC) — TOCTOU = 0 under the guarded UPDATE (D2)

- **The double-deactivation probe IS the proof.** The only state-transition mechanism in the domain is the repository's guarded conditional UPDATE (`… WHERE id = $id AND is_active = NOT $target` — `PlanRepository.setActiveStatusOnce`, plan D2). When two deactivations race, Postgres serializes them on the row: the first matches the guard and rewrites the row (returning it via `RETURNING`); the second matches ZERO rows, the service's `existsById` probe disambiguates "already in target state" from "missing", and the loser is denied with the service-owned `ConflictError("PLAN_ALREADY_INACTIVE")`. There is no read-then-write window to interleave into — the state check and the write are the SAME statement.
- **Exactly-once corroboration**: the DB `deactivated_at` equals the winner's wire-reported stamp. A second transition would have re-stamped the timestamp (`deactivated_at = now()`); it didn't, because the guard rejected it. (Both sandbox processes run UTC and `deactivated_at` is timestamp-without-tz, so the wire ISO string and the drizzle-parsed `Date` agree at millisecond precision — documented as the precision basis for the equality assert.)
- **LWW is semantics, not luck**: updatePlan's unguarded field UPDATE carries no read-modify-write window either — each patch is a single atomic statement; the chronological-last write is the surviving value. The suite deliberately asserts set membership (one of the issued patches), NOT which one — the deterministic chronological-last guarantee is documented D2/LWW semantics, never a timing assert.
- **Actor identity**: one admin identity (direct-DB `users(role:"admin")` + `admin` child row, REAL bcrypt hash, REAL public login) rides every mutation via per-request bearer headers — no cookie/identity bleed; all probes exercise the same authorized-actor race surface REQ-074 targets.
- **Fields**: every document requests exactly the ten-field REQ-060 whitelist + `__typename` pinning — no over-fetch, no smuggled fields.
