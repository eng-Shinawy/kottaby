## Deviations / amendments

1. **Test location:** no dedicated seed-test layout existed; used the sanctioned fallback `backend/db/test/logic/billing/plan-catalog-seed.test.ts` (Task 3.5 instruction; mirrors the plan-catalog service-test layout).
2. **no-await-in-loop:** the initial `for…of` sequential bootstrap tripped `eslint(no-await-in-loop)` in the sub-loop. Fixed in-file with the repo-mandated reduce-chaining idiom (`users/seed-users.ts` precedent — sequential, deterministic order preserved); `Promise.all` was rejected because fixture (d) requires create→deactivate sequencing and seeders conventionally write sequentially.
3. **Assertions scoped to the demo set:** the dev DB legally contains additional committed plan rows, so "exactly one inactive" and count-stability assertions are evaluated relative to the pre-test baseline / scoped to the four demo titles (documented in the test header). No assertion weakness: demo-title uniqueness and run-1→run-2 count stability remain absolute.
4. **`_config` unused parameter:** the 1.5 contract froze the `seedOrGet(config?: SeedConfig)` signature; this seeder needs no credentials, so the param is kept for controller-call-site parity and marked unused (underscore convention).
5. **Verification-service probe:** dev-DB row verification used a one-off `bun -e` script (`psql` client binary is not installed in the sandbox); this is diagnostics only — the seeder and test remain service-only.
