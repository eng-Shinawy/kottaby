## Implementation notes

- **Data layer (final for 4.4)**: `useQuery(adminPlansQueryDocument, { variables: { includeInactive: true } })` from `@apollo/client/react` (REQ-064: the lifecycle toggle needs the full catalog). Branch order is **error → loading/!data → empty → table**; a settled failure arrives as `(loading=false, data=undefined, error)` so `!data` must be checked AFTER `error` or the failure strands on the skeleton forever (first draft had that bug; fixed before any run).
- **Translation handles**: `useAppTranslation(Plans)` (property access only) + `useAppLocale()` for the date util. The 4.2 shell hands the **string-keyed subset** (`PlanCatalogStaticLabels`, an 18-key `Pick<PlansLabels,…>`) as the `labels` prop; the container merges `{ ...clientHandle, ...labels }` so the server-resolved copy wins for shared keys while the client handle supplies the six title-formatter keys (dialog/toast copy) that Task 4.4 interpolates **in-container**. See Deviation A.
- **Table**: columns title (ellipsis-truncated), sessionCount, price + currency (decimal STRING rendered verbatim — no coercion/no `toFixed`, REQ-060), intervalDays, status chip, deactivatedAt, createdAt (`formatApplicantDate` from `frontend/lib/i18n/format-date` — the established locale-aware util; Arabic-Indic digits under `ar`), and per-row `*Outlined` actions (`EditOutlined`, `UnpublishedOutlined` = deactivate, `PublishedWithChangesOutlined` = activate) whose labels/tooltips reflect the row's CURRENT state. Null `deactivatedAt` renders a locale-neutral em dash (punctuation, not copy).
- **Status chips**: Active = `successContainer`/`onSuccessContainer`; Inactive = mode-aware MUI `grey` pair via `inactiveChipPair(palette)` helper (nested ternaries extracted for `sonarjs/no-nested-conditional`). Zero hardcoded hex; verified in-browser via computed styles (`rgb(20,83,45)` = `successContainer`, inactive `rgb(66,66,66)`/`rgb(238,238,238)` = grey 800/200).
- **Loading/empty/error**: skeleton rows (`aria-busy`, testid `plan-catalog-loading`, `t.loading` copy); empty state (testid `plan-catalog-empty`, `Inventory2Outlined` icon + `emptyStateTitle`/`Body` + create CTA calling the same 4.4 intent as the page-header `createButton` button); error state (testid `plan-catalog-error`, namespace error copy + retry → `refetch`). The plans namespace has no permission-denied copy, so no `PermissionDeniedFallback` branch here (unlike ApplicantStatusCard) — every Apollo failure surfaces as the recoverable namespace error state; the page-level guard already owns authorization.
- **4.4 boundary**: `onCreatePlanIntent` / `onEditPlanIntent` / `onTogglePlanStatusIntent` are stable `useCallback` placeholders (clearly marked; `noUnusedParameters` satisfied via `_plan` naming). NO dialog files, NO mutations in 4.3 — 4.4 only swaps the callback bodies and composes mutations.
- **Responsive/RTL**: `useMediaQuery(theme.breakpoints.up("md"))` switch (DashboardLayout convention: SSR renders mobile-first, client re-renders — documented no-hydration-mismatch contract). Logical properties only; flex/grid + gap mirror under `dir=rtl`.

## Deviations & findings

- **A. `labels` prop is the STRING-keyed subset, not the full `PlansLabels`** (task text said `<PlanCatalogContainer labels={…plansTranslations} />`): RSC props are serialized — the namespace's six title-formatter functions cannot cross the server/client boundary (a full-tree `labels={t}` would throw `Functions cannot be passed directly to Client Components`; precedent: `ProfilePage` passes NO labels to `ProfileView` for the same reason). The page forwards each label via property access (4.2.2's "shell labels via property access as props" honored) and the container merges over `useAppTranslation(Plans)`, keeping 4.4's in-container dialog copy fully available. `useAppTranslation(Plans)` remains the primary handle as instructed.
- **B. Namespace gap — no column-header keys for `createdAt`/`deactivatedAt`** (`PlansLabels` pins exactly 45 keys; `EXPECTED_KEY_COUNT = 45` is asserted by `shared/locale/plans-namespace.parity.test.ts`): the two timestamp columns render as UNLABELED data columns (empty `th`s) and mobile cards show them as a muted stamp footer rather than inventing hardcoded header copy against the zero-hardcoded-strings gate. Follow-up proposal: add `columnCreatedAt`/`columnDeactivatedAt` keys (+ parity-test bump) in a namespace-owning task; the table's header row is the only change needed.
- **C. Pre-existing platform-wide hydration warning**: Next dev overlay shows 1 recoverable "Hydration failed" issue on `/admin/plans` — and identically on the untouched `/profile` and `/student/dashboard` (same Apollo-provider SSR posture: the server pass attempts the query, the client re-renders the resolved tree). Not a 4.3 regression; the final rendered state is correct on all pages. Out of scope to fix here (would touch `AppClientProviders`/Apollo SSR strategy).
- Dev DB carries Phase-3 QA fixture rows (see BF §5) — cosmetic seed noise only.
