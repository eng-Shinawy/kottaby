### Design deviation on `PlanReturnType` (lint-driven, identity preserved)

Gate design context prescribed the bare identity alias `type PlanReturnType = PlanSelectType`. That exact form is rejected by the repo's own quality loop:

1. `type PlanReturnType = PlanSelectType` → `sonarjs/redundant-type-aliases` error ("Remove this redundant type alias…").
2. Fallback `interface PlanReturnType extends PlanSelectType {}` → `@typescript-eslint/no-empty-object-type` error.
3. Final form `type PlanReturnType = Readonly<PlanSelectType>` → sub-loop EXIT 0.

`Readonly<PlanSelectType>` is structurally interchangeable with `PlanSelectType`: TypeScript ignores `readonly` modifiers in assignability, so the identity proof in the test-d file (below) compiles. It keeps `PlanSelectType` on the RHS, so any future field omission on the select type propagates into the return type automatically. Behavior notes for consumers: reading a plan via `PlanReturnType` is unchanged; in-place mutation of a returned plan is now a type error (protective for API return shapes).

## BOPLA audit

- Money discipline: `price` is `string` (decimal string, e.g. `"250.00"`), never `number`/`Float` — enforced in the input type and proven negatively in the test-d (both submit and update payloads).
- `intervalDays`, `sessionCount` are `number`; `title`, `currency` are `string`.
- No field of `PlanReturnType` is removed (plans carry no forbidden fields); the lifecycle columns remain visible on reads so the deactivation state is renderable/auditable.
