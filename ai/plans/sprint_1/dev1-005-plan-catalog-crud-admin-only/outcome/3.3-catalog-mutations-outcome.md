## SDL contract delivered

- `createPlan(input: CreatePlanInput!): Plan!` / `updatePlan(id: ID!, input: UpdatePlanInput!): Plan!` / `setPlanActiveStatus(id: ID!, isActive: Boolean!): Plan!` — all backed by the canonical `PlanPothosObject` (REQ-060) so every mutation returns the FULL persisted row (service ends in single INSERT/UPDATE … RETURNING *) for Apollo cache convergence.
- **BOPLA at the SDL layer**: both inputs carry EXACTLY `title/sessionCount/price/currency/intervalDays`; server-owned columns (`id`, `isActive`, `deactivatedAt`, `createdAt`, `updatedAt`) are structurally absent — a caller cannot even EXPRESS them on the wire. `price` is a decimal STRING (REQ-013: no Float). `CreatePlanInput` all-required (service requireAll contract); `UpdatePlanInput` all-optional (service owns the `planPatchEmpty` reject; `{}` stays expressible for exactly that reason).
- **No delete surface by construction (INV-PC3)**: the file registers exactly three fields — no `deletePlan`/`removePlan` exists anywhere in the chain (grep-verifiable).
- Resolvers are THIN: `if (!ctx.user)` guard exists purely for TypeScript narrowing (no-non-null-assertion rule; message mirrors builder.ts's `authenticated` scope verbatim); then a single service call with `ctx.locale`. The resolver-local code between scope check and service call is ONLY structural mapping: createPlan's explicit five-field object (BOPLA boundary) and updatePlan's defined-and-non-null partial-patch builder (explicit-null normalized to "not supplied", mirroring auth.mutation.ts's `?? undefined` idiom; no key can be forged as undefined). `id` args ride the `ID` scalar (string on the wire) and are handed to the service via `Number(args.id)` — the service owns positive-integer validation.

## SEC audit

- **BFLA before resolver body**: the `$all { authenticated, role: [UserRole.Admin] }` conjunction is evaluated by scope-auth BEFORE `resolve` runs (proven by cells 5–10: denials carry the canonical 401/403 split and the service is never reached — a student trigger of createPlan would have produced a service-layer rejection, not FORBIDDEN). The explicit `$all` is mandatory (ANY-semantics trap documented in the file header); anonymous hits the `authenticated` scope's UnauthorizedError (401), authenticated non-admins fail the `role` scope into localized FORBIDDEN (403).
- **Actor identity from ctx only**: resolvers take NO caller-supplied identity — the service receives only field payloads + `ctx.locale`; ownership/role is derived exclusively from the verified context row (`ctx.user` after scope enforcement).
- **BOPLA**: server-controlled lifecycle fields are unrepresentable at the SDL layer AND explicitly field-mapped at the resolver layer (double boundary); cells 16–17 prove the wire rejects smuggle attempts before execution even for a fully-authenticated admin.
- **Rate posture**: inherits the global limiter stub (DISABLE_RATE_LIMITING=true in the test server env); no per-field throttle added — consistent with the existing auth mutations' posture (no rate-limit surface exists yet project-wide).
- **No LIKE/search inputs** (escapeLikeWildcards N/A): all string inputs are fixed-length commercial fields (`title`, `currency`, `price`) handled by the service's pure validators; no search/filter surface in this task.
- **No delete/ledger reach**: zero imports of subscription/payment/student/wallet tables; the mutation layer cannot cascade into any commercial ledger (grep-verifiable, mirrors service discipline).
