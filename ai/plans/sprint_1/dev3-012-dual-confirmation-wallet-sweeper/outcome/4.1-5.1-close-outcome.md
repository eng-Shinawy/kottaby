## Sweep-route hardening (bug fixes found by the new route test)

`app/api/cron/sweep-sessions/test/sweep-sessions-route.test.ts` (NEW — 9 tests, module-boundary service mock, live `process.env` stubbing) exposed TWO real defects in the cron-r5 route:

1. **404 oracle (fixed).** The disabled-surface arm returned `apiErrorResponse(new NotFoundError("ENDPOINT", …))`. `ENDPOINT` is NOT a canonical taxonomy code → it falls through normalization → the envelope answers **400** with a code — a 400 tells the caller the path EXISTS and is a cron route, directly contradicting R-204's "indistinguishable from any other unknown path" (and the route's own docblock). Root cause: the shared envelope's status derivation is the ONLY sanctioned path and its nine canonical codes have NO 404 row (REST envelopes never 404 by design). Fix: the disabled arm now returns a BARE `new Response(null, { status: ENDPOINT_GONE_STATUS })` — no envelope, no code, no requestId — with the status literal documented in-file as the single sanctioned taxonomy exemption.
2. **Escaped error (fixed).** The route had NO try/catch: a thrown sweep failure (e.g. unreadable refund lane rolling the transaction back) escaped the GET handler raw (framework 500, no envelope, no correlated log). Fix: the sweep call is wrapped; the error goes through `apiErrorResponse` (masked 500 `INTERNAL_SERVER_ERROR` + one correlated redacted log line) — asserted by the test including a message-non-leak check.

Both fixes verified: route test 9/0, full linters green, backend battery unaffected (the service contract is untouched — only the route's gate/envelope arms changed).

Pre-existing finding recorded: the repo-root `test:cron` npm script references non-existent paths (`backend/services/cron/test/`, `backend/db/test/repo/cron.repository.test.ts`, `backend/lib/cron-auth.test.ts`) — a stale template script that fails to collect. NOT fixed this round (out of plan scope); the new colocated route suite is the working coverage for the cron surface.
