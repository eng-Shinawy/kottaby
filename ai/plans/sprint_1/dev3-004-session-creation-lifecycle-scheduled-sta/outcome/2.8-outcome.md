## 0. Summary

`backend/services/classes/session-lifecycle.service.ts` (NEW, namespace `SessionLifecycleService`, 7 public methods) implements the booking + lifecycle state machine for the `session` entity: `createSession` composes the REQ-040 FOUR-PHASE creation inside ONE `withTransaction` transaction in a fixed, never-reordered order (teacher certification lock → trial-first guarded debit ladder → savepoint-bracketed idempotency claim insert → session insert with server-side defaults + claim backfill); `startSession`/`completeSession`/`cancelSession` are single guarded repository UPDATEs whose zero-row misses are classified by ONE cold probe read that never influences any write; `getSessionById` and the participant list pair are owner-scoped, oracle-safe reads. ## 3. Behavior Contract (per method)

**`createSession` — the four-phase order is FIXED (REQ-040); phases never reorder:**
- **Phase 0 (pre-DB, before any database work):** `studentId` / `input.teacherId` positive-safe-integer guards (`isPositiveSafeInteger` — no `as number`) → `ValidationError(t.validation)`; idempotency key non-empty and ≤ 128 chars → `ValidationError(t.idempotencyKeyRequired)` (carried verbatim — never trimmed, never coerced, never logged); intent ∈ {`SessionIntent.Hifz`, `SessionIntent.Tajweed`} → else `ValidationError(t.invalidSessionIntent)`. ONE `now` instant is captured for the whole flow (REQ-046): `confirmationDeadline = now + SESSION_CONFIRMATION_WINDOW_MS` (86 400 000 ms = now+24h EXACTLY).
- **Governance re-check (pre-tx):** `assertActorGovernanceClean(studentId)` — a governed acting user (isDeleted ∨ isBlocked ∨ suspended, mirrored from the login predicate) → `ConflictError("FORBIDDEN")`.
- **Phase 1:** `TeacherRepository.lockForCertificationCheck` — the certification value this booking commits against (teacherless id → `NotFoundError("TEACHER")` = `TEACHER_NOT_FOUND`; never mints certification); `isApproved !== true` → `ConflictError("TEACHER_NOT_CERTIFIED")`.
- **Phase 2:** trial-first guarded debit ladder — `decrementLaneIfAvailable(Trial)` first, then the intent's own lane (`Hifz`/`Tajweed`); all-miss → `ValidationError("INSUFFICIENT_BALANCE")` (→ 422 per REQ-050 Ruling 2026-08-30); the rollback is the only cleanup — no compensating writes. The winning lane is recorded as the session row's `heldBalanceLane` provenance.
- **Phase 3:** idempotency claim insert — savepoint-bracketed (`tx.transaction`) so a duplicate key poisons only the savepoint and the transaction stays readable for the replay lookup; a PG `23505` is detected by the cycle-safe cause-chain walker (`isClaimKeyUniqueViolation` — `seen`-set traversal, never `.message`) and branches to `replayBooking`.
- **Phase 4:** `SessionRepository.insertSession` with every server-controlled column set field-by-field (BOPLA — never a spread of caller input): `status=Scheduled`, `sessionType=StudentSession`, intent, fee = platform decimal STRING constant per intent, `feeHeld=true`, `heldBalanceLane`, `confirmationDeadline`; then the claim's `sessionId` backfill in the same tx (claim + session commit atomically).
- **Replay (duplicate key):** THROWS per the ruling — see §5.

**`startSession` / `completeSession` — teacher-only guarded transitions:** governance re-check on the acting teacher first; one guarded UPDATE each (`startSessionOnce`: id ∧ teacherId ∧ Scheduled → Started + startedAt/updatedAt stamps, confirmation deadline untouched; `completeSessionOnce`: fused certification `EXISTS` predicate inside the SAME where-clause → Completed + endedAt + confirmedByTeacherAt, report/homework side effects deliberately absent). A zero-row miss is classified by ONE cold probe read (`rejectTransitionMiss` — classification-only, never gates a write): unknown id → `SESSION_NOT_FOUND`; non-owning caller (incl. the session's student) → `SESSION_NOT_FOUND` (oracle-safe: foreign ≡ nonexistent); owned row in the wrong state → `SESSION_INVALID_TRANSITION`; complete-only: owned + in-progress ⇒ the fused certification predicate was the miss cause → `TEACHER_NOT_CERTIFIED` (probe status compared against the enum-derived widened constant, never a bare literal).

**`cancelSession` — participant-side, governance EXEMPT:** NO governance re-check (a governed participant may still release an in-flight hold — REQ-023 no-punishment clause). Optional `reason` is validated (trim-normalized length > 500 → `ValidationError`) then **DISCARDED — never persisted by this flow** (the session status-history surface owns that persistence; DEV3-005). One guarded UPDATE (`cancelSessionOnce`: id ∧ (student ∨ teacher) ∧ (Scheduled ∨ Started) → Cancelled + `feeHeld=false`; keeps `startedAt`, never writes `endedAt`).

**Refund logic (REQ-042/REQ-073):** on success, only when the cancelled row carries held-balance provenance (`heldBalanceLane !== null` — the `feeHeld` marker; a fee was actually held) the SAME lane is refunded by one unit via the unguarded `incrementLane` **inside the same `withTransaction`** (same-lane: trial→trial, paid→paid — the lane that paid is refunded exactly once). An unreadable provenance value fails closed (refusal rolls the whole cancellation back). A terminal or foreign target is classified by the cold probe (non-participant → `SESSION_NOT_FOUND`; anything else → `SESSION_INVALID_TRANSITION`), so a double cancel can never double-refund.

**Oracle-safe reads:** `getSessionById` — participant-scoped after a single lookup; a nonexistent id and a non-participant caller resolve to the identical `null` (no error, indistinguishable); unknown/garbage ids degrade to `null` through the parameterized lookup. Lists (`listMyStudentSessions`/`listMyTeacherSessions`) — owner-side scoping only; page bounds normalized BEFORE any DB work (page < 1 / non-integer → 1; pageSize outside 1..50 → 25) with the EFFECTIVE values echoed honestly; `SessionStatus` filter guarded pre-DB against the closed vocabulary (out-of-vocabulary values drop out — filters never error); `totalCount` computed under the SAME filtered predicate as the items (count can never diverge); newest first.

**Governance re-check scope (Ruling 2026-08-30, bounded):** `createSession` (acting student) + `startSession` + `completeSession` (acting teacher) ONLY — **`cancelSession` is EXEMPT**.

## 4. REQ-052 — DUPLICATE_REQUEST Construction Mechanism (MANDATORY record)

**Mechanism actually used: `ConflictError` extended with an overloaded `(code, message)` constructor** — the additive `backend/lib/errors.ts` extension scheduled as this task's prerequisite (`new ConflictError("DUPLICATE_REQUEST", t.duplicateRequest)`), mirroring the `ValidationError` `(code, message)` precedent with the fixed `"CONFLICT"` default preserved. Direct `DomainError(code, message)` construction was NOT used. Codes routed through the extended ctor: `TEACHER_NOT_CERTIFIED`, `SESSION_INVALID_TRANSITION`, `DUPLICATE_REQUEST` (all 409). `INSUFFICIENT_BALANCE` deliberately routes through `ValidationError`'s PRE-EXISTING overload (→ 422) — never through `ConflictError` (Ruling 2026-08-30). `TEACHER_NOT_FOUND` / `SESSION_NOT_FOUND` come from `NotFoundError(entity, …)`'s auto `${entity}_NOT_FOUND` code.

## 5. Replay-Throw Ruling (2026-08-30) — MANDATORY record

A replayed booking **THROWS `ConflictError("DUPLICATE_REQUEST")` and NEVER returns the row**. `replayBooking` is typed `Promise<never>` and funnels EVERY same-caller duplicate into the same 409: a claim with its session pointer, a spent claim without a resolvable pointer, and a vanished claim (fail-closed) are indistinguishable to the caller. A key spent by a DIFFERENT caller is denied with the oracle-safe `SESSION_NOT_FOUND` — another user's claim is never surfaced. Success-equivalence is the CLIENT-side REQ-065 mapping of the 409 (`duplicateSuccessEquivalent` info notice) — the SERVICE surface has no success-shaped replay path. The throw is what guarantees the replayed attempt's own partial writes (its debit-ladder step) roll back with the transaction: **zero new rows, no second debit, no burned second allowance unit** (REQ-073 — proven by the REQ-043(e) chaos test: 4 concurrent same-key bookings → 1 session, 1 claim, exactly ONE net debit, three `DUPLICATE_REQUEST` denials). Plan.md §1.2 diagram + tasks.md 2.8 were already amended to match; the service's file-header / `createSession` / `@returns` docblocks were aligned to the ruling in this close-out (comment-only diff).
