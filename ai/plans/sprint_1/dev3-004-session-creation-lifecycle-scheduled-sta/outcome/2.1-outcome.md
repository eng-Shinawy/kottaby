### 2.1 `journey-fixtures.ts`

```ts
// FK-safe hard-delete order — children first, users last. THE trackable vocabulary.
export const JOURNEY_TRACKED_TABLE_DELETE_ORDER = [
  "session_request_idempotency", // refs users (cascade) + session (set null)
  "session",                     // restrict-FKs into teacher/students → delete before them
  "students",                    // shared-PK role-child (users)
  "teacher",                     // shared-PK role-child (users)
  "applicants",                  // shared-PK role-child (users)
  "parents",                     // shared-PK role-child (users)
  "admin",                       // shared-PK role-child (users)
  "users",                       // deleted LAST
] as const;

export type JourneyTrackedTable = (typeof JOURNEY_TRACKED_TABLE_DELETE_ORDER)[number];

export interface JourneyFixtureRegistry {
  track(table: JourneyTrackedTable, id: number): void;            // deduplicated; throws on id ≤ 0 / non-integer
  trackAll(table: JourneyTrackedTable, ids: readonly number[]): void;
  ids(table: JourneyTrackedTable): readonly number[];             // read-only snapshot (assertions/debug)
  trackedCount(): number;                                          // total ids across all tables
  cleanup(): Promise<void>;   // ONE committed db.transaction; deletes every tracked id in
                              // JOURNEY_TRACKED_TABLE_DELETE_ORDER order (empty buckets skipped);
                              // clears registry only AFTER the tx commits. Repeated calls are
                              // no-ops; a failed cleanup KEEPS its worklist so a retry still
                              // removes everything.
}

export function createJourneyFixtureRegistry(): JourneyFixtureRegistry;  // one per suite

// Side-effect row-count oracles (assert ABSENCE by count deltas scoped to fixture ids;
// audit_logs + teacher_transaction are trigger-immutable and NOT trackable — assert ZERO).
export async function countNotificationsForUser(userId: number): Promise<number>;
export async function countAuditLogsForActor(actorUserId: number): Promise<number>;       // audit_logs.actor_id
export async function countWalletsForTeacher(teacherUserId: number): Promise<number>;      // wallet.teacher_id (shared PK)
export async function countTeacherTransactionsForTeacher(teacherUserId: number): Promise<number>; // ledger via wallet join
```

## 3. Design Decisions

1. **Teacher rows built inside `session-cast.ts`, not `entity-setup.ts`.** `backend/db/test/entity-setup.ts`
   has NO teacher factory (`createTestUser/Student/Parent/Applicant/Admin` only — verified).
   Plan §4.4 conditionally suggests adding a certified-teacher helper *there*; task 2.1's
   binding file list does not include `entity-setup.ts`, and this run holds the task scope.
   `buildTeacherCastMember` therefore performs ONE shared-PK insert
   (`tx.insert(teacher).values({ id: user.id, isApproved }).returning()` + no-row guard),
   byte-for-byte the `createTestParent`/`createTestAdmin` pattern from `entity-setup.ts`
   ("mirror existing entity-setup patterns exactly"). Flagged to the orchestrator as a
   candidate follow-up (extract `createTestTeacher` into `entity-setup.ts` when the logic-tier
   session suites need it — §8 carry-forward), NOT silently expanded scope.
2. **Registry holds numeric row ids only** — `session_request_idempotency.id` is an identity
   integer (task 1.2), `users.id` integer; no uuid PKs in the tracked vocabulary.
3. **`cleanup` is ONE committed transaction** (single `db.transaction`, sequential deletes in
   `JOURNEY_TRACKED_TABLE_DELETE_ORDER` order) — atomic teardown; partial cleanup is impossible
   (either the whole tracked set goes or the transaction fails and ids stay tracked).
4. **`no-await-in-loop` accommodation:** the FK-ordered deletes are sequential BY DESIGN (row
   locks + FK order), so the loop is a bounded-depth recursive helper (`deleteNext(index)`),
   root-cause-shaped for the linter, no disable comments.
5. **Immutable tables excluded from tracking by design:** `audit_logs` and `teacher_transaction`
   are trigger-immutable (schema JSDoc: "UPDATE and DELETE are blocked by a trigger") and
   restrict-delete into `users`/`wallet`. Tracking them would make legitimate teardown
   impossible; instead journeys assert ZERO rows via the counters, and a buggy leak fails the
   suite AND the `users` delete loudly. Documented in `AGENTS.md` + module JSDoc.
6. **Trial-grant realism:** a student profiled with `trial > 0` also gets
   `trialGrantedAt = new Date()` (mirrors the DEV1-004 registration grant shape); booking
   eligibility itself is the balance — no behavioral logic in the builder.
7. **`label.slice(0, 255)`** guards `users.full_name` varchar(255) against oversized prefixes.
8. **Roles as pgEnum string literals** (`"student" | "teacher" | "parent" | "admin"` — the
   canonical `UserRole` values) typed via `UserSelectType["role"]`; no TS-enum/DB-enum mapping
   friction, no casts.
