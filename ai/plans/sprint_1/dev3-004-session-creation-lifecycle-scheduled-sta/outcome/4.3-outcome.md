## 6. Seam decision (as implemented)

**Extended props on the shared student-session primitives — NO wrapper, NO fork, NO ui-layer move:**

- **`SessionRow`** gained optional `actions?: ReadonlyArray<SessionRowAction>` (`{ id: "start" | "complete"; label; disabled; onIntent }`) rendered beside the Cancel button in the row's existing action stack. Rationale (documented in the component docblock): the Cancel CTA lives INSIDE the row's action stack — a `TeacherSessionRow` wrapper would have to duplicate the meta/actions layout to sit beside it, which is exactly the duplication the "extending rather than duplicating" mandate forbids. The row never owns mutation bookkeeping (`disabled` is the caller's per-mutation in-flight state; `onIntent` is an activation intent only).
- **`SessionStatusFilterChips`** reused as-is (locale-agnostic; props `{ value; onChange }` unchanged).
- **`CancelSessionConfirmDialog`** composed directly (already role-neutral per its docblock); its not-found arm was generalized to filter BOTH role list fields so the same component converges the teacher list cache without refetch.
- The list-item codegen types of `myTeacherSessions` / `myStudentSessions` are structurally identical closed 14-field shapes, so the teacher container passes teacher rows into the student-typed `SessionRow` prop without a mapping layer (documented at the prop).
- Container-level wiring (stateful `useQuery`, per-kind in-flight slots, `mapGraphQLErrorByCode` + caller-kept arms, snackbar chrome) is pattern-copied from the student container per the 4.2 carry-forward, retargeted at the teacher list field and the Start/Complete lifecycle (the only container-level code NOT imported).
