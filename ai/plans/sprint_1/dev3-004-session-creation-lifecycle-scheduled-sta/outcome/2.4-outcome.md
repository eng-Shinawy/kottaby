## 2. Exact Public API (consumption surface for task 2.8)

```ts
// namespace StudentRepository (backend/db/repo/students/student.repository.ts)
// Import consumers: `import { StudentRepository } from "@/backend/db/repo";` (top-level barrel, unchanged)

/**
 * ONE guarded conditional UPDATE per call; lane column resolved from the
 * frozen LANE_BALANCE_COLUMNS map (enum-member keys only). tx is LAST/optional.
 * @returns true  — row matched, one unit debited (balance_<lane> - 1 + updated_at = now())
 *          false — student unknown OR lane balance already 0 (caller decides semantics;
 *                  the repo raises nothing)
 */
export async function decrementLaneIfAvailable(
  studentId: number,
  lane: HeldBalanceLane,
  tx?: DBTransaction
): Promise<boolean>;

/** Unguarded `+ 1` refund (no upper bound; CHECK >= 0 cannot trip on +1). tx is LAST/optional. */
export async function incrementLane(
  studentId: number,
  lane: HeldBalanceLane,
  tx?: DBTransaction
): Promise<void>;
```

Rendered statement (verified empirically against PostgreSQL 17.11) — debit, `lane = trial`:

```sql
UPDATE "students"
SET "balance_trial" = "students"."balance_trial" - 1, "updated_at" = now()
WHERE "students"."id" = $1 AND "students"."balance_trial" > 0
RETURNING "students"."id"
```

(`RETURNING id` + `result.rows.length > 0` is the row-match boolean; the refund is the
same shape with `+ 1`, no `> 0` arm, no RETURNING.) Implementation notes that matter to
2.8:

- **`updated_at` is stamped EXPLICITLY** in both statements (`updated_at = now()`): the
  raw-`sql` statement bypasses the query-builder's `$onUpdate` hook, so without the
  explicit stamp the row's audit timestamp would silently go stale on lane writes.
- **Identifiers are structural, never strings:** the SET target is
  `sql.identifier(<schema column>.name)` and every other column reference is the real
  Drizzle column object interpolated into the `sql` template — the only runtime value is
  the bound `studentId` parameter. There is NO `sql.raw`, NO string concatenation, NO
  path by which a caller string could become a column name.
- **The map is module-private.** The service cannot resolve lane columns itself — lane
  identity can only flow as `HeldBalanceLane` members through these two methods.
- **Executor resolution:** `const executor = tx ?? db;` — the file's own write-path
  precedent (`grantFreeTrialOnce`). `queryDb` remains the READ path (`findById`) and is
  intentionally NOT used here: these are writes.

## 8. Carry-Forward Knowledge (for task 2.8 and later)

- **Debit ladder composition:** call `decrementLaneIfAvailable(studentId, HeldBalanceLane.Trial, tx)` FIRST
  (INV-B8 trial-first), then — only on `false` — `decrementLaneIfAvailable(studentId, <intent lane>, tx)`;
  both `false` → throw the localized `INSUFFICIENT_BALANCE` (`ValidationError`, 422 per the
  REQ-050 ruling) and roll back. Each call is ONE statement; the second call's predicate
  sees the first call's effect inside the same tx. A `true` tells you the lane to record in
  `session.held_balance_lane`.
- **Refund:** `cancelSessionOnce`'s returned row carries `heldBalanceLane`; guard-validate
  the varchar read with `isHeldBalanceLane(...)` before calling
  `incrementLane(session.studentId, lane, tx)` in the SAME transaction. Do NOT probe the
  increment's void — row existence is FK-guaranteed upstream; a missing row would be a
  data-integrity bug, not a user error.
- **Trial lane holds N units:** the debit removes exactly ONE unit per call (the plan's
  `grantFreeTrialOnce` may have granted more than 1); repeat debits across bookings drain
  it unit by unit (Tier 3 multi-unit proof).
- **`updated_at` advances on every lane mutation** (explicit `now()` stamp — raw SQL
  bypasses `$onUpdate`); any 2.8 test asserting row byte-equality on an unchanged student
  must compare lane fields, not the whole row, after a debit/refund.
- **The lane→column map is module-private by design** — services must never map lanes to
  columns themselves; if a future ticket needs a read-side lane projection, add a repo
  method, not a second map.
- **Repo-level concurrency primitive is proven:** the guarded predicate yields exactly-N
  crossings under contention; 2.8's REQ-043(d) chaos proof (real concurrent transactions,
  two creations vs one unit) composes on top of this guarantee.
- **pg DeprecationWarning** appears under same-client concurrent queries (chaos tiers);
  harmless, framework-level, also visible in the pre-existing applicant-lifecycle suite.
