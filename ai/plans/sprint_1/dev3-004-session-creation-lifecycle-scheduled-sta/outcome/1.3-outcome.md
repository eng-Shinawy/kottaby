## 7. Documented Deviation (plan §2.5 literal form)

Plan §2.5's code block shows `export type SessionReturnType = SessionSelectType;`. The mandatory quality gate rejects that exact line: type-aware `sonarjs/redundant-type-aliases` flags a bare alias-of-alias as redundant ("replace its occurrences with `SessionSelectType`"), and `oxlint-disable` is prohibited. Root-cause accommodation (within the file, semantically identical): `export type SessionReturnType = typeof session.$inferSelect;` — the identical derived row, straight from the same `$inferSelect` the alias points at. Correctness is pinned rather than assumed: the conformance suite asserts `Equals<SessionReturnType, SessionSelectType> = true` at the type level, so the two spellings can never fork. This also matches the repo-wide `ReturnType` precedent (`AuthUserReturnType = Omit<UserSelectType, …>`, `RegistrationReturnType = Omit<UserSelectType, …> & {…}`): every `ReturnType` in `backend/types/**` is a derivation/transform of its `SelectType`, never a bare alias. The static suite pins this exact spelling.
