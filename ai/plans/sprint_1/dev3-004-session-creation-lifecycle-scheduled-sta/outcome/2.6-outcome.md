## 2. Exact Public API (for task 2.8 — method-by-method contract)

All 10 methods: **`tx?: DBTransaction` LAST parameter** (grep-verified on every signature). Reads: on `tx` → Drizzle select on the caller's transaction; standalone → raw parameterized SQL via `queryDb` (Neon-HTTP-eligible pattern). Writes: `tx ?? db` (same fallback as 2.4's lane debit/refund).

```ts
export namespace SessionRepository {
  insertSession(insert: SessionInsertType, tx?: DBTransaction): Promise<SessionSelectType>;
  findById(id: number, tx?: DBTransaction): Promise<SessionSelectType | null>;
  startSessionOnce(id: number, teacherId: number, tx?: DBTransaction): Promise<SessionSelectType | null>;
  completeSessionOnce(id: number, teacherId: number, tx?: DBTransaction): Promise<SessionSelectType | null>;
  cancelSessionOnce(id: number, participantId: number, tx?: DBTransaction): Promise<SessionSelectType | null>;
  findTransitionProbe(id: number, tx?: DBTransaction): Promise<SessionTransitionProbeRowType | null>;
  listForStudent(studentId: number, filter: SessionListFilterInput, limit: number, offset: number, tx?: DBTransaction): Promise<SessionSelectType[]>;
  listForTeacher(teacherId: number, filter: SessionListFilterInput, limit: number, offset: number, tx?: DBTransaction): Promise<SessionSelectType[]>;
  countForStudent(studentId: number, filter: SessionListFilterInput, tx?: DBTransaction): Promise<number>;
  countForTeacher(teacherId: number, filter: SessionListFilterInput, tx?: DBTransaction): Promise<number>;
}
```

### Statement + return-shape contracts

| Method | Statement essence | Returns |
|---|---|---|
| `insertSession` | ONE `INSERT … RETURNING *` on `tx ?? db`; caller supplies every server-controlled column (participants, status/type/intent vocabulary, fee as decimal string verbatim, `feeHeld`, `heldBalanceLane` provenance, `confirmationDeadline`); schema defaults fill legitimately-omitted columns (status → pre-start, feeHeld → false). NO other statement touches anything. | full `SessionSelectType`; throws the repo-wide defensive invariant `Error("SessionRepository.insertSession: insert returned no rows")` only if RETURNING yields nothing (unreachable; identical precedent in admin/user/parent/student/applicant create repos) |
| `findById` | tx → `select().where(eq(session.id, id)).limit(1)`; standalone → `queryDb` raw SQL with the full aliased column list | row or `null` (unknown id). NO participant scoping — the read service scopes (constant-shape oracle, plan D9) |
| `startSessionOnce` | ONE guarded UPDATE: `SET status=SessionStatus.Started, started_at=$now, updated_at=$now WHERE id=? AND teacher_id=? AND status=SessionStatus.Scheduled RETURNING *` — all from ONE captured `now`; `confirmationDeadline` deliberately NOT in the SET clause (written at creation, never re-armed) | updated row, or `null` on zero matches (unknown id / non-owner teacher / wrong state — caller classifies via probe) |
| `completeSessionOnce` | ONE guarded UPDATE: `SET status=SessionStatus.Completed, ended_at=$now, confirmed_by_teacher_at=$now, updated_at=$now WHERE id=? AND teacher_id=? AND status=SessionStatus.Started AND EXISTS (SELECT 1 FROM teacher WHERE teacher.id = session.teacher_id AND teacher.is_approved = true) RETURNING *` — certification is FUSED into the same statement, so a decertified teacher can never complete and no separate read exists to race against. Zero report/homework side effects (INV-S7 is DEV3-005). | updated row, or `null` on zero matches (unknown / non-owner / wrong state / decertified — probe classifies) |
| `cancelSessionOnce` | ONE guarded UPDATE: `SET status=SessionStatus.Cancelled, fee_held=false, updated_at=$now WHERE id=? AND (student_id=? OR teacher_id=?) AND (status=Scheduled OR status=Started) RETURNING *` — either participant; terminal states structurally unreachable (double-cancel can never double-release the hold). Keeps `started_at` as-is; NEVER writes `ended_at`. | updated row (with `heldBalanceLane` provenance intact for the caller's refund), or `null` on zero matches |
| `findTransitionProbe` | 4-column projection read (`id, status, student_id, teacher_id` = `SessionTransitionProbeRowType` = `Pick<SessionSelectType, "id"|"status"|"studentId"|"teacherId">`); tx → Drizzle select; standalone → `queryDb` raw SQL | projection or `null` (unknown id). COLD-PATH ONLY — never feeds any write |
| `listForStudent` / `listForTeacher` | shared predicate builder → `WHERE (student_id|teacher_id) = $1 [AND status = $2]`; `ORDER BY created_at DESC, id DESC` (same-instant tiebreak); bound `LIMIT`/`OFFSET`; tx → Drizzle, standalone → `queryDb` raw SQL with the rendered predicate | page rows (`[]` when the window is past the end — the count companion stays honest) |
| `countForStudent` / `countForTeacher` | SAME shared predicate builder as the lists (`count(*)`) | `number` — the honest total for the exact filtered set (totalCount can never diverge from the list) |

Shared module-private builder (the ONE source of list/count filter truth):

```ts

// conditions = [eq(ownerColumn, ownerId)]; + eq(session.status, statusFilter) only when filter.status ?? undefined !== undefined
// joined via sql.join(conditions, sql` and `); status flows as a BOUND PARAMETER from the SessionStatus enum
```

`SessionOwnerColumn = typeof session.studentId` — the owner side (`session.studentId` vs `session.teacherId`) is passed as the schema column object at each entry point, a closed in-code decision, never caller input.
