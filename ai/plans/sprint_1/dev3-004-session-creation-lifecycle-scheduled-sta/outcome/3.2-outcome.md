## 2. Exact signatures & scopes (as registered)

| Field | SDL shape | authScopes | Delegates to |
|---|---|---|---|
| `sessionById` | `sessionById(id: ID!): Session` (nullable) | `{ authenticated: true }` — authenticated-but-role-agnostic; BOTH participants must reach it; the participant predicate is SERVICE-side (REQ-032/D8) | `SessionLifecycleService.getSessionById(ctx.user.id, Number(args.id))` |
| `myStudentSessions` | `myStudentSessions(filter: SessionListFilterInput, page: Int = 1, pageSize: Int = 25): SessionPage!` | `$all { authenticated: true, role: [UserRole.Student] }` | `SessionLifecycleService.listMyStudentSessions(ctx.user.id, filter, page, pageSize)` |
| `myTeacherSessions` | identical shape to `myStudentSessions` | `$all { authenticated: true, role: [UserRole.Teacher] }` | `SessionLifecycleService.listMyTeacherSessions(ctx.user.id, filter, page, pageSize)` |

401/403 split (verified against `@pothos/plugin-scope-auth@4.1.7` — the DEV2-004/DEV1-013 lesson): a plain `{ authenticated, role }` key-map is WRONG (Pothos combines ONE map's keys with ANY semantics), so the conjunction is made EXPLICIT with `$all`. Anonymous → `authenticated` scope's UnauthorizedError throw passes through `builder.ts`'s mapping VERBATIM → `UNAUTHORIZED`/401. Authenticated wrong-role → fails the `role` leg → canonical localized `FORBIDDEN`/403.

Resolver-local details that matter:
- `ctx.user` narrowing guard (unreachable in practice — the scope guarantees the row) throws `UnauthorizedError` with a message mirroring `builder.ts` verbatim; exists purely for TypeScript narrowing (repo-wide no-non-null-assertion rule).
- `args.filter ?? {}` — absent filter becomes the empty filter; `args.page ?? 1` / `args.pageSize ?? 25` — the `??` restores the declared SDL defaults when a client sends an EXPLICIT `null` (GraphQL field defaults do not apply to explicit nulls). The resolver NEVER clamps — the service normalizes bounds pre-DB and echoes them honestly.
- `Number(args.id)` on `sessionById` is a shape-only scalar coercion; every shape decision (positive safe integer, existence, participation) is the service's.
- The reads take NO `ctx.locale`: they never raise localized errors (service contract, task 2.8 outcome §8.3). Only the mutations carry locale.
