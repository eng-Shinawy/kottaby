## 2. Exact signatures & scopes (as registered)

| Field | SDL shape | authScopes | Delegates to |
|---|---|---|---|
| `createSession` | `createSession(input: CreateSessionInput!): Session!` | `$all { authenticated: true, role: [UserRole.Student] }` | `SessionLifecycleService.createSession(ctx.user.id, input, ctx.idempotencyKey ?? "", ctx.locale)` |
| `startSession` | `startSession(id: ID!): Session!` | `$all { authenticated: true, role: [UserRole.Teacher] }` | `SessionLifecycleService.startSession(ctx.user.id, Number(args.id), ctx.locale)` |
| `completeSession` | `completeSession(id: ID!): Session!` | `$all { authenticated: true, role: [UserRole.Teacher] }` | `SessionLifecycleService.completeSession(ctx.user.id, Number(args.id), ctx.locale)` |
| `cancelSession` | `cancelSession(id: ID!, reason: String): Session!` | `{ authenticated: true }` ONLY — participant predicate is SERVICE-side (REQ-032/D8); a single-key map needs no `$all` wrapper | `SessionLifecycleService.cancelSession(ctx.user.id, Number(args.id), args.reason ?? null, ctx.locale)` |

401/403 split (mirrors `query/teachers/applicant.query.ts`, verified against `@pothos/plugin-scope-auth@4.1.7`): explicit `$all` conjunctions everywhere a role leg exists; anonymous → `UNAUTHORIZED`/401 (explicit scope throw passes through `builder.ts` verbatim); authenticated wrong-role → localized `FORBIDDEN`/403. On `createSession` the `role: [Student]` leg IS the Ruling 2026-08-30 (B3) surface: teacher-role callers (certified OR applicant) are unconditionally FORBIDDEN — honest denial, never an existence oracle (REQ-064 cell as amended; REQ-011 carve-out struck → D7; REQ-032 static scope stands).

Resolver-local details that matter:
- `Number(args.id)` is a shape-only ID→number boundary parse on start/complete/cancel; the service re-validates as a positive safe integer and classifies every zero-row miss (unknown ≡ foreign ≡ `SESSION_NOT_FOUND`; wrong state → `SESSION_INVALID_TRANSITION`; decertified complete → `TEACHER_NOT_CERTIFIED`).
- Every mutation passes `ctx.locale` (localized messaging happens inside the service); the narrowing guard (`if (!ctx.user)`) throws `UnauthorizedError` with the `builder.ts`-verbatim message — TypeScript narrowing only, unreachable in practice.
- All imports top-level static (gate A1); resolvers carry NO branching beyond delegation.

## 3. idempotencyKey flow (propagation-only — REQ-014, gateway Rule 3, docs/IDEMPOTENCY.md)

- The key rides through VERBATIM exactly as captured by `createGraphQLContext` (`ctx.idempotencyKey`): NEVER re-derived, NEVER trimmed, NEVER consultable by any authorization decision.
- An absent header arrives as `null` and coalesces to `""` SOLELY to satisfy the service's string parameter — the empty key hits the service's own `idempotencyKeyRequired` guard → `VALIDATION`, pre-DB.
- The suite proves the propagation shape end-to-end: a KEYED client whose booking is denied for an unrelated reason (applicant's `users.id` as `teacherId`) surfaces `TEACHER_NOT_FOUND` — and because a denial's claim rolls back with its denial, the probe key is never burned (the `studentProbe` client is fresh-per-run for exactly this reason).
