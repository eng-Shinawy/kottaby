**Primary guarded statement** — built with the file's established write idiom (`tx.update(teacher).set(…).where(…).returning()`), the direction guard fused into the WHERE clause as ONE pinned predicate (the direction is a BOUND PARAMETER, never a JS branch — the statement text never varies):

```typescript
const [row] = await tx
  .update(teacher)
  .set({
    isOnline,
    wasOnlineBeforeLock: sql`CASE WHEN ${teacher.wasOnlineBeforeLock} IS NULL THEN NULL ELSE ${isOnline}::boolean END`,
    updatedAt: sql`now()`,
  })
  .where(
    and(
      eq(teacher.id, id),
      sql`(${isOnline} = false OR NOT EXISTS (SELECT 1 FROM ${session} WHERE ${eq(session.teacherId, id)} AND ${eq(session.status, SessionStatus.Started)}))`
    )
  )
  .returning();
return row ?? null;
```

**Rendered SQL (verified via a `.toSQL()` probe against the live builder, probe file deleted immediately after; params shown for `isOnline=true, id=42`):**

```sql
UPDATE "teacher"
SET "is_online" = $1,                       -- bound param: the intent
    "was_online_before_lock" = CASE WHEN "teacher"."was_online_before_lock" IS NULL
                                     THEN NULL ELSE $2::boolean END,
    "updated_at" = now()
WHERE "teacher"."id" = $3                   -- bound param: id
  AND (($4 = false OR NOT EXISTS (SELECT 1 FROM "session"
        WHERE "session"."teacher_id" = $5 AND "session"."status" = $6)))  -- $4: direction, $6: 'started'
RETURNING "id", "is_approved", "is_evaluator", "average_rating", "is_online",
          "was_online_before_lock", "subjects", "request_preference", "created_at", "updated_at"
```

— i.e. exactly the plan §4.3 pinned statement (marker CASE `WHEN was_online_before_lock IS NULL THEN NULL ELSE $online END`; Available-direction `NOT EXISTS(started)` guard; `updated_at = now()`; `RETURNING *` via the file's `.returning()` column-enumeration idiom). **One documented empirical addition:** the `::boolean` cast on the CASE's ELSE param — an all-untyped CASE resolves to `text`, which cannot assign into the boolean column at the driver; the cast is parameterization-preserving and semantically identical to the pinned `ELSE $online END` (docblock + test pin both record why). The guard predicate mirrors the repo's EXISTS precedent (`session.repository.lifecycle.helpers.ts:56`); `SessionStatus` is the VALUE import (`eq(session.status, SessionStatus.Started)`), never a string literal.

**Semantics (docblock, domain language):**
- **Marker CASE — never minted, never consumed:** a marker-less row stays marker-less (minting one would corrupt the release's `no_lock_held` classification), while a HELD marker is re-stamped with the intent value — the in-session toggle IS the pre-lock intent now, so the eventual release restores the DELIBERATE decision (disputed-window consistency, REQ-009).
- **Direction guard — the security control:** Unavailable (`$4 = false`) short-circuits the probe — going offline is always permitted, even mid-session (the held marker re-stamps to `false` so the release cannot resurrect availability the teacher explicitly withdrew); Available requires zero `started` sessions for THIS teacher id — the RACE-CLOSED write: a toggle racing a session start can never flip a locked teacher back online (INV-A2 at write time).
- **Zero-row null is the miss signal; the SERVICE tier disambiguates** (the standard repo convention — no deviation here): row absent on the Unavailable direction, or the race-blocked Available direction, decided by the caller's preceding in-transaction existence read.
- **Required-tx** (no `tx?:` — calling without one is a compile error); **repo trusts the typed boolean** — runtime type-guarding of untrusted input stays in the service layer (pinned: no `typeof isOnline` in the slice).
- Zero plan-artifact references (file-wide static pin enforces); zero `--`, no prepared statements, no i18n/logging.
