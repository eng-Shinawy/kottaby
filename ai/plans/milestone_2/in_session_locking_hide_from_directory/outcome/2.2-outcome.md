### Tier-4 empirical deviation (recorded, not silently "fixed")

The task text pinned "hostile ids (0, -1, NaN, 2^53) → NULL (zero rows), no throw". **Empirical probe against the live PostgreSQL (`app_db`) proves `NaN` and `2^53` CANNOT return `null` without a JS-side guard that would violate the pinned single-statement shape:** `NaN` binds as the string `"NaN"` and fails the int4 parse gate (`22P02 invalid_input_syntax`); `2^53` overflows the id column's int4 domain (`22003 numeric_value_out_of_range`). The suite therefore splits Tier 4 truthfully, mirroring the repo precedent `backend/db/test/repo/classes/progress.repository.test.ts:509-545` (in-domain misses + savepoint-bracketed raw driver-error probe):

1. `0`, `-1`, far-beyond-sequence (`absentTeacherId`) ⇒ `null`, no throw, row population unchanged (count before/after).
2. `Number.NaN` ⇒ raw `22P02`; `2 ** 53` ⇒ raw `22003` — each probed inside its own savepoint bracket (`expectRepoError` + `hasPostgresErrorCode` on the Drizzle cause chain), then rolled back; zero side effects proven by the unchanged row count. Nothing executes for either id — which is the security property 2.2.SEC actually requires ("hostile-id probes prove zero side effects").
