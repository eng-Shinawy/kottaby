- **Tier-3 race determinism inside `runInRollback`:** two bare releases racing on one row can only yield {released, no_lock_held}; the pinned {released, active_sessions_remain} pair requires the overlapping-exits interleaving (exit A's release attempt RUNS while exit B's session is still live, then B lands). Realize it with a JS `createGate()` holding the second transition until the first release has resolved — safe inside one tx (no DB operation is pending while the gate is open; the single connection never blocks). FIFO ordering on the single connection is otherwise deterministic: statements queue in the order the closures reach their awaits.
