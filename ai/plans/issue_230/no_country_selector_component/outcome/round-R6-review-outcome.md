## Findings

| Severity | Location | Finding |
|----------|----------|---------|
| LOW | `frontend/components/ui/CountrySelector.tsx` + `RegisterIdentityFields.tsx:97-107` | **Country controller ref is never bound — submit-failure focus skips the country field.** `CountrySelectorProps` exposes no ref/`inputRef`, so `countryField.field.ref` is dropped; the gender `Select` binds `inputRef={genderField.field.ref}`, making country the only register-form field without a bound ref. Verified in RHF 7.88 dist that the `shouldFocusError` submit walker requires the attached ref's `focus()` (controller refs install it only when `field.ref` reaches an element), so a failed submit with country as the (only) error focuses nothing. Validation/errors/announcement are unaffected (helper node is a live region). Matches plan D5's interface (which also omits ref) — a design-level nicety, not a deviation. Fix: optional `inputRef` prop merged into `params.slotProps.htmlInput` (alongside the existing onBlur chain), wired to `countryField.field.ref`. |
| INFO | `useRegisterFormState.ts:80-84` | The `validate` empty-string branch (`return t.countryCodeRequired`) is unreachable at runtime: RHF's required rule fires and returns before validate for empty values (dist-confirmed; the integration test likewise reports `type:"required"` for empty). Harmless defensive copy-splitting that mirrors the service's partition — worth a one-line comment, no change required. |
| INFO | `RegisterIdentityFields.tsx:36` vs `useRegisterFormState.ts:91-105` | Pattern asymmetry: gender/role/recitation pin their degraded values in the hook (`selectedGender` passed alongside the field), while the country pin (`countryFromValue`) happens inside `RegisterIdentityFields`. Functionally equivalent (no prop drift, no extra re-renders) and arguably better encapsulated — noting so the pattern is a conscious choice, not drift. |
| INFO | `frontend/components/ui/CountrySelector.test.tsx:388-389` | The Tier-4 XSS test probes the component **source file** via `Bun.file(new URL("./CountrySelector.tsx", import.meta.url))`, coupling the suite to the worktree layout; in this review's first run it failed with ENOENT when the sandbox flipped the worktree mid-run (the exact artifact documented in outcome 7.2). Two clean re-runs confirm it is environmental, not a code defect — but an inline/guarded probe would remove the environment-coupled flake surface. Related contract note: `getOptionLabel` is total over dataset members and prototype keys only; a raw non-member `value` (impossible through both real consumers, which pin via `countryFromValue`/`isValidCountryCode`) would throw — consistent with the documented "consumer owns validation" posture. |
