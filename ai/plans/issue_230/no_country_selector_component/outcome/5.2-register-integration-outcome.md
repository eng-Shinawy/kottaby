## Summary

The register form's free-text country `TextField` is replaced by the shared
`CountrySelector` (5.1). The country field is owned by a dedicated RHF
`useController` in `useRegisterFormState` (defaultValues keep
`country: ""` at `useForm`; **no `@hookform/resolvers` added** — the raw value
is gated inline by `countryCodeSchema.safeParse`, splitting empty →
`countryCodeRequired` vs non-member → `countryCodeInvalid` exactly like
`RegistrationService.validateInput` does on the unchanged `country` field
path). The identity grid binds the picker to the controller
(`name`, pinned value via the new `countryFromValue` guard, `onBlur` chaining,
`error`/`helperText` projection from the existing
`projectMutationFieldErrors`/`applyProjectedFieldErrors` pipeline). The server
error contract from 3.3 (`{ field: "country", code: "COUNTRY_CODE_REQUIRED" |
"COUNTRY_CODE_INVALID" }`) projects onto the same field with zero changes to
`mutationFieldErrors.ts`. Client validation is advisory only — the server
re-validates (defense in depth).
