## 1. Summary

The admin **create** path now validates `country` with the shared `countryCodeSchema` (`@/shared/lib/country-code`) — the exact schema public registration uses (no drift) — emitting `COUNTRY_CODE_REQUIRED` (absent/blank/whitespace-only) or `COUNTRY_CODE_INVALID` (anything else failing the normalize→membership pipeline: legacy free text, over-length strings, valid-shape non-members, curated-out codes) on field path `country`, with messages from the typed keys `tAuth.countryCodeRequired` / `tAuth.countryCodeInvalid`. The dead free-text branches (`COUNTRY_REQUIRED`, `COUNTRY_TOO_LONG`) were removed from `validateCreateInput` (deferred-items P1 anticipated the TO_LONG branch would become unreachable for ISO-2 codes). `buildCreateUserInsert` now writes the normalized ISO code to `countryCode` and the English display name (`COUNTRIES[code].en`) to the legacy `country` column — explicit field-by-field, never a spread. `validateUpdatePatch` is byte-identical untouched (free-text `country`, D-4).

## 3. Validation changes (exact)

```typescript
// validateCreateInput — country branch (field path stays "country")
if (typeof input.country !== "string" || input.country.trim().length === 0) {
  entries.push({ field: "country", code: "COUNTRY_CODE_REQUIRED", message: tAuth.countryCodeRequired });
} else {
  const parsedCountry = countryCodeSchema.safeParse(input.country);
  if (!parsedCountry.success) {
    entries.push({ field: "country", code: "COUNTRY_CODE_INVALID", message: tAuth.countryCodeInvalid });
  }
}

// buildCreateUserInsert — normalized code + display name, field-by-field (BOPLA)
const parsedCountry = countryCodeSchema.safeParse(input.country);
const countryCode = parsedCountry.success ? parsedCountry.data : null;
return {
  /* …explicit fields… */
  countryCode,
  country: countryCode !== null ? COUNTRIES[countryCode].en : input.country,
  /* …server-controlled governance defaults unchanged… */
};
```

- The `typeof` guard mirrors 3.3's parallel landing (`registration.service.ts` country branch) so both services share the identical REQUIRED/INVALID partition for any runtime input.
- `parsedCountry.data` is the already-normalized uppercase `CountryCode` (1.2 contract) — persisted directly, never re-normalized; `COUNTRIES[...]` lookup is member-typed so it cannot be polluted.
- The builder's failure arm is NOT dead: `buildCreateUserInsert` is exported, and a direct call with unvalidated free-text degrades to the legacy free-text row (`countryCode` null) rather than persisting an unmapped code — pinned by a dedicated test.
- Dead-branch resolution: `COUNTRY_REQUIRED` + `COUNTRY_TOO_LONG` + `MAX_COUNTRY_LENGTH` usage are GONE from the create path; `MAX_COUNTRY_LENGTH` remains a live constant for `validateUpdatePatch` (kept, no unused constant).
