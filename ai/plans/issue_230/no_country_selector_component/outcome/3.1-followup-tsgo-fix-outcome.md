## Problem

Task 3.1 added `countryCode: varchar("country_code", { length: 2 })` (nullable) to
`backend/db/schema/users/users.ts`. `UserSelectType.countryCode` became a required
(`string | null`) property, so every full user-row **literal** typed against the user
select/row shapes (and every projection expected to match those shapes) stopped
compiling: 17 `error TS` entries — the plan's Phase-0 baseline is 0.

## Fix applied (one minimal additive edit per site)

### Projection / mapper pipeline (3 files — resolves errors 1–4 and 14)

- `backend/db/repo/admin/admin-user-query-helpers.ts` — `SAFE_USER_SELECT` gains
  `countryCode: users.countryCode`. This is the ONE canonical safe-projection spot: the
  four guarded write paths (`updateProfileFields`, `setDeletedOnce`,
  `setSuspendedOnce`, `setBlockedOnce`) use `.returning(SAFE_USER_SELECT)`, and
  `findDetailById` spreads it, so the returned rows again match
  `AdminUserSafeSelect = Omit<UserSelectType, "passwordHash">` structurally.
- `backend/db/repo/admin/admin-user-row-types.ts` — `AdminUserDetailRow` gains
  `readonly countryCode: string | null` (the raw detail row now carries the column via
  the spread projection).
- `backend/services/admin/user-management.mappers.ts` — `assembleDetail` literal gains
  `countryCode: row.countryCode` (threaded through verbatim; the GraphQL entity type
  does not expose the field, so the wire surface is unchanged).

### User-row fixtures (10 files)

Semantics applied: `countryCode` is the normalized ISO-3166-1 alpha-2 code, nullable.
Coded-row fixtures use `"EG"` only where the fixture's `country` display string equals
`COUNTRIES["EG"].en` (`"Egypt"`); legacy/unsure rows use `null`. Fixture data stays
internally consistent.

## Carry-forward

Adding a property to a table schema (hence to `*SelectType`) silently breaks every
full-row literal (fixtures, mocks, seeds, mappers) and every explicit projection that
must stay structurally identical to the row type. Before/when adding a column: grep for
full-row literal constructions and for explicit `select({...})`/`returning({...})`
shapes of that table, and extend them in the same task (or log the follow-up in
`deferred-items.md` immediately — see `D-IP-1`).
