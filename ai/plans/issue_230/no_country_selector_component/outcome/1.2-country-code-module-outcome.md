## 1. Summary

Implemented `shared/lib/country-code.ts` — the single cross-tier country-code validation authority — with the exact D3 export surface, plus its colocated 4-tier test `shared/lib/country-code.test.ts`. The module normalizes (trim + uppercase) **before** the `COUNTRY_CODES` membership check in the zod pipeline, keeps a strict normalization-free type guard (so `value is CountryCode` narrowing is sound), and provides a case-insensitive shape-only schema for membership-free pre-checks.

## 2. Exact export surface (D3 — implemented verbatim)

```typescript
export const COUNTRY_CODE_PATTERN: RegExp;                    // /^[A-Z]{2}$/ (anchored, uppercase, stateless — no g flag)
export function normalizeCountryCode(raw: string): string;    // raw.trim().toUpperCase()
export function isValidCountryCode(value: unknown): value is CountryCode;
export const countryCodeSchema: z.ZodType<CountryCode>;       // z.string().transform(normalizeCountryCode).pipe(z.enum(COUNTRY_CODES))
export const countryCodeShapeSchema: z.ZodType<string>;       // z.string().regex(/^[A-Za-z]{2}$/) — any-case, no membership, no normalization
```

Module-private (NOT exported): `ISO_SHAPE_ANY_CASE` (`/^[A-Za-z]{2}$/`) and `COUNTRY_CODE_SET: ReadonlySet<string>` (`new Set(COUNTRY_CODES)` — O(1), prototype-chain-free so `"__proto__"` can never resolve as a member).

**Design rationale locked in code:**
- **Guard is strict on the RAW value.** `isValidCountryCode("eg")` / `(" EG ")` → `false`. Normalizing inside the guard would make `value is CountryCode` unsound (the runtime value would not be a `CountryCode`). Unnormalized input goes through `countryCodeSchema` (REQ-2 AC7 path). The `typeof value === "string"` conjunct makes the guard return `false` for every non-string (incl. `null`/`undefined`) without throwing.
- **Schema = normalize → membership.** `z.string().transform(normalizeCountryCode).pipe(z.enum(COUNTRY_CODES))`: the transform runs before the enum pipe, so `" eg "` → `"EG"` (accepted) while `"EGY"`/`"Egypt"`/`"XX"` fail. Non-strings fail at the `z.string()` stage with `{ success: false }` — parsing never throws.
- **Membership is dataset-based, not regex-based.** `z.enum(COUNTRY_CODES)` IS the `COUNTRY_CODES` membership check (compiled by zod into an exhaustive literal set), so `XX`/`AA` and curated-out codes (`IL`, `XK`, …) are rejected even though they match the shape — the mandatory service-side gate for codes the `graphql-scalars` wire resolver still accepts (S-1 defense-in-depth).
- **Shape schema is case-insensitive and pass-through** (REQ-2 AC4): `safeParse("XX")` SUCCEEDS (shape-only), data is returned untouched (no trim, no uppercase) — the wire's own full-ISO-list scalar enforcement is the separate layer.
- **zod v4 conventions** mirrored from the repo's only existing zod module (`backend/types/classes/admin-session-governance.types.ts`): `import { z } from "zod"`, `.refine`/`.pipe`, exported schema constants annotated with their contract type (`z.ZodType<CountryCode>` compiles clean under tsgo — v4's `ZodType<out Output, out Input>` covariance accepts it).

## 5. Carry-forward knowledge (for tasks 3.2–3.4, 2.1, 5.x)

**Consumption contract (stable — import exactly these):**

```typescript
import {
  COUNTRY_CODE_PATTERN,
  countryCodeSchema,
  countryCodeShapeSchema,
  isValidCountryCode,
  normalizeCountryCode,
} from "@/shared/lib/country-code";
```

- **Backend services (3.2/3.4):** use `countryCodeSchema.safeParse(input.country)`. On failure, emit `COUNTRY_CODE_INVALID`; treat empty/missing (`""`, whitespace-only) as `COUNTRY_CODE_REQUIRED` — the empty check must stay separate (empty fails the schema too, but the REQUIRED code takes precedence per the plan's draft branch). On success, `result.data` is already the normalized uppercase code — persist it directly; do NOT re-normalize.
- **Normalized display name:** `COUNTRIES[result.data].en` (dataset module) supplies the legacy `country` display value (3.3).
- **`IL`/`XK` case:** the graphql-scalars wire resolver (task 2.1) will still accept them (its own full-ISO list); only `countryCodeSchema` rejects them. The service membership check is therefore NOT redundant — do not "simplify" it away.
- **Type guard vs schema:** frontend pinning helpers (5.2 `countryFromValue`) can use `isValidCountryCode` for exact-value narrowing (`CountryCode | ""`), but form-field validation of raw user input must use `countryCodeSchema.safeParse` (the guard rejects lowercase/padded raws by design).
- **`countryCodeShapeSchema` is intentionally loose** (any-case, pass-through, no membership): suitable only for pre-checks where dataset membership is deliberately not required; it does NOT replace the full schema anywhere.
- **zod v4 note for future shared schemas:** `z.enum(<as const readonly tuple>)` compiles fine with a 255-member tuple under tsgo; `z.ZodType<T>` annotations on piped/transformed schemas are accepted (v4 variance).
