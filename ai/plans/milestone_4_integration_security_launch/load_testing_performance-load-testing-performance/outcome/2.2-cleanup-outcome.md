## Summary

The stub `cleanup-perf-data.ts` entrypoint was replaced with the real manifest-driven cleanup tool plus its supporting library. One invocation hard-deletes every row a seed run created: the run is selected by `--run <hex8>` (specific seed run) or `--last` (newest manifest under `logs/perf/`), the seed manifest is the ONLY write-scope contract, rows are deleted strictly in the manifest's FK-safe `tables` order (children first, `users` last), and — after the deletes — every one of the nine tables is re-probed for rows still matching the escaped prefix pattern (`perf\_<runId>\_%`) with success defined as zero residue. `assertTestDatabaseTarget` is the FIRST effectful call (the `@/backend/db/client` module is imported dynamically only AFTER the guard allows, so no pool object exists before the guard decides), and the selected manifest is validated before any database seam runs: the prefix must equal `perf_<runId>_` and the table list must deep-equal the canonical FK-safe order, so a tampered or foreign manifest can never broaden the delete scope. Cleanup is idempotent by construction — deletes are prefix-predicate-based, so a second run (or a retry after an interrupted pass) deletes whatever still matches and re-probes to zero; proven live in the smoke. The CLI keeps the stub's semantics (unknown flag → exit 2, non-`--` tokens are flag values) and adds `--force-prod-shaped-target` (REQ-1.7's guard override, symmetric with the seeder).

**Lint-forced notes (no plan deviation in shape):** the plan named two files; the repo's oxlint `max-lines`/`max-lines-per-function` and `consistent-return`/`different-types-comparison` rules drove the same decomposition discipline as 2.1 — the pure library lives under `scripts/perf/lib/` (map below), all consumed, knip-clean, and the entrypoint keeps the registered path/name byte-identical. ## CLI Contract (exact — binding for later tasks)

```text
bun --env-file=.env.test scripts/perf/cleanup-perf-data.ts
  --run <hex8>                       (^[0-9a-f]{8}$ — injection-shaped values rejected at parse)
  --last                             (newest manifest under logs/perf/)
  --force-prod-shaped-target         (boolean; guard override passthrough — exactly one selector required)
```

Validation → exit 2: unknown `--flag` (message lists unknown + accepted flags, each unknown reported once), missing `--run` value, `--run` + `--last` together, no selector at all, malformed run id. Non-`--` tokens are flag values and ignored (stub-compatible). Repeated flag: last wins.

**Exit codes:** 0 = cleaned with zero residue · 2 = usage refusal / guard refusal / unusable manifest (missing, corrupt, or untrusted) · 1 = residue after cleanup or runtime failure. Partial-delete failures carry an actionable `CleanupDeleteError` message (failed table, already-cleaned tables, remaining tables, "re-run the same cleanup command to complete") — never a silent continue.

**Idempotency ruling (picked and tested):** cleanup NEVER deletes the manifest — a second `--run <id>` resolves the same manifest, deletes 0 rows, probes 0, exits 0. Re-running after an interrupted pass completes the remaining tables (unit-proven; live-proven in the smoke).

## Manifest Consumption Contract (from 2.1, enforced)

- **Location:** `logs/perf/<YYYY-MM-DDTHH-MM-SS>[-N]_seed/seed-manifest.json` — discovered by scanning run directories (name pattern-validated, path-containment-checked), sorted newest first by directory stamp + collision suffix (unsuffixed = first, `-2` = newer).
- **Validation before ANY database work:** shape (runId/prefix/tables fields present), runId hex8, `prefix === "perf_<runId>_"`, `tables` deep-equal the canonical order `notifications → session → subscriptions → wallet → plans → teacher → students → admin → users`. Any deviation → exit 2, refused untrusted.
- **Selection:** `--last` → newest entry; newest unreadable (corrupt JSON) → actionable error naming the file + escape hatch (`--run <id>`); zero manifests → "nothing to clean up". `--run <id>` → newest readable manifest for that run id; corrupt entries skipped (and noted in the not-found error); no match → error listing available run ids.
- **Deletion scoping:** the escaped pattern `perf\_<runId>\_%` (canonical `escapeLikeWildcards`) bound as a LIKE parameter. Tables with a prefix column match it directly (`users.email`/`users.full_name`, `students.handshake_code`, `plans.title`, `subscriptions.payment_reference`, `notifications.title`); tables without one (`teacher`, `wallet`, `session`, `admin`) are scoped through the owning prefixed `users` rows via `IN (SELECT id FROM users WHERE email LIKE pattern)` subqueries — join-armed predicates additionally match their prefixed column where one exists. Only this run's rows can ever match.
- **Crashed runs are cleanable:** `completedAt: null` manifests (interrupted seeds) are fully valid cleanup targets — the crash-discoverability contract from 2.1 pays off here.
