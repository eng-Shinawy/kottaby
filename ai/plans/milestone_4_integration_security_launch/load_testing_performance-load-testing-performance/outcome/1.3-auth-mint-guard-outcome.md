## Module Contracts (as built — exact signatures)

### `db-target-guard.ts`

```ts
export const TEST_DATABASE_NAME = "kottaby_test";
export interface DatabaseTarget { dbName: string | null; host: string | null }
export type DatabaseTargetAssessment =
  | { allowed: true;  dbName: string;      host: string | null; reason: string }
  | { allowed: false; dbName: string|null; host: string | null; reason: string };
export interface DatabaseTargetOk { ok: true; dbName: string }
export function resolveDatabaseTarget(databaseUrl: string): DatabaseTarget
export function assessDatabaseTarget(databaseUrl: string): DatabaseTargetAssessment
export function formatDatabaseTargetRefusal(assessment: DatabaseTargetAssessment): string
export function assertTestDatabaseTarget(databaseUrl: string, opts?: { forceFlag?: boolean }): DatabaseTargetOk
```

**Binding semantics for every perf entry point (Tasks 2.1, 2.2, 6.1, 8.1):**

- Call `assertTestDatabaseTarget(process.env.DATABASE_URL ?? "", { forceFlag })` FIRST, before any DB client is constructed. It returns `{ ok: true, dbName }` only when the target is `kottaby_test` (silent on success) or a forced override was confirmed; on any other target it prints the refusal block to **stderr** and calls `process.exit(2)` — control never returns. There is no catchable exception on refusal (destructiveDbGuard posture, operator-bypass-proof by construction).
- **Resolution mirrors `pg` exactly** — the validated name IS the connected name. Supported shapes (all unit-proven): `postgres://` / `postgresql://` URLs (any-case scheme), URL-encoded credentials (`%40`-embedded `@`), raw `@` inside passwords (WHATWG last-`@` rule), query params (`?sslmode=`, `?host=` overrides — including the encoded-unix-socket-host pathname-prepend branch), IPv6 `[::1]` hosts, percent-encoded db names (`%5F` decodes → allows; `%2F` stays encoded → refuses), the unix-socket space form (`/var/run/postgresql kottaby_test`), and `socket:` URIs (`?db=`). The pg parser's `encodeURI` space/broken-escape pre-pass + `@___DUMMY___/` empty-host retry are mirrored verbatim, so e.g. a **trailing-space DSN resolves to the name `"kottaby_test "` and is refused** (pg itself would connect to that literal name — refusing is parity, not a false positive).
- **Strictness rulings (fail-closed):** db-name comparison is exact-string (`KOTTABY_TEST`, `kottaby_test_extra`, `kottaby-test`, `kottaby_test `, `kottaby%2Ftest`, empty/missing name, whitespace-only, key-value parts-style — all refused; pg-connection-string cannot consume parts-style DSNs either, so refusal is parity). Unparseable DSNs → dbName `null` → always refused, even with the force flag (there is no name to confirm against).
- **Force override:** `opts.forceFlag === true` (strict boolean) PLUS a stdin confirmation that repeats the resolved db name exactly (`readSync`-based, bounded at 128 bytes, `\r`/whitespace-trimmed, never echoes the typed answer). Wrong answer / EOF / closed stdin / read error → exit 2.
- **Secret hygiene:** refusal and confirmation output name the database and host ONLY — usernames and passwords never appear (asserted in tests); unprintable bytes in a resolved name are masked and the display is capped at 80 chars (log-injection guard). The pure `assessDatabaseTarget` / `resolveDatabaseTarget` / `formatDatabaseTargetRefusal` trio is deterministic, side-effect-free, and safe for concurrent callers (proven by rapid-fire stability test).

### `auth-mint.ts`

```ts
export interface MintedSession { userId: number; email: string; cookieHeader: string }
export class AuthMintError extends Error {}
export const ACCESS_TOKEN_COOKIE_NAME = "access_token";
export const LOGIN_MUTATION_DOCUMENT =
  "mutation PerfHarnessMintLogin($email: String!, $password: String!) { login(email: $email, password: $password) { user { id } } }";
export function parseSetCookiePair(header: string): { name: string; value: string } | null
export function collectCookiePairs(setCookieHeaders: readonly string[]): ReadonlyMap<string, string>
export async function mintSessionCookie(baseUrl: string, email: string, password: string): Promise<MintedSession>
```

**Binding semantics for the load harness (Tasks 6.1, 8.1):**

- **How login is reached (mechanism):** plain `fetch` POST of `LOGIN_MUTATION_DOCUMENT` to `${baseUrl}/api/graphql` (baseUrl = server root; an explicit `/api/graphql` path is used as-is; trailing-slash roots gain `/api/graphql`) with `Content-Type: application/json` and `{ query, variables: { email, password } }` — the same wire contract as the repo's `scripts/browser-login.ts` login. The selection asks only for `user { id }`; the tokens travel exclusively in the server's httpOnly `Set-Cookie` values (`access_token`, `refresh_token`, `session_id` — pushed unconditionally by the login resolver), so no token ever appears in the JSON body. A non-browser fetch sends neither `Origin` nor `Sec-Fetch-Site`, which the route's CSRF origin-guard (`app/api/graphql/origin-guard.ts:27-31`) explicitly passes — no extra headers needed.
- **Return value:** `cookieHeader` is a ready-to-send `Cookie` header value with the three auth cookies in canonical order, e.g. `access_token=<jwt>; refresh_token=<jwt>; session_id=<id>`. It authenticates both the API load path (SSR/GraphQL cookie auth) and the WS handshake (`backend/ws/notification-ws-server-handshake.ts:88-90` reads `access_token` as the only identity source). **In-memory only — never logged, never reported, never persisted** (REQ-12.6; console-silence proven by test).
- **Server requirements for minting:** just the target server's `/api/graphql` over HTTP — under the load harness that is the production-mode test server booted per REQ-6 conventions (`TEST_SERVER=1` + `IS_DEMO=true` limiter bypass); identities come from the seed manifest (Task 2.1). Rate limiting is bypassed by that boot env, so ~1 mint per VU at ramp start is safe. No 1.3 test needs a live server (stub-server + subprocess proofs below).
- **Credentials are sent byte-for-byte** — passwords are never trimmed or transformed (SQL-ish/Unicode/whitespace-only payloads round-trip unchanged, asserted). Arguments validated before any network work: baseUrl must be an absolute http(s) URL; email must be non-blank; password must be non-empty.
- **Failure taxonomy (all typed `AuthMintError`):** invalid baseUrl/args (no request issued); network failure (cause preserved via `Error.cause`); non-2xx status (message carries the status code only — body never echoed); non-JSON body; unexpected body shape (non-objects and arrays are shape violations); GraphQL `errors` array (messages joined, scrubbed of the submitted email+password via split/join `[REDACTED]`, capped at 300 chars); missing/non-integer user id; missing/empty `access_token` cookie. `parseSetCookiePair` reads only the first `;`-separated segment (Expires-comma forms and attributes never corrupt the pair) and keeps `=` padding inside values; `collectCookiePairs` gives duplicate names last-value-wins.
