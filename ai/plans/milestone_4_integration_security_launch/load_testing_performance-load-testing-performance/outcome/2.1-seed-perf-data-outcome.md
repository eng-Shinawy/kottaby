## Summary

The stub `seed-perf-data.ts` entrypoint was replaced with the real seeder and its supporting library. One invocation builds the full production-shaped dataset (certified online teachers browsable by the real matching pipeline — with a hot subset carrying `started` sessions that the matcher's NOT EXISTS branch excludes — funded students, one admin, wallets, a 3-lane plan catalog, subscription/session/notification volumes), guarded by `assertTestDatabaseTarget` as the FIRST effectful call (the `@/backend/db/client` module is imported dynamically only AFTER the guard allows, so no `pg.Pool` object is ever constructed before the guard decides), refusing re-runs whose prefix already holds rows, and writing `seed-manifest.json` BEFORE the first insert (crash discoverability) with an atomic finalize after the last one. ## CLI Contract (exact — binding for 2.2 and later tasks)

```text
bun --env-file=.env.test scripts/perf/seed-perf-data.ts
  --teachers <n>          default 2000    (0..1,000,000)
  --students <n>          default 120
  --sessions <n>          default 5000
  --notifications <n>     default 20000
  --subscriptions <n>     default 500
  --hot-teachers <n>      default 8       (must be ≤ --teachers)
  --run-id <hex8>         default: random 4 bytes hex (^[0-9a-f]{8}$)
  --seed <n>              default 0       (0..2,000,000,000 — determinism knob)
  --force-prod-shaped-target              (boolean; passes forceFlag to the 1.3 guard)
```

Validation → exit 2: unknown `--flag` (message lists unknown + accepted flags, each unknown reported once), missing flag value, non-integer/negative value, value above the cap, `--hot-teachers > --teachers`, `--sessions > 0` with `--teachers 0` or `--students 0`, `--subscriptions > 0` with `--students 0`, malformed `--run-id` (injection-shaped values rejected by the `^[0-9a-f]{8}$` pattern — Tier-4 tested). Non-`--` tokens are treated as flag values and ignored (stub-compatible). Repeated flag: last wins.

**Exit codes:** 0 = seeded · 2 = usage refusal / guard refusal / prefix collision · 1 = runtime failure (message notes partial rows stay discoverable by prefix + manifest).

**Idempotency ruling (picked and tested):** re-running the same `--run-id` **REFUSES** — preflight `countUsersWithEmailLike` over the escaped prefix returns > 0 → exit 2 with "run perf:cleanup --run <id> first, or pass a fresh --run-id". This doubles as the concurrent-seeder guard (a second process holding the same prefix cannot interleave). Proven live in the smoke (second invocation → exit 2, no new run dir).

## Manifest Contract (exact — task 2.2 consumes this)

**Location:** `logs/perf/<YYYY-MM-DDTHH-MM-SS>_seed/seed-manifest.json` (via the 1.1 `openRunDirectory("seed")` convention: 0700 dir, same-second collisions suffixed `-2`, `-3`, …). Written BEFORE the first insert with `completedAt: null` (crash discoverability — REQ-12 Reliability 2), finalized atomically after the last insert (sibling `.tmp` write + rename, 0600, `wx` clobber-guard).

**Schema (as landed):**

```jsonc
{
  "runId": "5eedc0de",                       // 8 lowercase hex
  "prefix": "perf_5eedc0de_",                 // see Prefix Format below
  "startedAt": "2026-10-09T04:09:48.401Z",   // ISO
  "completedAt": "2026-10-09T04:09:48.625Z",  // null while the run is in progress / crashed
  "database": "kottaby_test",                 // from the guard's resolution
  "tables": ["notifications","session","subscriptions","wallet","plans","teacher","students","admin","users"], // FK-safe DELETE order: children first, users LAST
  "counts": { "users": 2121, "teacher": 2000, "student": 120, "session": 5000, "notification": 20000, "subscription": 500, "wallet": 2000, "plan": 3 },
  "identities": {
    "studentEmails": ["perf_<id>_student000000@test.local", "..."],  // ALL students
    "adminEmails": ["perf_<id>_admin@test.local"],                   // exactly one admin per run
    "wsIdentityEmails": ["..."],   // admin + first 20 students + teacher fill, capped at 25 (≥21 at every usable volume)
    "hotTeacherEmails": ["..."],   // first --hot-teachers teacher emails
    "passwordHash": "$2b$12$...",  // bcrypt hash of the per-run credential (hashPassword, 12 rounds — hashed ONCE per run, reused across rows)
    "passwordNote": "random per run (derived from the run id); never persisted in plaintext — bcrypt hash only"
  }
}
```

**Deviations from the plan's sketch (documented):** `counts.plan` added (plans are created rows — manifest completeness); `counts.wallet` is the teacher count (2000 at defaults), not the sketch's 120 — the `wallet` table is teacher-owned per schema (`backend/db/schema/billing/wallet.ts`), so the sketch's 120 was a copy-paste artifact; `tables` (cleanup order contract) and `completedAt` added; `identities` gained `passwordHash` + `hotTeacherEmails`. **Password derivation:** `buildRunPassword(runId) = "perf-load-" + runId` — random per run (run id is per-invocation), never persisted in plaintext; 6.1/8.1's login scenario reconstructs it from the run id (the only design compatible with "identities drawn from the seed manifest" AND "never persisted in plaintext").

## Prefix Format (exact — 2.2's cleanup scans)

- **`prefix = "perf_" + runId + "_"`** (e.g. `perf_5eedc0de_`), stamped into: `users.email` AND `users.full_name`, `students.handshake_code`, `plans.title`, `subscriptions.payment_reference` (NULL for `pending` rows — no gateway reference before settlement), `notifications.title`.
- **Prefix scan pattern:** `escapeLikeWildcards(prefix) + "%"` → `perf\_5eedc0de\_%` (backslash-escaped `_`; the canonical `@/backend/lib/db/escape-like-wildcards` helper — LIKE's default backslash escape applies). The preflight probe uses exactly this pattern.
- **Tables with NO natural prefix column:** `teacher`, `wallet`, `session`, `admin` — reachable by join to prefixed `users` (teacher/students/admin/wallet CASCADE on user delete; **`session` and `subscriptions` are RESTRICT** — they MUST be deleted before `users`; `plans` is RESTRICT from `subscriptions`). The manifest's `tables` array is the FK-safe order: notifications → session → subscriptions → wallet → plans → teacher → students → admin → users.

## Seeded-Data Semantics (binding for 3.x/4.x/6.x/8.x consumers)

- **Matcher eligibility:** every teacher row is `is_online=true`, `is_approved=true`, `is_evaluator=false`, owner `is_deleted/suspended/is_blocked=false` (pure mirror `satisfiesMatcherEligibility` unit-proves every row; live smoke re-proved via SQL: 2/2 eligible). Deterministic distributions over `recitations` (1–3 of 6 RecitationReading values, JSON array), `subjects` (JSON array over the session-intent vocabulary `["hifz"]`/`["tajweed"]`/`["hifz","tajweed"]` — the matcher's quoted-token patterns match them), `languages` (0–3 non-Arabic lowercase tokens), `country`/`countryCode` (10 pairs on `users`), `average_rating` (2-decimal strings 0.00–5.00, ~10% NULL so minRating floors exclude someone by construction).
- **Hot subset:** the FIRST `--hot-teachers` teacher ids; they receive the `started` sessions (`computeHotSessionCount`: `min(total, max(hot, ceil(total*0.2)))` → 1000 of 5000 at defaults) — the matcher's NOT EXISTS branch excludes them from browse (INV-A3 exercise) while all other sessions cycle scheduled(45%)/completed(35%)/cancelled(20%) and NEVER attach `started` to a non-hot teacher, so the browsable pool stays at the requested volume (1992 at defaults).
- **Students:** every student `balance_hifz ∈ [4,20]` (≥1 — INV-B4 booking eligibility), ~40% also hold reviews/tajweed balances; `balance_trial = 0`.
- **Subscriptions:** ~78% active (in-window), ~12% expired (past endDate), ~10% cancelled, ~8% pending (NULL dates + NULL reference per the pending-until-paid semantics); settled rows carry `offline_cash` + verifiedAt + unique prefixed reference.
- **Notifications:** all 10 `NotificationType` values, prefixed titles, ~35% read, `createdAt` spread over the past 30 days, 60% session-pointed (`relatedEntityType="session"` + real session id) when sessions exist.
- **Determinism:** every builder gets `createSeededRandom(\`${runId}:${seed}:<builder>\`)` (FNV-1a fold + mulberry32) — same run-id + same `--seed` → byte-identical rows (unit-proven end-to-end through `runSeedRun` with fakes).
