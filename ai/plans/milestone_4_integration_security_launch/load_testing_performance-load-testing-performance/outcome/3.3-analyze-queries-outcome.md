## Summary

The stub `analyze-queries.ts` entrypoint was replaced with the real EXPLAIN query auditor plus five supporting library modules. The auditor executes the **real repository reads** — the registry entries call the actual repository methods (`MatchingTeacherRepository`, `SubscriptionRepository`, `NotificationsRepository.listForUser`, `SessionRepository.listForStudent/listForTeacher`, `UserRepository.findById`) inside a pg `Client.prototype.query` capture window, so every captured SQL statement is the production query byte-for-byte (drift-proof by construction — the repo SQL is never re-typed or copied). Each captured statement is re-executed under `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)` with its parameters re-bound positionally (never spliced), and the JSON plan tree is walked by a cycle-safe, fail-closed plan analyzer. Two gates:

- **`scan-gate`** — any `Seq Scan`/`Parallel Seq Scan` node with `Plan Rows >= --scan-threshold-rows` (default 1000, inclusive; null/unreadable rows count as a breach — fail closed) FAILs the run. CTE scans (`CTE Scan`/`Named Tuplestore Scan`) are reported but are not seq-scan breaches.
- **`matching-session-index`** — every registry entry flagged `requiresSessionIndexCheck` must show the NOT EXISTS subplan reading `session` through `session_teacher_id_status_idx`; a Seq Scan (or any node without that index) FAILs.

Plans persist per entry as `logs/perf/<runDir>/explain/<entryId>.json` (0600, redacted, id-charset-validated), the run flows through the 1.1 report writer (`openRunDirectory("analyze-queries")` → `writeReport` → `emitVerdict`), and the CLI keeps the stub contract (exit 0 pass / 1 gate-or-runtime failure / 2 usage or guard refusal; single flag `--scan-threshold-rows`, no `--json`). `assertTestDatabaseTarget` is the FIRST effectful call; the `@/backend/db/...` modules are imported dynamically strictly after the guard allows (the pool constructs at module load — guard-first is load-bearing, proven by real-subprocess tests: wrong DSN → exit 2 with no run directory created).

**Full-volume evidence run (the pre-3.4 artifact for §6 item 6.4 and Task 3.4's conditional-index decision):** against the Phase-2-seeded `kottaby_test` (seed run `034957e6` — users 2121, teachers 2000, students 120, sessions 5000, notifications 20000, subscriptions 500), the audit analyzed all 18 registry queries and reported `VERDICT: FAIL`, exit 1, with exactly the honest planner evidence: **`scan-gate`: 6 breaches** — `Seq Scan on users (1931 >= 1000)` in the 3 plain matching variants (count + page statement each); the `teacher` seq scan estimates only 48 rows after the `is_online AND is_approved` filter, below the threshold. **`matching-session-index`: 6 breaches** — the same 3 plain variants execute the NOT EXISTS as `Materialize → Seq Scan on session` instead of the index. The filtered matching variants are clean (`subject-language`, `name-search`, `min-rating`: teacher filtered scan → `users_pkey` → `Index Only Scan session_teacher_id_status_idx`), and every list/read entry is clean: `sessions-student-list` → `session_student_id_idx`, `sessions-teacher-list` → `session_teacher_id_status_idx`, `my-subscriptions`/`admin-student-subscriptions` → `subscriptions_user_id_idx`, `notifications-list` → bitmap `notifications_user_id_is_read_idx`, `user-find-by-id` → `users_pkey`. The seed run was cleaned to zero residue (`perf:cleanup -- --last` → 0 rows across 9 tables); the evidence run directory is retained at `logs/perf/2026-10-09T10-57-45_analyze-queries/`.

**Task 3.4 input:** the failing surface is precisely the 3 plain matching variants (unfiltered eligibility window at 2000-teacher volume): the `users` seq scan (1931 rows) feeds a hash join with the 48-row teacher scan, and the NOT EXISTS anti-join is a materialized session seq scan. The conditional-index decision (`teacher_matching_online_approved_idx` + `teacher_average_rating_idx`) should be evaluated against this plan shape — note the observed scan-gate breach is on `users` (post-filter teacher row estimate is 48), and the NOT EXISTS materialization is a cost-based planner choice that flips to `session_teacher_id_status_idx` under any additional teacher filter.

## CLI Contract (exact — binding for 3.4's "after" run)

```text
bun --env-file=.env.test scripts/perf/analyze-queries.ts [--scan-threshold-rows <n>]
```

- Unknown `--flag` / non-numeric or non-integer threshold / threshold < 1 → stderr usage message + **exit 2** (stub-compatible). Stray non-`--` tokens are usage errors. Repeated flags: last valid value wins; any usage error wins over earlier valid values.
- `--scan-threshold-rows` — inclusive Seq Scan `Plan Rows` breach threshold; default 1000. Scale-aware: at seeded production-scale volume only tables ≥ the threshold breach.
- **Exit codes:** 0 = both gates pass · 1 = any gate FAIL or runtime failure · 2 = usage refusal / guard refusal.
- Output: human summary lines + `VERDICT: PASS|FAIL` via `emitVerdict` (failed gates + breaches listed); no `--json` mode (design D6 keeps the operator surface minimal — report.json carries the machine body).

## Security Audit (3.3.SEC)

- **Read-only against the DB:** the auditor issues repository SELECTs (inside the capture window) and `EXPLAIN (ANALYZE, ...)` of those same SELECT statements only — no writes, no DDL. Non-SELECT captured statements are refused by construction.
- **Guard-first, provably:** `assertTestDatabaseTarget(process.env.DATABASE_URL ?? "")` is the first effectful call, OUTSIDE the try block (the failure path cannot be mistaken for a runtime failure — exit 2, not 1); every `@/backend/db/...` import is `await import(...)` strictly after. Proven live (subprocess exit 2, no run dir) and in units (call-index assertion).
- **No SQL injection surface:** the EXPLAIN prefix is a static constant; captured parameters are re-bound positionally (`values` array), never concatenated; CLI input is one integer; report content is plan metadata + identifiers only.
- **No secret leakage:** all persisted bytes (report.json, report.md, every `explain/<id>.json`) pass through the 1.1 `redactSecrets` writer; run/entry ids are charset-validated against traversal; artifact files created owner-only 0600 with `wx` (clobber-refused) in a 0700 directory.

## Cross-File: `report.ts` redaction fix (1.1-owned file, fixed in-task)

**CROSS-FILE DEPENDENCY (resolved in-task per the 3.1 `stub-entry.test.ts` precedent):**
- Target files: `scripts/perf/lib/report.ts`, `scripts/perf/lib/report.test.ts` (1.1-owned)
- Rule violated (found by this task's live smoke): EXPLAIN `FORMAT JSON` plans carry a `Sort Key` field — an ARRAY. `redactSecrets`'s `key`-core assignment pattern matched `Key": ["teacher.id DESC"...`, and the bare-value class consumed the array's opening bracket + first quote, splicing `[REDACTED` into the JSON array → every persisted explain artifact with a sort key became **invalid JSON** (first smoke run's artifacts did not parse).
- Required fix (applied): (a) container-value exemption in the replacement callback — a captured value starting with `[` or `{` is returned unchanged (a JSON container is never a secret scalar); (b) splitting the `dsn|authoriz|session[_-]?id|key` pattern into two patterns (`dsn|authoriz|key` + `session[_-]?id`) because the combined one tripped `sonarjs/regex-complexity` (24 > 20) — the exemption lives in the callback, not the value class, keeping every pattern ≤ 20; (c) 2 regression tests in `report.test.ts`: the exact `Sort Key` array body survives redaction byte-identical and JSON-parseable, and quoted secret assignments still redact.
- Both files re-ran sub-loop `duplicates` green; the full `report.test.ts` suite is 20 pass / 0 fail; the full-volume evidence artifacts all parse (`json.load` over all 18 explain files → 0 invalid) with `"Sort Key"` intact.
