### Semantics (binding for 5.3)

- **Enriched rows ALWAYS carry all three fields** — `Object.assign({}, row, {…})` sets every key, so `plan`/`auditTrailPeek` are present-but-`null` on a miss, never absent keys. 5.3's fast path can key on field presence (`"plan" in parent` / `parent.plan !== undefined`); a carried `null` is an honest value, NOT a "fall back to the single-row call" signal. The single-row fallback (design D4) fires only for rows a producer did NOT enrich (e.g. a resolver reached outside the two producers) — the single-row `findById`/`auditEntriesCount`/`auditTrailPeek` are KEPT, not dead.
- **`plan` enrichment has NO active predicate** (per design D4 / the 5.1 contract): a deactivated plan enriches historical rows — verified live (admin suite fixture with `isActive: false` enriches verbatim). Missing plan ids enrich `null` (the restrict FK makes a real miss impossible in production; the null arm is still type-forced and adversarially exercised).
- **`auditTrailPeekBatch` = the single-row peek, batched**: same `SUBSCRIPTION_AUDIT_ENTITY_TYPE` label, same "latest" row (the 5.1 `DISTINCT ON` proven equal to `listEntries`' first row), same raw-string map-lookup certification (`AUDIT_ACTION_TYPE_MEMBER_BY_RAW`, now shared by both paths), same `createdAt` → `at` rename, same withhold-`null` + one `logger.logDomainError` (`{ code: "VALIDATION", subscriptionId }`) on an uncertifiable literal.
- **Ordering / counts**: producer order preserved row-for-row; `auditEntriesCount` honest `0` for trail-less rows.
- **Sequential batches**: plan → count → peek are awaited in sequence (no `Promise.all`) so a caller-supplied transaction client never pipelines concurrent statements; the plan batch rides the caller's `tx`, the audit batches are bare pool reads exactly like their single-row twins (the plan's sanctioned benign read-read window).
- **GraphQL parent compatibility**: `EnrichedSubscriptionReturnType` is a flat intersection of `SubscriptionReturnType` — every enriched row is assignable to `objectRef<SubscriptionReturnType>`; SDL byte-diff is 5.3's gate.
