## CLI Contract (exact — binding for Task 8.2)

```text
bun run perf:load-ws [--connections 100] [--identities 21] [--duration-s 300]
                     [--ramp 5/2s] [--fanout-bursts 3] [--no-reconnect]
                     [--base-url http://127.0.0.1:3000] [--run <hex8>]
                     [--force-prod-shaped-target] [--help]
```

- `--connections <n>` — authenticated connections to hold; default 100; 1..10,000; **must satisfy `connections ≤ identities × perUserCap`** (perUserCap from the sidecar env seam, default 5; e.g. 21×5=105) → usage refusal (exit 2) with the cap math in the message.
- `--identities <n>` — distinct seeded identities; default 21; **floor 21** (headroom so a 100-connection run never saturates any user's cap — `--identities 20` is refused), **ceiling 25** (the 2.1 manifest's `wsIdentityEmails` cap).
- `--duration-s <n>` — stability window seconds; default 300; 1..86,400 (`3600` = the §6.3 soak evidence).
- `--ramp <burst>/<seconds>s` — default `5/2s` (burst 5, then 1 per 2s) **mirroring the server constants** (`WS_HANDSHAKE_BUCKET_CAPACITY=5`, `WS_HANDSHAKE_BUCKET_REFILL_INTERVAL_MS=2000` — asserted in tests against the exported constants). Ramp schedule = first `burst` at t=0, then one every intervalMs + a **250ms client-side safety margin** so the client stays strictly behind the bucket refill boundary (a handshake racing a refill would be refused `4429`). 100 connections → last offset 190,250ms (~190s).
- `--fanout-bursts <n>` — default 3; 0..100. Bursts are evenly spaced inside the window at k×window/(n+1). **0 bursts fails closed** (the fan-out gate is unverifiable — never a vacuous pass).
- `--base-url <url>` — server root for the real login mint; default `http://127.0.0.1:3000` (normalized). 8.2 must point it at the running server (dev or prod-mode test server both work — 21 mints is far below the rate-limit budget even un-bypassed).
- `--run <hex8>` — seed run selector; default = newest **completed** manifest under `logs/perf/` (incomplete/unreadable manifests are skipped for `--last`-style selection, refused when explicitly selected).
- `--no-reconnect` — accepted; **always the behavior** (drops recorded, never retried; per-connection `reconnectAttempts: 0` is a report field per REQ-8.6).
- `--force-prod-shaped-target` — passes the 1.3 guard override through (requires stdin re-confirmation).
- `--help` — full usage incl. both sidecar paths, preconditions, and the soak command.

**Exit codes:** 0 = `VERDICT: PASS` · 1 = `VERDICT: FAIL` or runtime failure · 2 = usage refusal / guard refusal / configuration refusal (in-process transport, missing `REDIS_URL`, manifest/minting problems). Unknown flags → exit 2 with the accepted-flag list (stub-compatible).

## Gate Semantics (exact — 8.2 consumes)

Five gates; all must pass for `VERDICT: PASS`:

1. **handshake** — every requested connection opened. Pre-open closes classify by the sidecar's close-code vocabulary (`4401 unauthenticated`, `4429 throttled`, `1013 overloaded`, …); a connection with no open/close within the 10s handshake window is `handshake-timeout`. 0 connections requested fails closed.
2. **stability** — zero drops: any post-open close before teardown is a drop breach (`connection N dropped at Xms (<label> [code])`). Harness-initiated closes at teardown are never drops.
3. **liveness** — no connection reaches **2 consecutive missed** 30s liveness checks (mirrors `WS_PING_INTERVAL_MS`/`WS_MISSED_PONG_LIMIT`). A live observation resets the streak; a drop is not double-counted as a liveness failure.
4. **fanout-delivery** — per burst: publish failures breach (`could not be published: <error>`); every expected connection must receive (`N/M delivered (missing: …)`); p95 over delivered latencies must be **strictly below 2000ms** (`FANOUT_P95_GATE_MS`, evaluated through 1.1's `evaluateGate` — exactly-at-limit FAILS, zero deliveries fails closed). Expected = connections live at publish time; `userIds` covers ALL connected identities; `data.id` unique per burst (epoch-ms base + index — unique across runs).
5. **residue** — zero post-teardown fan-out deliveries and zero still-open sockets (client-observable zero-residue, REQ-8.7).

A run that aborts mid-flight (e.g. the booted sidecar dies before listening) gains a sixth gate `run-completed` (FAIL) and still writes a partial report — gates judge whatever was observed.

## Protocol Findings (studied from the sibling-owned sidecar — read-only)

- **Handshake:** Bun-native `new WebSocket(url, { headers: { origin, cookie } })`; the server reads `Origin` FIRST (allowlist, 403 pre-upgrade on mismatch) then the per-IP token bucket (`4429`), then the `access_token` cookie as the ONLY identity source (`4401` on any verify failure), then caps (`1013` global / `4009` per-user eviction, oldest evicted).
- **Liveness:** the SERVER pings every 30s and terminates at 2 missed pongs; a spec-compliant client auto-pongs at the protocol layer (invisible to the client API), so the harness's client-observable mirror is a 30s open-state observation round per connection with a 2-consecutive-miss threshold — the same constants, consumed from `backend/ws/notification-ws-server-constants.ts` (drift-proof, asserted in tests).
- **Fan-out wire:** publish `{"userIds":[…],"payload":{"v":1,"kind":"notification","data":{id,type,title,body,relatedEntityType,relatedEntityId,createdAtISO}}}` on `kottaby:notifications:fanout` (constant imported from `redis-pubsub-transport.ts`); the envelope must survive `parseFanoutEnvelope` (exact key sets, positive-int userIds, valid `NotificationType` — the harness uses `system_broadcast` — parseable `createdAt`) — unit-proven by round-tripping the built wire through the real guard. The sidecar egresses the projected payload; the client recognizes deliveries by `v:1`/`kind:"notification"`/positive-int `data.id`, tolerating foreign/duplicate frames (counted as `extraMessages`, never corrupting latency accounting).
- **Origin allowlist:** the harness uses its own env seam's FIRST allowlisted origin (`getWebSocketAllowedOrigins()[0]` — default `http://localhost:3000`); it never invents or bypasses an origin. When the harness boots the sidecar it pins the child's `WS_HOST/WS_PORT/WS_ALLOWED_ORIGINS` to the harness-resolved values so both sides always agree.
- **Env reality:** `perf:load-ws` runs under `--env-file=.env.test`, which does NOT contain `REDIS_URL` (and `--env-file` suppresses Bun's `.env` auto-load — probe-verified). The operator MUST export it: **`REDIS_URL=redis://localhost:6379 bun run perf:load-ws …`**. The harness fail-fasts with the sidecar entry's own actionable message when the transport resolves to `in-process` or `REDIS_URL` is missing (REQ-8.5). The booted sidecar child inherits the harness env (incl. `.env.test`'s `DATABASE_ENCRYPTION_KEY`) so minted tokens always verify.

## Semantic Review (8.1.SR)

- **Liveness accounting:** miss vs drop disambiguation is structural — a close event is a drop (stability gate); an open-but-unresponsive observation is a liveness miss; a dropped connection is excluded from later liveness rounds (no double-counting); 2 consecutive misses is the failure threshold, mirroring the server constants by import.
- **Delivery-gate arithmetic:** 100% = every connection live at publish time recorded a latency for that burst id (first frame only; duplicates/foreign frames counted separately); p95 over delivered latencies via the 1.1 nearest-rank integer-first math; expected/delivered/missing per burst + aggregate observed values on the gate; missing deliveries count as gate errors (`maxErrorCount: 0`); publish failures are classified breaches, never crashes.
- **Bounded state:** the connection registry is bounded by `--connections` (≤10,000), the burst map by `--fanout-bursts` (≤100), per-socket delivery maps by burst count; no module-level mutable state (all state is per-run-instance); the harness-booted sidecar + ioredis publisher are closed on every exit path (finally + signal handlers).
- **Uninstall/close discipline:** teardown closes every open socket (1000), waits a 2s settle + 2s residue window, stops a spawned sidecar (SIGTERM → 5s grace → SIGKILL), and closes the publisher; refusals before the report leave nothing behind (no run dir).
- **Comments:** domain-behavior only — zero plan-artifact references (grep-verified across all 10 files); enums as value imports (`NotificationType`); no `any`, no unsafe casts (type guards throughout); deep `@/` imports only.
