## Coverage Rule (as implemented — matches plan.md Component 4 exactly)

An FK column is **covered** iff some index on the same table satisfies BOTH: access method `btree`, AND (a) the column is the index's **leading** key element, OR (b) the constraint's full referencing-column list (declaration order) is a **prefix** of the index's key elements. Expression key parts parse as `null` elements and never match; quoted identifiers (with `""` escapes), ordering/collation/opclass qualifiers (`DESC`, `NULLS LAST`, `COLLATE`, `*_ops`) parse as plain columns; non-btree methods (gin/gist/hash/brin) and unparseable definitions never cover (conservative — an unreadable index never proves coverage). The rule is unit-locked against the live catalog's real shapes, including the composite `student_subscriptions_pkey (student_id, subscription_id)` that covers `student_id` as a leading column.
