### Incident (recorded honestly — sibling-stream DB concurrency, NOT a pagination defect)

Between run 1 (22:10:22) and run 2 (22:14:19), the 1,992 browsable perf teachers were bulk-flipped `is_online=false` by the product's **presence-decay sweep** (`backend/db/repo/teachers/teacher.repository.ts:780-811` — flips teachers whose `users.last_active_at` is NULL/stale, excluding active-`started`-session holders, which is exactly why the 8 hot teachers survived). The seeder does not stamp `users.last_active_at`, so every seeded non-hot teacher is decay-eligible; a concurrent sibling-stream event triggered the sweep at ~22:12 local. Consequence: run 2/3's `browseAvailableTeachers` honestly returns an empty pool (`total=0` — "zero matches is a valid browse state" per the query contract), while **run 1 (retained) carries the full-volume browse evidence** (`total=1992`). No bounds behavior differs between the states — the absent-args echo (25), the cap-edge window (100), the `VALIDATION` rejection at 5000, and the deep-offset emptiness were verified identically in all three runs. Nothing in this incident is a pagination gap; it is carried forward as a **runbook caveat for 10.1** (below).
