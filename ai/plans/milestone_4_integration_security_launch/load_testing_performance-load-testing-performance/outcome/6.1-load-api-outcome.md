```bash
bun run perf:load-api -- [--vus N] [--duration-s S] [--ramp C/Is] [--gate-ms MS]
                            [--base-url URL] [--weights SPEC] [--run HEX8]
                            [--self-check] [--force-prod-shaped-target] [--help]
```

- Defaults: `--vus 100` · `--duration-s 120` · `--ramp 10/5s` · `--gate-ms 500` · server harness-booted on port **3066** · newest completed seed manifest.
- Bounds: vus 1–10000 · duration 1–86400s · gate 1–60000ms · ramp count ≤1000, interval ≤600s · run `^[0-9a-f]{8}$`.
- `--weights SPEC` — comma list `scenario=weight` over registry ids; unknown ids / non-positive / zeroing every scenario of a role → exit 2.
- `--self-check` — forces 2 VUs × 10s, gates `[]` (vacuous `emitVerdict([])` PASS); the 6.1.TE wiring proof.
- Exit codes: **0** PASS · **1** FAIL/runtime failure · **2** usage / guard refusal / configuration refusal.
- Safety order: destructive-target guard (`assertTestDatabaseTarget`) is the FIRST effectful call; the shared db client is imported dynamically only inside `samplePgActivity` (post-guard).

## Gate + window semantics (exact for 6.2)

- Gates: per active scenario `scenario-<id>` with `p95MaxMs = --gate-ms` (strictly-below passes; exactly-at-limit FAILS; zero-sample gates fail closed) and `maxErrorCount = 0`. Errors = transport errors + unexpected-shape + domain rejections on mustSucceed scenarios. Zero-weight scenarios (via `--weights`) drop out of gates entirely. Self-check → gates `[]`.
- Role partition: admin VUs = `round(vus × adminWeight/totalWeight)`; ≥2 VUs guarantees ≥1 of each role; all admin VUs share the single admin identity (each mints its own session). vus=100 → 9 admin.
- Window: `--duration-s` is the steady window AFTER the full ramp; windowEnd = windowStart + rampSpan + durationS×1000; ramp `10/5s` adds 10 VUs every 5s. Closed model: each VU loops `while now() < windowEnd { one request }`; one in-flight overshoot per VU recorded honestly. Scenario fetches abort at 30s.
