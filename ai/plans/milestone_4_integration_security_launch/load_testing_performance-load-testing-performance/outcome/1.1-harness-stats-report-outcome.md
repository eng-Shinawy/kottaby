## Module Contracts (as built)

### `stats.ts`
- `nearestRankPercentile(values, percentile)` — exported helper; deterministic nearest-rank (no interpolation), input never mutated, `percentile ∈ (0, 100]` (p100 = max; p0 rejected), empty set rejected.
- `summarizeSamples(samples)` — percentiles over ALL sample durations (success + failure), `errorCount` counted separately; empty set → all zeros; non-finite/NaN/negative `durationMs` → typed `PerfStatsError` (reject, never crash); zero-duration is a valid observation.
- `evaluateGate(summary, threshold)` — contract chosen and unit-tested on both sides: **p95 < p95MaxMs passes (exactly-at-limit FAILS)**; **errorCount <= maxErrorCount passes (inclusive)**; latency-bounded gate over zero samples **fails closed** (unverifiable gate is never a pass); threshold with no bounds → `PerfStatsError`.
- **FP-drift fix discovered by the tests:** rank computed as `ceil((p*n)/100 - 1e-9)` (integer-first math + epsilon snap). The naive `(p/100)*n` form drifts upward at exact boundaries (e.g. p99.9 @ n=1000 → rank 1000 instead of 999) and silently inflates percentiles. **Carry-forward: any future percentile math in perf tools must use the integer-first form.**

### `report.ts`
- `openRunDirectory(tool)` — creates `logs/perf/<YYYY-MM-DDTHH-MM-SS>_<tool>/` (mode 0700) resolved from `import.meta.dir` (repo-root-anchored, cwd-independent); same-second collisions suffixed `-2`, `-3`, …; tool id charset-validated (`^[a-z0-9][a-z0-9-]{0,48}$`, lowercase-dash — traversal/absolute/uppercase rejected before any mkdir).
- `writeReport(ctx, gates, sections)` — writes `report.json` (machine: `{tool, runId, startedAt, args, gates, sections, verdict}`) + `report.md` (human: args echo, gates table, per-section fenced JSON); both **redacted before disk**, both mode 0600, both written `wx` (clobber-guard: reports are immutable — a second write refuses); run id charset-validated (`<stamp>[-N]_<tool>` only — no `/`, no `..`) + defense-in-depth containment re-check after `resolve`.
- `redactSecrets(content)` — exported; ordered passes: (1) connection strings with `user:password@` userinfo (any URI scheme) → `[REDACTED-CONNECTION-STRING]`, (2) JWTs, (3) `Bearer <token>`, (4) `sk|pk|rk_live|test_…` vendor keys, (5) secret-named key assignments (identifier cores: `token|secret|cookie`, `password|passwd|pwd`, `dsn|authoriz|session[_-]?id|key`; values quoted or bare, either side of `=` or `:`; surrounding quote characters are **preserved** so redacted JSON stays parseable). `emitVerdict` breach lines are redacted too.
- `emitVerdict(gates)` — prints terminal `VERDICT: PASS|FAIL` (+ failed-gate breach lines), returns pass boolean; empty gate list passes vacuously. Uses `console.log` under the sanctioned `scripts/**` ops idiom (`eslint.config.mjs` override; precedent `scripts/ops/backup-database.ts:127-128`).
- **Design note (SR):** NO module-level mutable state at all — not even the run-dir singleton the SR checklist allowed. `writeReport` is fully parameterized via `ctx.runId`, so no current-run caching is needed; collision avoidance is fs-based (`existsSync` probe loop), not counter-based.

### Redaction false-positive hardening (found during build)
- The secret-key regexes deliberately do NOT use a bare `pass` core (`password|passwd|pwd` only): a bare-`pass` wrapper would have redacted the report's own `"passed": true` gate field.
- Value classes exclude quote characters so a JSON closing quote is never consumed (an earlier draft produced `JSON Parse error: Unterminated string` — regression-locked by the parse-after-redact assertion in the Tier-4 proof test).
- Bare `session` is not a core (only `session[_-]?id`), so `"sessions": 5000` counts stay readable; cookie coverage comes from the `cookie`/`token` cores.
