## 1. Summary

The full onboarding dialog component tree landed as 8 files under `frontend/views/admin/students/onboarding/`:

- `OnboardStudentDialog.tsx` — host: ONE `Dialog` (maxWidth="sm") on the shared `FormDialogShell` chrome (title / cancel / save / saving / global error band) hosting the four sections Profile → Parent (optional) → Plan → Offline Payment, plus the post-submit `OnboardStudentSuccessContent` swap. Owns the flat draft state (`EMPTY_ONBOARD_STUDENT_FORM` reset on every close affordance), client-side submit validation (`validateOfflinePaymentDraft`), plan pre-binding (`first active plan` derive-on-arrive fallback, mirroring the lessons catalog selector), the `planId` GraphQL-ID→safe-int parse, and the server/client error merge (`{ ...serverFieldErrors, ...clientFieldErrors }`).
- `OnboardStudentProfileSection.tsx` — fullName / email / phone / initial credential (`type="password"`, `autoComplete="new-password"`) / optional gender / country on the two-column grid family of the admin create-user dialog; reuses `AdminUserGenderSelect` (single-sourced option labels, `AdminUsers` handle) and `AdminDialogFieldLabel`.
- `OnboardStudentParentSection.tsx` — optional `Autocomplete` parent picker over prop-fed parent-role directory rows; `parentId: null` = onboard without a link; linked-to/none helper line; `params.slotProps` merge preserved so the autocomplete end-adornment survives.
- `OnboardStudentPlanSection.tsx` — selectable outlined cards over prop-fed ACTIVE catalog plans; title / sessions · interval · lane facts / price+currency rendered verbatim; lane vocabulary via `Record` lookup (no enum comparisons); selection tint via `primaryContainer`/`onPrimaryContainer`.
- `OnboardStudentPaymentSection.tsx` — three-segment exclusive `ToggleButtonGroup` over the offline gateway tokens (`OfflineCash | BankTransfer | Scholarship`) + required reference `TextField` (helper explains the 1–255 bound; the host trims/bounds at submit; service re-validates).
- `OnboardStudentSuccessContent.tsx` — post-submit handoff: student identity line, handshake-code line (`userSelect: "all"` select-on-tap, REQ-030.6 — the one place the code renders), credited-sessions line; credential structurally absent from the payload and never rendered.
- `onboardingDialog.types.ts` — LOCAL view types only: `OnboardStudentFormState`, `OnboardStudentFieldKey`, `OnboardStudentFieldErrors`, `EMPTY_ONBOARD_STUDENT_FORM`, token→member `Record` tables (`GENDER_BY_TOKEN`, `OFFLINE_GATEWAY_BY_TOKEN`), `validateOfflinePaymentDraft`, `buildOnboardStudentInput` (trims identity fields, password verbatim, optional gender → null, parent passthrough). The 255 reference ceiling is deliberately duplicated (never imported from backend machinery).
- `index.ts` — barrel (`export * from "./…"` × 7).

## 6. Carry-forward for task 4.3 (exact prop seams — hooks wiring)

- **`OnboardStudentDialogProps`** (the hooks layer instantiates this one component):
  - `open: boolean` / `onClose: () => void`
  - `parentOptions: readonly AdminUsersQuery_adminUsers_items[]` — pass the role-filtered `adminUsersQueryDocument` page items through VERBATIM (no mapping).
  - `planOptions: readonly PlanCatalogQuery_planCatalog[]` — pass `planCatalogQueryDocument` (active-only) items through VERBATIM.
  - `submitting: boolean` — mutation `loading`.
  - `globalError?: string | null` — top-level server rejection, rendered in the shell band.
  - `serverFieldErrors?: OnboardStudentFieldErrors` — per-field server VALIDATION messages keyed by input field name (Profile: `fullName/email/phone/password/gender/country`; Parent: `parentId`; Plan: `planId`; Payment: `paymentMethod/paymentReference`).
  - `onSubmit: (input: AdminOnboardStudentOfflineInput) => Promise<void>` — called with the validated, mapped whitelist input; the hook should `await` the mutation so `submitting` and the success swap sequence correctly.
  - `success: AdminOnboardStudentWithOfflinePaymentMutation_adminOnboardStudentWithOfflinePayment | null` — non-null payload swaps the form for the success content; reset to `null` when re-opening.
- **Section props (all already wired by the dialog — 4.3 never touches sections):** `form` + `setForm` + `submitting` + `fieldErrors` on Profile/Parent/Payment; Plan additionally takes `selectedPlanId` (dialog pre-binds the first active plan) instead of reading `form.planId` directly.
- **Server-error mapping contract:** `OnboardStudentFieldErrors = Partial<Record<OnboardStudentFieldKey, string>>` — map backend VALIDATION `paymentReference`/`paymentMethod`/etc. messages onto these keys; client errors clear on any draft edit, server errors persist until the next submit replaces them (dialog-merged, server wins until edit).
