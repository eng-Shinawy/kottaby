## 6. Notes for the plan

1. **INV-HW3/HW4 "previous session's homework" is implemented as "the student's newest prior homework row."** The grading probe (`findLatestByStudentId`, home-work.repository.ts:142-171) has NO grade predicate and NO session-predecessor check; "previous session" is emergent from `home_work_session_id_unique` (one row/session) + newest-first ordering + the fixed grade-before-insert order (session-report.service.ts:177-181). The recommended "routing nuance" test in §4 pins the shipped semantic; the plan should cite the normal-sequence journeys (:1228/:1352) as the invariant's primary evidence.
2. **The INV-S7/S8 gates have NO production consumer** — `assertSessionCompletedForReport`/`assertReportSubmittedForHomework` (session-lifecycle.enforcement.ts:127/:164) are exported and unit-tested only. The live homework-requires-report enforcement is COMPOSITIONAL: the homework insert (session-report.service.ts:227) runs strictly after the report insert (:286) inside the same transaction, gated by `lockForReportGate` (:261-279). Sibling dossier `01-session-lifecycle.md` owns S7/S8 — this plan must NOT re-test the gates; HW tests should target the production surface (session-report.service.test.ts).
