## Design decisions (recorded for reviewers)

1. **`probeInsideSavepoint` for every violation leg** (plan's C4 mandate): both CHECK legs, both enum legs run inside the shared savepoint bracket that ALWAYS rolls back — a failed probe can never poison the outer `runInRollback` tx. The succeed-then-rollback rule (2.2-outcome) never applies here: every probe leg is designed to FAIL.
2. **`createTestStudentPayment` for the CHECK legs, raw SQL for the enum legs** — the typed insert surface (`Partial<StudentPaymentSelectType>`) cannot express an out-of-vocabulary gateway string or a NULL gateway (SelectType types the column non-null), so PAY4's two negative legs use `tx.execute(sql…)` inserts with both `student_id`/`subscription_id` NULL (both nullable by schema; the enum/NOT NULL validation fires long before any FK is consulted, and the savepoint discards the row regardless). This is the dossier §4 recipe verbatim.
3. **Zero-row leak oracle on the CHECK test** — after both rolled-back brackets, a fixture-scoped select over the student's ledger slice asserts `toHaveLength(0)`: proves the savepoints actually contained the failed statements and the outer tx is queryable (the same post-rollback read-back idiom as the file's trigger tiers).
4. **Closed-set pin asserts order + count + membership simultaneously** — `enum_range` returns values in the enum's declaration order, so `toEqual(Object.values(PaymentGateway))` is the strongest form: a re-ordered, added, dropped, or renamed value on either the pgEnum or the TS enum side fails. The separate `toHaveLength(9)` makes the "nine shipped values" census claim explicit.
5. **No UPDATE-leg CHECK probe** (plan §5.2 hazard): the immutability guard raises first for any amount edit — re-probing it would duplicate the existing amount-tamper matrix in the same file; the in-test comment points at that matrix instead.
6. **`INV-PAY1`/`INV-PAY4` prefixes in test titles** are the census binding strings the drift oracle greps (`content.includes(testName)`) — required by the oracle, not plan references (same ruling as 3.2-outcome SR).
