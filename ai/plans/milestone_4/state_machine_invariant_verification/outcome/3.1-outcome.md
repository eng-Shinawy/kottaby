## Design decisions (recorded for reviewers)

1. **Table-wide sweep, not fixture-scoped** — the plan/dossier/census all prescribe the residual `=== 0` over the whole table, and that IS the oracle: a single report-less homework row anywhere is a violation (the invariant's data-level reading). This is deliberately not the `AGENTS.md` rule-12 grow-by-N count pattern (that guards additive-count tests); a residual sweep that scoped to its own fixture could never fail. Isolation is sound: parallel db-test workers each run inside their own uncommitted transactions (invisible under read-committed), committed journey fixtures are registry-torn-down, and seeds contain zero `home_work` rows (grep-verified).
2. **Cast-free raw-count read** — `tx.execute(sql…)` rows are untyped; the count is read as `Number(result.rows[0]?.orphan_count ?? 0)` — zero `as` casts (oxlint `no-unsafe-type-assertion` clean), matching the raw-execute precedents (`admin-user.repository.ts:640`, `platform-analytics-query-helpers.ts:305`).
3. **No FK-target pins added** — tasks.md 3.1 and plan §5.2 prescribe exactly the two `notNull` pins. (Probed live: drizzle's FK config on these tables is anonymous — `foreignKeys[0].name === undefined` — so a name-keyed FK pin is impossible anyway; `reference().foreignColumns`/`onDelete: "cascade"` are available if a future task wants them.)
4. **`INV-S7`-style production faithfulness in the fixture** — the probe's session is written with `status: SessionStatus.Completed` + `startedAt`/`endedAt` (the state in which report submission is sanctioned), modelling the real composition rather than the default scheduled row.
