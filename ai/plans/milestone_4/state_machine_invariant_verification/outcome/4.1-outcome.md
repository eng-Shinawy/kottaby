## Design decisions (recorded for reviewers)

1. **The S8 scan scope is the production backend surface, precisely excluding perturbable territory.** The dossier recipe says "the services tree"; the census statement is "exactly ONE production call site". The pin scans the five production roots (services, graphql, db/repo, lib, app) because any of them could host a report-less creation path, while `*.test.ts`, `*.spec*`, `__tests__/`, dot-dirs, and `node_modules` never enter the walk — sibling test-authoring activity cannot perturb it; only a NEW production caller can (which is exactly the drift the pin exists to catch). The scan reads only repo source files — no secrets, no `.env` (the tools' own guards plus the exclusion of dot-entries).
2. **Regex shape, not bare name**: the pin matches `HomeWorkRepository.insertHomeWork(` — the call shape with the repository prefix. The repo's own declaration (`export async function insertHomeWork(`) and its error string ("HomeWorkRepository.insertHomeWork: insert returned…") deliberately do NOT match, so the census is honest: exactly one CALL site, not one string mention. The test's own title and regex literal cannot self-match either (the title lacks the paren; the literal carries `\` escapes; and the file is a `.test.ts`, outside the scan).
3. **The "inside the report transaction" leg is composed of index-ordering pins, not line numbers.** `indexOf`/`search`/`matchAll` over the file's own source: composite definition < insert call < submission body; composite invocation count === 2 (definition + exactly one call); invocation index > report-insert index. No `path:line` cite can rot; any reordering that detaches the insert from the post-report composite fails the pin.
4. **HW4 determinism**: `createTestHomeWork` accepts a `createdAt` override, so the two prior rows carry distinct stamps (now−2d, now−1d) — the `ORDER BY created_at DESC, id DESC` probe resolves without relying on the id tiebreak (though `newerRow.id > olderRow.id` is also asserted as fixture sanity).
5. **U2 pins, never widens**: the stricter raw-boolean denial is asserted as shipped behavior with a domain-language comment; the live `isSuspensionActive(...) === false` pre-assert makes the test non-vacuous (it proves the fixture really models a LAPSED window — otherwise the test would pass for the trivial reason that the suspension is active).
6. **W4 oracle completeness**: wallet NULL + `confirmedByStudentAt` NULL + zero session-linked ledger rows together close the "no credit without student confirm" proof at the composition level — `creditEarningOnce` is unreachable because `confirmStudentCompletionOnce`'s predicate requires the student stamp, and no other earning writer exists (the import-allowlist source pin at `session-lifecycle.service.test.ts` cites the single-writer composition).
7. **No mock idioms invented**: all four tests reuse the files' existing helpers (`provisionReportCast`, `homeworkRowBySessionId`, `countReportRowsFor`, `freshEngineOptions`, `createSessionActors`, `setLaneBalances`, `bookSession`, `readLaneBalances`, `countClaimsForUser`, `countSessionsForStudent`, `readClaimByKey`, `expectRepoError`, `expectDomainDenial`). The only new imports are two schemas/modules and the `node:fs`/`node:path` pair for the source pin.
