## Fixture design notes (carry-forward)

1. **Unique name-search token scoping** (`wb-<uuid8>` embedded in both browse-target teachers' `fullName`): the browse's `search` argument is an ILIKE on `users.full_name`, and the count query shares the same WHERE chain (`teacher.repository.matching.helpers.ts` — `listMatchingCandidates` runs rows + count on one `where`), so `total === 1` is a razor-sharp, fully fixture-scoped oracle. RandomUUID token → zero collision risk with parallel suites or seed rows.
2. **Stale-true flag posture**: the in-session teacher row keeps `is_online = true` (production's `acquireInSessionLock` would have flipped it false, but the compose rule composes the flag WITH the session-state check precisely so a stale-true window can never re-admit an in-session teacher). This makes the wire test the STRONGEST form of the exclusion probe — if the `NOT EXISTS (… status = Started)` leg ever regresses, the test fails even though the flag alone would still have hidden the teacher in the production-shaped posture.
3. **The admin (staff) actor needs no `admin` child row** — the role scope reads the JWT/users role; the sibling suite's cast confirms the same. Login works off the `users` row.
4. **Anonymous denial passes NO auth header** (context `undefined`) — the shared `testClient` sends no cookies between tests, so the call is genuinely unauthenticated.
