## THE CITE-FORMAT CONTRACT for Task 2.3's drift oracle (authoritative — do not guess)

The catalog was authored for the oracle to scan. **Exact contract:**

1. **Imports** — `import { CENSUS_DOC_PATH, CENSUS_ROWS, INVARIANT_CENSUS, type InvariantCensusEntry } from "@/backend/db/test/logic/invariants/invariant-census.catalog";` (types `InvariantMachine`, `InvariantVerdict`, `InvariantDisposition`, `InvariantCensusBinding` are exported too).
2. **Doc side** — read `CENSUS_DOC_PATH` (repo-root-relative, POSIX), extract tokens with regex **`/INV-[A-Z]+\d+/g`** into a `Set<string>`; corpus sanity **≥ 60** (today exactly 67 unique — the doc's prose mentions like `INV-S1..S5` resolve into real IDs only). Assert set-equality BOTH directions vs the 67 census IDs: a doc ID missing from the census fails; a census ID missing from the doc fails.
3. **Binding checks** — for every row × every binding:
   - `testPath` is **repo-root-relative POSIX**; resolve against the repo root. Precedent in the same tree: `backend/db/test/logic/audit/audit-census-drift.test.ts:63` uses `join(process.cwd(), ...)` and passes under both `bun run test:db` (parallel runner spawns workers inheriting the repo-root cwd) and `bun run test/scripts/run-test.ts <path>` (pins child `cwd` to `PROJECT_ROOT`). `join(import.meta.dir, "../../../../..")` is a cwd-independent alternative — either works; recommend the precedent unless robustness to caller-cwd is wanted.
   - `testName` is a **plain substring** of the file content — grep `content.includes(testName)`. For long titles the catalog deliberately stores unique *fragments* (e.g. `"mutation set grows ONLY by the sanctioned additions"` in schema-surface.test.ts, `"the unit's cross-surface channels are the wallet-credit slice"` in session-lifecycle.service.test.ts) — substring check handles both.
4. **docLine** — **do NOT hard-assert it** in the oracle. It is the statement-row anchor at authoring time (all 67 verified against today's doc). Task 6.1's `†` annotations will reflow doc lines (the doc's amendment-glyph precedent annotates inline, so shifts should be small — but any inserted line shifts every later anchor). The bijection is ID-set-based; `docLine` is metadata. At most soft-check the ID appears somewhere in the doc.
5. **PIN rows** — assert `ledgerRef` present on the 6 PIN rows (`disposition === "PIN-APP-LAYER+DOC-DRIFT"`) and the `D-4xx` string appears live in `ai/plans/milestone_4/state_machine_invariant_verification/deferred-items.md` (match `| D-40x ` in the ledger table). **Note:** TV7 (NEW-PROBE) also carries `ledgerRef: "D-401"` per plan §5.2 — the oracle must check PIN rows *have* one, not that *only* PIN rows have one.
