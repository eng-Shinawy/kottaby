## 2. Recurring patterns & gotchas extracted across ALL task outcomes

The non-obvious engineering learnings that recurred across the plan's 24 task outcomes and 12 dossiers. Headline count: **28 gotchas** in five classes. Each carries its origin outcome(s); the ones already canonized in `docs/testing/invariant-verification.md` are marked `[canonicalized]`.

### 2.1 PostgreSQL / Drizzle semantics (the twice-proven class)

1. **ON DELETE RESTRICT fires SQLSTATE 23001 (`restrict_violation`), NOT 23503** (3.4, 3.6 — twice-proven against the live DB: `subscriptions_plan_id_plans_id_fkey`, `session_student_id_users_id_fkey`). 23503 (`foreign_key_violation`) fires only for plain FK mismatches on insert/update. The C4 helper's `expectFkViolation` (23503-hardcoded) is for insert-side violations only; referenced-row deletes under RESTRICT need `hasPostgresErrorCode(err, "23001")` + `constraintNameOf`. A candidate C4 follow-up: an `expectRestrictViolation` expector (owner: the helper's maintainer — recommended in §4 below). `[canonicalized §3/§5]`
2. **Drizzle single-column FK constraint names are generated as `{table}_{column}_{referencedTable}_{referencedColumn}_fkey`** — dossier hand-abbreviations (`subscriptions_plan_id_fkey`) are not always the live names; always verify the constraint name from the live error before writing a named-constraint assertion (3.4 carry-forward #2).
3. **`session.student_id` references `users.id` (RESTRICT), not `students.id`** — re-pointed by migration `20260920140048_real_garia`; the dossier-06 cite (`session_student_id_students_id_fkey` → `students.id`) was stale (3.6 KEY DEVIATION). Fixture authors must key session rows on user ids.
4. **Shipped CHECKs are stricter than the doc**: `teacher_transaction_amount_check` and `student_payments_amount_check` are `> 0`, not `>= 0` (3.5, 3.7; dossiers 05/08). Tests pin shipped semantics, never doc wording — the D4 doctrine. The same class: `payment_gateway` is a 9-value pgEnum, not the doc's 5 (3.7).
5. **`enum_range` closed-set pin idiom** — `select unnest(enum_range(null::<enum>))::text` toEqual `Object.values(<TsEnum>)` pins TS enum and pgEnum to each other, order-sensitive, one statement (3.7 carry-forward #3). `[canonicalized §5]`
6. **A single-guard trigger IF raises on the FIRST failed arm** — a tamper probe that changes a frozen column without also presenting a valid settlement shape proves nothing about that column's arm (the status arm fires first). Settlement-shaped probes isolate the named arm; mirror `wallet.repository.admin.test.ts:621-658` (3.5 carry-forward #3). `[canonicalized §5]`
7. **Nullable CHECK columns pass on NULL** — concrete out-of-range integers (101/-1), never NULL, are the only way to trip a CHECK on a nullable column (`evaluations_score_check`, 3.9).
8. **Trigger tiers need `isPgliteProvider()` gating (`describeTriggerTier`); CHECK/enum probes do not** — verified live on `kottaby_test` (3.5, 3.7, dossier 11). `[canonicalized §5/§6]`
9. **Orphan ids are computed, not guessed**: `coalesce(max(id), 0)::int + 1_000_000` inside the caller's transaction can never collide with a parallel worker's committed row (3.8, the `absentSessionId`/`absentLessonId` pattern).

### 2.2 Probe-helper and transaction discipline

10. **`probeInsideSavepoint` is strictly for must-FAIL probes — it THROWS when the probe resolves.** Succeed-then-rollback legs (unreferenced-plan DELETE, set-null survival, legal NULL-lesson rows, cascade legs) run plain statements inside `runInRollback` (2.2 usage rules; applied by 3.1, 3.4, 3.8, 3.9). `[canonicalized §5]`
11. **Never `expect(...).rejects.toThrow()` inside `runInRollback`; `tx` threaded to EVERY call — mixing `tx` and `db` inside a block deadlocks** (every Phase-3 outcome; the C4 helper asserts these properties). `[canonicalized §5/§9]`
12. **The committed-fixture exception is structural, not stylistic**: `AuthService.login`/`refreshToken` resolve identity through the bare pool and rotate in their own transactions — tests of those gates need committed fixtures + `deleteUsersByIds` teardown, never `runInRollback`; likewise any observable-that-must-commit (FK SET NULL survival) (3.6, 3.9, 4.5). `[canonicalized §6]`
13. **Zero-oracles need detector-liveness legs**: a table-wide `=== 0` residual sweep is only trustworthy with a savepoint-bracketed deliberate-violation leg (insert the orphan, see 1, roll back, see 0) (3.1 carry-forward #4).
14. **Raw-count read idiom**: `Number((await tx.execute(sql\`… count(*)::int AS x …\`)).rows[0]?.x ?? 0)` — cast-free, provider-portable (3.1 carry-forward #3).

### 2.3 Harness, runner, and tooling hazards

15. **`bun run test:graphql` never discovers `backend/graphql/test/**`** — `test/scripts/run-server-tests.ts:15` `DEFAULT_TEST_PATH = "frontend/graphql/test/"`. The wire tier runs via `bun run test/scripts/run-test.ts backend/graphql/test` (plan-review F2; applied across tasks rule 4). `[canonicalized §6]`
16. **`run-test.ts` pins `--env-file=.env.test`; bare `bun -e` probes read the DEV database** — one stray dev-DB fixture cast was caught and cleaned in 4.5 (carry-forward #9).
17. **JSDoc `**/*.test.ts` glob self-terminating-comment hazard**: a block comment containing the glob `` `**/*.test.ts` `` self-terminates at the `*/` inside `**/`, producing cascading bogus syntax errors (44 in 2.2's case). Keep glob patterns out of block comments.
18. **`/g`-regex `.test()` is lastIndex-stateful** — single-id validation needs a separate non-global pattern (2.3 carry-forward #5).
19. **`sonarjs/concise-regex` rejects `[^a-zA-Z0-9_]` in this layer — use `\W`** (2.2 carry-forward #2); type-aware lint also demands explicit `localeCompare` comparators and specific assertions (2.3 fix iterations).
20. **The audit-immutability teardown allowlist is a live tripwire**: any test file that deletes audit rows under `withAuditDeleteTriggersSuspended` must add its `TEARDOWN_ALLOWLIST_PATHS` entry in the SAME change — task 4.6's journey was caught red by it in 5.1a precisely because the journey had been verified through the workflow runner only. Layer-wide `test:db` runs catch what per-file loops miss.
21. **`git checkout --` on a shared-workspace file another agent may be editing creates a clobber window** — the 3.6 auth-file race incident merged cleanly only because the sibling's edit was append-shaped. Verify pre-existing failures via failure-independence reasoning or a temp worktree instead (3.6 incident section).
22. **Markdown files are sub-loop-exempt** (oxlint: "No files found to lint" for `.md`); the workflows-layer gate for `DIAGRAMS.md` is `bun run validate:mermaid` alone; the docs-layer gate for glyph edits is the census/oracle re-run (4.3/4.4/6.1/6.2 exemptions).
23. **`/tmp/baseline-*` is a collision-prone shared namespace** under concurrent sibling plan agents — every baseline comparison must read the durable per-plan copies (`/tmp/m4-smi-baseline/`, `outcome/phase0-baseline.md`), never the shared paths (phase0-baseline §7; applied by 5.2).

### 2.4 Environmental / shared-state hazards (all ledgered)

24. **Disabled-trigger stale leak**: the two `audit_logs` immutability triggers sit installed-and-wired but `tgenabled='D'` in the shared migrate-provisioned test DB — a stale leak from an interrupted trigger-suspension sweep (crash between DISABLE and restore). Probe `pg_trigger.tgenabled` FIRST when trigger-tier tests fail; re-enabling mid-flight is unsafe while sibling suites hold suspension windows (suspension helpers restore the *captured* state, so an ENABLE racing an open window corrupts their sweeps) (3.5; ledger D-413). `[canonicalized §8]`
25. **Committed-fixture leak cascade when `beforeAll` fails**: a cast helper that commits rows before a failing registration leaves orphaned rows because `afterAll` early-returns when the registry was never assigned — 39 leaked `jrn_gov_`-admin rows accumulated before the 4.5 cleanup. Fixture provisioning order and early-return teardown guards are a leak surface of their own (4.5).
26. **`closePool()` in an `afterAll` kills the process-wide shared pg pool mid-`bun test`** — every DB-touching file scheduled after the killer dies with `Cannot use a pool after calling end on the pool`; victims are individually green. Diagnose by log position (`[WARN] [db] pool closed` boundary) + two-file minimal repro, not by contention theories (5.1b; ledger D-415). `[canonicalized §8]`
27. **DEV `.env` admin credentials leak into every `bun run`-mediated process** (Bun auto-loads cwd `.env`; `DEV_LEAKED_ENV_KEYS` strips only the payment keys) — the leaked DEV password mismatches the seeded test-DB admin's FALLBACK password, failing 4 wire suites' seeded-admin logins. Fixing only the strip list without the `.env.test` pair breaks the suites differently (5.1b; ledger D-414). `[canonicalized §8]`
