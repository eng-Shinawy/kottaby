## Gaps

1. **5.3.3 (INV-B3) deferral is stale** — the checklist's "no expiry surface exists this milestone" no longer holds. `subscription-expiry.service.ts` flips expired subscriptions and zeroes the owning lane (via `zeroLaneIfNoCoveringSubscription`, which skips zeroing when another active subscription covers the lane, and never zeroes `balance_trial`). The launch plan must either (a) flip row 5.3.3 to ✅ citing the existing tests, or (b) explicitly confirm with the team that DEV1-008 delivered this and update the checklist text. What is NOT yet pinned: an end-to-end "expired → balance zeroed → booking denied" chain test (expiry sweep + booking denial in one journey) — the pieces exist separately.
2. **No GraphQL transport test for admin extend (5.3.6/INV-B6)** — `subscription-admin.mutation.ts:109` wires `extendSubscription` and service tests cover admin-role enforcement (`subscription-admin.service.test.ts:626` non-admin denied, `:646` anonymous UNAUTHORIZED), but no `backend/graphql/test/subscription-admin.*.test.ts` exists (glob returned nothing). Pattern to copy: `backend/graphql/test/session-booking-balance.test.ts` (transport pin + role-gate probes).
3. **INV-W8 wording mismatch** — checklist says "amount >= 0"; schema enforces `amount > 0` (`teacher-transaction.ts:50`). Also amounts are `decimal(10,2)` strings, not integers. The checklist row should be corrected to match the stricter implementation; no code change needed.
4. **INV-B1 nullable-lane nuance** — `balance_hifz/tajweed/reviews` are nullable (`students.ts:24-26`); only `balance_trial` is NOT NULL (`:27`). CHECK `>= 0` does not reject NULL. The activation path quarantines NULL-lane plans (`subscription-activation.service.test.ts:652`) and repo credits treat NULL as 0 (`:463`), so behavior is sound — but a launch DB probe could optionally assert the prod DB has no NULL lane values on active students.
5. **Wallet CHECKs are repo-tested, trigger-immutability is migration-tested — but no single "constraint inventory" probe** exists that asserts all 6 named constraints (`wallet_balance_check`, `wallet_total_earning_check`, `wallet_teacher_id_unique`, `teacher_transaction_amount_check`, 4x `students_balance_*_check`) are present in the deployed prod schema. Each is individually verified in dev/test DBs via the tests above; a scripts/ probe could diff `pg_constraint` names against the expected list post-deploy.
