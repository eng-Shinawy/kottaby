## D. Design decisions

1. **Predicate identity without touching the client** — the truth table must exercise the real predicate, but exporting `shouldUseSsl` from `backend/db/client.ts` would be a production change outside the task's file list. The test extracts the predicate source from the client via a regex and pins it whitespace-normalized against `CANONICAL_PREDICATE_SOURCE`; the mirror function evaluated by the truth table is that exact text re-typed (kept in lockstep by an adjacent docblock). A runtime `toString` identity comparison was attempted and REJECTED: Bun's transpiler strips types and minifies literals (`false` → `!1`) before `Function.prototype.toString`, so toString output is not source text. Any drift in the client's predicate fails the identity pin until the canonical text and mirror are consciously updated.
2. **Scanner stays explicit-target, fail-closed** — no default corpus anywhere: an empty target list remains the named FAIL row `secrets-scan.targets` (the 1.5 §G mandate: "do NOT auto-default the scanner"). The registry command is what carries the corpus; the D7 pre-commit leg (the stamped launch report path, task 4.4) rides the same positional interface — the registry command cannot carry a stamped path by design.
3. **Detection over ACTIVE lines only** — comment lines (`#`, `//`, `*`, `/*` prefixes) are skipped uniformly across all three rules. Rationale: the env template documents examples in comments (`# DATABASE_URL=postgresql://<user>:<password>@ep-example…`), and the row's criterion is hardcoded secrets in active assignments. Honest blind spot, recorded in the scanner docblock and in §G below.
4. **`\w`-based lexers after lint** — sonarjs `super-linear-regex` + `concise-regex` forced the simplification: env form `^(\w+)=(.*)$` (no spaces around `=`, the dotenv convention), code form `\b(\w+)\s*["']?[:=]\s*(["'])(.*?)\2` (one `\s*` before the optional closing quote). Semantics re-verified against the corpus and all fixtures after the change.
5. **Quoted JSON keys join the code-literal rule** — `"NAME": "value"` matches via the optional closing quote after the name, so a secrets-bearing JSON report row body would trip; the paired test pins this shape (and a redacted-shaped report fixture passes — the D7 leg).
