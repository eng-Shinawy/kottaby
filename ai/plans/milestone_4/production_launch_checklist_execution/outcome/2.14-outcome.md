## E. Harness Findings Fixed During the Work

1. **ws-soak pacing** — the initial driver opened all 100 sockets in one burst; the sidecar's per-IP handshake bucket correctly throttled it (95× `4429`). The fix is on the DRIVER side (open sequentially, retry `4429` after one refill interval, settle grace before counting a socket established) — the sidecar's fail-closed throttle is production defense and was never touched.
2. **Self-close misread** — the original verdict computed `heldCount` after the driver's own graceful `close(1000)`; a socket's own teardown close would land in the mid-window watcher and zero the hold count. Fixed: snapshot all verdict counts BEFORE closing (plus a 500ms boundary-race grace).
3. **Role casing in the load mix** — the login payload carries enum casing (`Student`), so the student hot-read set (directory browse + session list) silently fell through to the inbox-only shared set. Fixed with case-insensitive role matching; the final run exercises all three hot reads (~4.6k requests each).
4. **Per-status latency split** — with 98.8% of requests 429'd, overall percentiles measure the limiter, not the serving path. The driver + artifact now record a per-status breakdown (`perStatus`) so the 200-only percentiles are explicit evidence for the <500ms target's drill.
5. **`main()` over the 75-line oxlint cap** (load-test.ts after the split) — extracted `reportRun` per the repo convention (split, never disable).
