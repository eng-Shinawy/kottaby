## D. Exported API (authoritative for task 1.4 — deep-import from `@/scripts/launch/launch-report`)

```ts
export interface SignedWaiver {
  readonly rowId: string;
  readonly why: string;
  readonly owner: string;
  readonly signatory: string;   // "" / whitespace-only = unsigned → verdict FAIL
}

export interface LaunchReportWriteOptions {
  readonly outputDir?: string;                  // default "docs/planning" (resolved against cwd)
  readonly now?: Date;                          // clock for stamp + generatedAt (default now)
  readonly stdout?: (line: string) => void;     // VERDICT print sink (default console.log)
}

export interface LaunchReport {                 // the emitted JSON document, field-for-field
  readonly generatedAt: string;
  readonly verdict: "PASS" | "FAIL";
  readonly stages: readonly StageResult[];      // {stage, status, startedAt, finishedAt}
  readonly rows: readonly LaunchReportRow[];    // {rowId, section, modality, command, exitStatus, result, evidenceRef, timestamp}
  readonly waivers: readonly SignedWaiver[];    // {rowId, why, owner, signatory}
}

export function computeVerdict(
  rows: readonly LaunchReportRow[],
  waivers: readonly SignedWaiver[] = []
): "PASS" | "FAIL";

export function writeLaunchReport(
  rows: readonly LaunchReportRow[],
  stages: readonly StageResult[],
  waivers: readonly SignedWaiver[] = [],
  options: LaunchReportWriteOptions = {}
): string;   // returns the written path (repo-relative with the default outputDir from the repo root)
```

### Verdict rule (as implemented — matches the Launch Gate rule exactly)

`computeVerdict` returns `"FAIL"` iff ANY of:
1. any row's `result === "FAIL"`;
2. any waiver record has an empty/whitespace-only `signatory` (the literal "any waiver lacks a signatory" rule — it applies over the whole waivers array, not only rows marked WAIVED);
3. any row marked `"WAIVED"` has no waiver record with a non-empty signatory for its `rowId` (waiver matched by `rowId` only).

Otherwise `"PASS"`. All-PASS → PASS · one FAIL → FAIL · unsigned waiver → FAIL · signed waiver → PASS (the mandated truth table, all four pinned by tests).

### Signature reconciliation (documented deviation-additive, not a break)

The design §8 lists the two-param shapes `computeVerdict(rows)` / `writeLaunchReport(rows, stages)`, while the same design + the signatory rule + the TE truth table require signatory awareness — which cannot live in `LaunchReportRow[]` (the 1.1 type module froze that shape; the report's `waivers` array carries `signatory`, collected at human sign-off). Resolution: **optional trailing parameters** (`waivers = []`, `options = {}`). Every plan-mandated call shape still compiles and behaves per plan; the gate (1.4) supplies the signed-waiver records and may pass `options.outputDir` (1.6's dry-run temp report) — with the defaults reproducing the plan's exact two-arg behavior.

## E. Stamping & naming (carry-forward for 1.4)

- File name: `launch-report-${utcStamp(now)}.json` where `utcStamp` is the ops precedent (`@/scripts/ops/backup-artifacts`) — second-resolution `YYYYMMDDTHHMMSSZ`, charset `[0-9TZ]` (e.g. `launch-report-20260102T030405Z.json`). `generatedAt` is the full `now.toISOString()` (millisecond precision).
- Default output directory: `"docs/planning"` joined with the name and resolved against the process working directory — the gate runs from the repo root, so the returned path is the repo-relative `docs/planning/launch-report-<stamp>.json` (usable directly as an `evidenceRef`).
- **Exclusive create (`flag: "wx"`)**: the writer fails closed if the stamped file already exists — a same-second double run throws instead of clobbering a committed report (restore-family precedent). Distinct runs get distinct stamps, so ordinary re-runs never collide.
- **Path safety**: the path is derived from `outputDir` + the clock ONLY; row/stage/waiver data never touches it (pinned by a hostile-rowId test — `"../../../etc/cron.d/evil"` rowIds leave the path unchanged).

## G. Carry-Forward Knowledge for Task 1.4 (launch-gate.ts)

1. **Call shapes**: `writeLaunchReport(rows, stages, waivers, options?)` returns the written path — print/keep it as the run's report reference; `computeVerdict(rows, waivers?)` if the gate needs the verdict before/without writing.
2. **The gate MUST pass a `SignedWaiver` for every row it marks `WAIVED`** — derive `{rowId, why, owner}` from `LAUNCH_CHECKLIST`'s `waiver` metadata and attach the collected human signatory; a `WAIVED` row without a signed record fails the verdict, and any unsigned waiver record anywhere fails it. Waiver→row matching is by `rowId` only.
3. **Report write happens once per completed run** — exclusive create means same-second rewrites throw; a resumed/repeated run naturally lands a new stamp (a new report file), which is what the reproducibility criterion expects (per-row verdicts reproduced across two stamped files).
4. **1.6 dry-run**: pass `options.outputDir` = a temp path (and optionally `options.stdout`) to avoid touching `docs/planning/`; the returned path is `join(outputDir, launch-report-<stamp>.json)` verbatim.
5. **Redaction is structural** — the gate can hand rows straight from its in-memory collection; any diagnostic baggage it attaches to those objects is dropped at serialization time, never reaching the committed report.
6. **Evidence row tuple** — the writer does NOT synthesize or mutate row fields; what the gate puts in `LaunchReportRow` (incl. `exitStatus: 0` for evidence-existence rows) is exactly what the report carries.
