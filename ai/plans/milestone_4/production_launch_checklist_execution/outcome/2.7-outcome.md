1. **Expired-token pin (row 4.1.3)** — `backend/lib/auth/jwt.test.ts` (EDIT, +61 lines): a new
   `describe("Expired-token rejection")` with a `signTokenWithExp` test seam that signs tokens carrying
   the EXACT claim structure the production signers produce (HS256, `sub`/`iss`/`iat`/`type` + domain
   claim, issuer `"draft-academy"`) but with a caller-controlled `exp` — the production signers only
   set future expiries, which is precisely why no expired-token test could exist before (research-04
   gap 1). Four legs: **control** (same claim structure, future `exp` → verifies, so the `null` results
   below are attributable to `exp` alone), **expired access** (`-1h` → `verifyAccessToken` → `null`),
   **expired refresh** (`-1h` → `verifyRefreshToken` → `null`), **exactly-now boundary** (`exp` equal to
   the current epoch second → `null` on both verifiers — deterministic because jose rejects
   `exp <= now` with `now` floored to whole seconds, and the verifier's floored now can only be ≥ the
   signer's; no timing window, no fake timers, verified flake-free across 5 consecutive full-suite runs).
2. **Cookie-contract pin (row 4.2.4 / D12)** — `backend/lib/auth/cookies.test.ts` (EDIT, +134 lines):
   a new `describe("auth cookie serialization contract")` pinning the serialized `Set-Cookie` strings
   produced by `setAuthCookies`/`clearAuthCookies` (as-built `serializeCookie`, `cookies.ts:197-202`)
   with **exact full-string equality** (stronger than the mandated flag-substring pin):
   - names `access_token` / `refresh_token` / `session_id` (pinned via `AUTH_COOKIE_NAMES`);
   - every auth cookie carries `HttpOnly; SameSite=Strict; Path=/` — the CSRF posture pin (NO token
     mechanism invented, per D12; the row's re-wording itself belongs to task 3.2 / REQ-002 AC-10);
   - `Max-Age` expiry semantics: access `900`, refresh `604800`, session `604800`; `clearAuthCookies`
     → empty value + `Max-Age=0` on all three;
   - `Secure` flag truth table: absent in development, present in production
     (`…; Path=/; Secure; Max-Age=…`), `AUTH_COOKIE_SECURE=false` disables it in production
     (opt-out only), `AUTH_COOKIE_SECURE=true` cannot force it on outside production — the documented
     "can only DISABLE, never force" posture;
   - **Tier-4 attribute-smuggling leg**: a token value shaped `v; Secure; SameSite=None; Max-Age=999999`
     stays URL-encoded inside the value position (`encodeURIComponent`), adds no attribute segments
     (`split(";").length === 5`), and neither raw flag string appears — cookie-flag tampering via
     token values is impossible.
