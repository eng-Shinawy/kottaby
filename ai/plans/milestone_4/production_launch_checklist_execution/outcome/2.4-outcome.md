## D. Census design (carry-forward)

- **Member derivation**: `Object.entries(NotificationType)` — never re-hardcoded (SR mandate). The sibling parity test intentionally keeps `CANONICAL_VALUES` as the single hardcoded ground truth; the census derives from the shipped enum, so the two form a two-sided lock (parity pins enum↔pgEnum↔canonical list; census pins behavioral coverage).
- **Emitter oracle**: read-only fs walk of `backend/services/**` non-test `.ts`/`.tsx` files; a member passes if ≥1 file contains `NotificationType.<Key>`. The service layer is the emitting layer by the 6-layer architecture (every production emission flows through a service calling the notification engine) — verified: all 10 members have key-referencing emitters there.
- **Exercising-test oracle**: fs walk of `*.test.ts(x)` under `backend/` + `test/`; ≥1 file must contain `NotificationType.<Key>`. The parity test `notification-type.enum.test.ts` is EXCLUDED (whole-inventory enumerator that exercises no emitter — counting it would make the oracle vacuous for any member).
- **Vacuity guards**: corpus floors (≥10 emitter files, ≥50 test files), 7 sentinel emitter paths (one per emitting flow), derived-member uniqueness. A broken walker (wrong root, empty corpus) cannot fake green.
- **Per-member evidence (as walked live)**: session_request → `session-request-notification.service.ts` / `session-request-notification.service.test.ts`; session_completion → `session-report-notification.service.ts` / `session-report-notification.test.ts`; session_cancellation → `session-request-notification.governance.ts` / `notification-engine.projections.test.ts`; parent_link_request → `parent-link-request.service.ts` / `parent-link-request.service.test.ts`; system_broadcast → `admin-broadcast.service.ts` / `admin-broadcast.journey.test.ts`; payment_confirmation → `subscription-activation.service.ts` / `subscription-activation.service.test.ts`; evaluation_result → `evaluation-rubric.helpers.ts` / `evaluation-rubric.service.test.ts`; session_dispute_opened + session_dispute_resolved → `session-dispute-notification.service.ts` / `session-dispute-notification.service.test.ts`; applicant_outcome → `applicant-lifecycle.helpers.ts` / `applicant-lifecycle.service.test.ts`.
