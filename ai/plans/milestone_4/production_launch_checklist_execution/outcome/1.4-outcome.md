### Execution semantics (as built)

- **Stage execution**: rows from `rowsForStage(stage)`, commands spawned verbatim (`shell: false`, `cwd` = repo root, output streamed live and captured). Repeated commands within a stage run once (`executedCommands` map); sibling rows reuse the first execution's result.
- **Existence-marking**: MANUAL-DRILL / DOC-SIGNOFF rows never spawn; marked from the existence of their evidence artifact (`join(cwd, evidenceRef)`). Missing artifact → FAIL with the rowId (never auto-passed).
- **Wildcard drill stamps**: an evidence ref still carrying a `<placeholder>` segment after substitution (row 7.7's `restore-report-<drill-stamp>.json`) is existence-checked as a directory glob: prefix/suffix match on the file name — the drill files its artifact with a real stamp.
- **Operator placeholders**: a command still carrying `<...>` (rows 6.1's `--url <server-url>`, 7.7's `--target <scratch-dsn>`) is a config error → the row is marked FAIL with the rowId, never spawned half-filled.
- **Waived rows**: run their command; green + registry waiver metadata → `WAIVED` in the report (the human signatory is collected at sign-off — until then the verdict computation blocks).
- **Self-referential criterion rows**: rows whose command IS the gate CLI (9.6–9.13 per-section criteria + 9.16) are NEVER spawned — the process lock is descendant-re-entrant, so a spawned gate would recurse the whole run. They are lineage-certified: the gate only reaches the final stage after every earlier stage passed, so a criterion row evaluated in the final stage is marked PASS from that lineage (pinned by test; see §F).
- **Verdict**: on full completion the gate writes the report via `writeLaunchReport` and computes the verdict with `computeVerdict(rows, waivers)` — unsigned waivers block by design, so a completed run today yields `VERDICT: FAIL` until human sign-off attaches signatories. `main()` exits 0 iff the final verdict is PASS (halted runs exit with the failing row's exit status).
- **Resume**: state persisted after every stage; interrupted runs resume at `STAGES.indexOf(state.stage)`; the stage index is trusted over the lifecycle label (a stale `DONE` on a non-final stage is resumable). A corrupted/mid-write-truncated state file falls back to FRESH (never a hard failure).
- **`--fresh`**: deletes `.launch-gate-state.json` ONLY — never any cache. **`--dry-run`** is fully read-only: walks all 173 rows, resolves evidence refs, validates the per-stage inventory (17/25/17/16/34/7/7/33/17), zero spawns, zero state/cache writes, no report.
- **Lock**: `withProcessLock("launch-gate", …)` from `@/scripts/lib` (existing helpers, no homemade locks); the D7a exemption (`isTimeoutExempt` + the `withProcessLock` comment) keeps the multi-hour gate from the 5-minute lock timeout.
- **Logging**: structured diagnostics via `@/backend/lib/logger`; record/evidence lines via bare `console.log` (the ops stdout-line-as-record pattern, lawful under the `scripts/**` no-console carve-out).

## F. Design discoveries (binding for 1.5/1.6/3.1)

1. **Self-referential gate rows (9.6–9.13, 9.16) must never be spawned** — the process lock's descendant re-entrancy would recurse the entire gate. The gate dispositions them from the completed lineage (PASS iff evaluated in the final stage). Row 9.16's deep ticket-state audit (TICKETS.md grep) is NOT implemented in the gate — its registry command cites the gate itself; if the orchestrator wants a real ticket audit, it belongs to the 3.1/4.x wave (see §G).
2. **`<drill-stamp>` substitution**: row 7.7's evidence ref carries a placeholder no stamp can fill at gate time — the gate glob-matches the filed artifact (`restore-report-*.json`) in the outcome directory. The 3.x drill tasks must file the artifact with a real UTC stamp for the row to flip.
3. **Completion ≠ PASS verdict**: a fully green run still reports `VERDICT: FAIL` while the 8 waiver records are unsigned (signatory collected at human sign-off, task 4.5). `main()` exits non-zero accordingly — "exit 0 iff final VERDICT: PASS" is exact.
4. **Today's real-run halt points** (verified by the resume tests): 6.1 (operator placeholder `--url <server-url>` — the load drill fills it), 7.1 (missing `backup-timer-signoff.md` drill artifact), 7.7 (missing restore report). Everything else disposition-resolves with stubs; s8+s9 complete end-to-end today.
5. **Dry-run gap for 1.6**: the current `--dry-run` walk validates registry resolvability + per-stage inventory + evidence-ref resolution and prints the waiver/drill row inventory, but does NOT itself round-trip the state file or write a sample report. Task 1.6's text ("validates state-file round-trip + resume short-circuit + `--fresh` scope, and writes a redacted sample report to a temp path") is fully covered by the paired test (state round-trip, resume short-circuit, `--fresh` scope) and by `runOptions.outputDir` + `runCommand` stubs; if 1.6 wants the CLI dry-run itself to perform those, extend `dryRunWalk` in that task (1.6.QL already anticipates "sub-loop on any file touched by fixes").

The branch is 2 lines of prefix/suffix matching; low risk.
