### Design decisions binding the Phase 2 fill-ins

1. **`ProbeDb` seam vs the plan's `NodePgDatabase` param** — plan C5 says `probeDecisions(db: NodePgDatabase)`. The implemented seam is the structural `ProbeDb` interface (the one `execute` method the probes use); the shared client's `db` satisfies it (verified by the live runs). Rationale: the repo's oxlint `no-unsafe-type-assertion` forbids the `as unknown as NodePgDatabase` casts test stubs would need, and `Pick<NodePgDatabase, "execute">` still cannot be stubbed cast-free (drizzle's `execute` returns `PgAsyncRaw`, a promise-like with extra members). The seam keeps every plan-mandated call shape compiling (`probeDecisions(db)` with the real handle). 2.13/2.10 extend probeDecisions/probeConstraints bodies — the raw-SQL catalog queries all ride `db.execute`, so the seam needs no change.
2. **Connection probe lives INSIDE the exported probe functions** (`probeDecisions`/`probeConstraints` call `probeDbConnection` first) — this keeps the plan §11 "named connection error row" behavior testable through the exported function and uses the `db` parameter at skeleton depth.
3. **`verify-cron` takes no process lock and no DB** — it is stage-level arming corroboration, deliberately cited by no registry row (1.2 outcome §G.5); its rowIds are the four route paths.
4. **`main(args = process.argv.slice(2))`** — argv is post-interpreter tokens (tests pass synthetic arg arrays). Usage surface per probe: `--help`; `--url <base>` (verify-cron only); positionals = target paths (secrets-scan only); everything else is a usage error (exit 1). `--secret` is rejected as unknown — argv carries no secret surface, pinned by test.
5. **Error-message details are scrubbed** through the existing `scrubDsnSecrets` (`@/scripts/ops/_shared`) before any line is emitted — a planted DSN-with-password in a connection error is masked (pinned by test). `errorMessage` is deep-imported from `@/scripts/ops/backup-toolchain` (the cross-script reuse precedent: launch-gate imports `utcStamp` from ops).
