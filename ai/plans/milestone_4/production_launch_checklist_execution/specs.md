## 1. Executive Summary & Problem Statement

### 1.1 Feature Summary

Ship a one-command, resumable launch gate (`scripts/launch/`) that executes the 173-row production readiness checklist by running existing suites, probing the deployed schema, executing DR and load drills, reconciling false-as-written rows to as-built semantics, emitting a machine launch report, and collecting the five human sign-offs — so that opening the platform is an evidenced decision rather than a hopeful one.

### 1.2 Problem from each perspective

- **Launch operator (Dev 3):** 173 rows × ~15 scattered suites per section — no single command produces per-row evidence; sign-off today would be manual transcription and trust.
- **Signatories (EM / Dev 1 / Dev 2 / Dev 3 / PO):** cannot honestly sign rows whose wording describes a platform that does not exist — 2.2.2 "balance held, not decremented" vs the real request-time lane debit; 3.2.1's nonexistent session-scoped WS lane; 4.2.4's nonexistent CSRF token; 8.11's "80% threshold" vs the real per-submission minimum score of 80.
- **SRE / operator:** DR tooling shipped but no drill has ever been executed or evidenced; the cron sweeps and the backup timer need an externally-armed scheduler that nothing in-repo proves is armed.
- **Future auditors:** evidence is scattered across 54 journey files and ~145 db/service tests with no row→suite manifest; the checklist's own five ✅ citations are the only precedent format to follow.

### 1.3 Business value

Closes Milestone 4's final gate (`MILESTONE_PLAN.md:367`) with reproducible evidence: every ✅ cites a command and artifact, every waiver names its owner, and the platform opens with a filed launch report instead of an untracked checklist.
