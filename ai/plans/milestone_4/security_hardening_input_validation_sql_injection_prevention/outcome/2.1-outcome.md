## Deviation from plan text (documented, deliberate)

The plan/tasks specify `readonly clientIp: string` (required). Making it required produced **15 NEW tsgo TS2741 errors** in pre-existing `Context`-shaped literal fixtures (`backend/graphql/test/*.test.ts` ×13, `app/api/graphql/test/graphql-route.pipeline-order.test.ts`, and more — all files NOT assigned to this task). Fix-Or-Report forbids modifying unassigned files, and leaving 15 new tsgo errors would breach the no-new-error baseline discipline. The factory's own sanctioned precedent for this exact situation — `idempotencyKey` (`gqlContextFactory.ts:81-84`, "Optional in the TYPE only so pre-existing Context-shaped fixtures stay compile-clean") — was applied: **`readonly clientIp?: string`, optional in the TYPE only; `createGraphQLContext` ALWAYS materializes it at runtime** (pinned by test: absent-headers context has `clientIp === "local"`, never `undefined`).

**Carry-forward for tasks 2.2/2.3:** `ctx.clientIp` types as `string | undefined` for literal-fixture callers. Task 2.3's planned `enforceAuthMutationRateLimit({ clientIp: ctx.clientIp, ... })` against 2.2's planned `{ clientIp: string }` input will need `ctx.clientIp ?? "local"` (or equivalent) at the call site, or 2.2 may widen the input type. Real factory-built contexts always carry the field.
