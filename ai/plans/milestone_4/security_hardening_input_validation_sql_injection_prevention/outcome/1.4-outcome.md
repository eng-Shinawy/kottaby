## Checkpoint Sequence as Implemented (`route.ts` POST)

1. **Origin gate** (unchanged, first).
2. **Declared checkpoint** — `Number(request.headers.get("content-length") ?? "0")`; rejects via `apiErrorResponse(badRequestError(tErrors.badRequest), …)` when `Number.isFinite(declaredLength) && declaredLength > MAX_SET_LOCALE_BODY_BYTES`, BEFORE the body stream is touched. Missing/garbage header falls through (transport-tier live predicate mirrored verbatim from `backend/lib/gateway/transport-guard.ts`).
3. **Bounded drain** — single `await request.text()`.
4. **Drained checkpoint** — `rawBody.length > MAX_SET_LOCALE_BODY_BYTES` → same localized `badRequestError` envelope (catches lying small declared headers; cap unconditional).
5. **`JSON.parse(rawBody)`** inside the kept try/catch — `SyntaxError` → localized BAD_REQUEST envelope (verbatim semantics); non-syntax faults rethrow to the single masked 500 hop.
6. **`isSetLocaleBody` whitelist** (unchanged, downstream of both caps) → success envelope + cookie.

## Notes for Downstream Tasks

- Bun/undici preserves an explicit `content-length` header verbatim on constructed `NextRequest`s even when it lies about the actual body — this is what makes the lying-header tests meaningful; it also auto-sets NO content-length for string bodies (the `?? "0"` fall-through is the common case in tests).
- Bun eagerly buffers `ReadableStream` bodies in the background after `NextRequest` construction — stream-side-effect counters cannot prove "handler never read the body"; use a `request.text` override spy instead (pattern now in the test file).
