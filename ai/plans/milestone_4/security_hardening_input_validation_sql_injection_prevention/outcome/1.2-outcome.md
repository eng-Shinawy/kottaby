## Guard decision table as implemented

| Request shape | Verdict |
|---|---|
| `Origin` present, `=== request.nextUrl.origin` | pass |
| `Origin` present, `space-z.ai` / `*.space-z.ai` (URL-parsed) | pass |
| `Origin` present, in `getWebSocketAllowedOrigins()` | pass |
| `Origin` present, anything else (incl. `""`, `"null"`, malformed URL, port-variant same-host, `space-z.ai.attacker.com`) | **403 `CROSS_ORIGIN_REJECTED`** |
| `Origin` absent + `Sec-Fetch-Site: same-origin` or `none` | pass |
| `Origin` absent + `Sec-Fetch-Site` absent (non-browser client) | pass |
| `Origin` absent + `Sec-Fetch-Site: cross-site` or `same-site` (or any other value) | **403 `CROSS_ORIGIN_REJECTED`** |

**Missing-`Sec-Fetch-Site` ruling (documented decision):** an absent `Sec-Fetch-Site` PASSES when `Origin` is absent — Bearer-header server clients and CLI tools send neither header and cannot be CSRF principals. The browser-forgeable metadata is what the gate inspects; absence of both headers is the non-browser signature, and identity/authorization is NOT this tier's concern (the gate is pre-authorization and identity-blind by design). This mirrors the design ladder's "reject unless `same-origin` | `none` | absent".
