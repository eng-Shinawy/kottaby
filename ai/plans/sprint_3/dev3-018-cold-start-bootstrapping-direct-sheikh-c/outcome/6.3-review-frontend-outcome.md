## Findings

### F-1 [LOW] Contract test does not pin variable types or the `makeEvaluator` `Boolean = true` default

- **Anchor:** `frontend/graphql/sharedDocuments/admin/teacher-certification.documents.test.ts:57-61`
- **What:** the variables test asserts only the NAME list `["userId","makeEvaluator"]`. It never inspects `variableDefinitions[].type` (so `Int!` vs `Int`, `Boolean` vs `Boolean!` are unpinned) and never inspects `defaultValue` (so the `= true` default — a load-bearing part of the REQ-062/plan §5.4 contract, matching the backend arg `defaultValue: true` — could regress to `= false` or be dropped while all 7 tests stay green). Codegen's `Variables` type does not discriminate defaults (`makeEvaluator?: boolean | null | undefined` stays identical either way), so tsgo cannot catch this either.
- **Gap check (vacuity):** the direction-style assertions elsewhere in the file are fine — full-order `toEqual` arrays would catch any field deleted or reordered, and `fieldSelections` filtering Field-only kinds cannot silently pass because the pinned arrays enumerate every expected field. The ONLY weak spot is the variables test.
- **Do:** extend the variables test to assert, per definition, the type shape (`NonNullType(Int)` for `$userId`, `NamedType(Boolean)` for `$makeEvaluator`) and `variableDefinitions[1].defaultValue` is `{kind: "BooleanValue", value: true}`. ~6 lines.
- **Severity rationale:** LOW — the shipped document itself was verified byte-equal to plan §5.4; this is a regression-detection depth gap, not a current defect.
