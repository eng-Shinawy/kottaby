## Deviation 1 — Pothos optional-arg typing (`args.makeEvaluator ?? true`)

The plan §3.2 code block passes `makeEvaluator: args.makeEvaluator` verbatim. tsgo rejects this:
Pothos types `t.arg({ type: "Boolean", required: false, ... })` as `boolean | null | undefined`
at the resolver boundary (the `defaultValue: true` is a SDL/runtime concern, not a static
narrowing), while `TeacherColdStartCertificationInput.makeEvaluator` is non-optional `boolean`.

Fix: `makeEvaluator: args.makeEvaluator ?? true` — mirroring the only in-tree precedent for an
optional Boolean arg with a default (`backend/graphql/query/plan-catalog.query.ts:42,50` —
`includeInactive: args.includeInactive ?? true`). Semantics are unchanged: the SDL default
(`Boolean = true`) makes the `?? true` arm unreachable at runtime; it is a type-level narrowing
only. Field-by-field BOPLA mapping is preserved (no spread).
