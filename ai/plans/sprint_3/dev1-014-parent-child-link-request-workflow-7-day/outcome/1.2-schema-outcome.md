## 3. Ledger D4 resolution — Drizzle expressibility of the partial unique

**Decision: NATIVE, zero custom SQL — implemented as `uniqueIndex("parent_link_requests_pending_pair_unique").on(t.parentId, t.studentId).where(sql`${t.status} = 'pending'`)`.**

Evidence trail (captured live this task):

1. **FIRST attempt per task text (plan §2.2 snippet `unique("…").on(…).where(…)`) FAILS at runtime** in the bundled drizzle-orm 1.0.0-rc.4:
   ```
   DATABASE_URL=…app_db bunx drizzle-kit push --force --config=drizzle.config.ts
   Error  (0 , _pgCore.unique)(...).on(...).where is not a function
   ```
   Root cause read from the installed package: `unique("name")` (`node_modules/drizzle-orm/pg-core/unique-constraint.js:5`) returns `UniqueOnConstraintBuilder` → `.on(...)` → `UniqueConstraintBuilder`, which has **no `.where()` method at all** — it builds a PostgreSQL table-level UNIQUE CONSTRAINT, and unique constraints cannot carry a WHERE predicate. (The `.d.ts` of `indexes.js` proves the `.where` capability exists on the OTHER builder: `IndexBuilder.where(condition: SQL): this` at `node_modules/drizzle-orm/pg-core/indexes.d.ts:67`.)
2. **The native partial-unique path is `uniqueIndex(...)`** (`node_modules/drizzle-orm/pg-core/indexes.js:105` → `IndexBuilderOn(true, name)` → `.on(...)` → `IndexBuilder` with `.where(condition: SQL)`). This is the same builder family as `index(...)` — only `unique: true` differs — so `uniqueIndex("…").on(…).where(sql`…`)` compiles AND pushes.
3. **Schema file corrected to `uniqueIndex(...)`** (the one-word deviation from the plan §2.2 snippet; semantics identical: a UNIQUE INDEX, which is exactly what PostgreSQL's `CREATE UNIQUE INDEX … WHERE` is).
4. **The fallback (custom SQL file + drizzle folder) did NOT fire.** D4 flipped 🔄 → ✅ in `deferred-items.md` with this outcome as reference. This is also the repo's FIRST native partial unique index in `backend/db/schema/` (grep: zero prior `uniqueIndex` usage; the WhatsApp `provider_message_id` partial unique cited in `backend/AGENTS.md:95` has no schema/migration artifact in this bundle).
