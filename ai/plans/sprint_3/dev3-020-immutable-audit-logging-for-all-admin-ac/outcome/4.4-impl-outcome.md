## 1. Harness finding (why `ReferenceError: document is not defined`)

Runner chain for the sanctioned single-file invocation:

- `bun run test/scripts/run-test.ts <file>` spawns **`bun --env-file=.env.test test <file> --timeout=60000`** with **NO `--preload` flags** (`test/scripts/run-test.ts:154`).
- `bunfig.toml` honors a **single** `[test]` preload list, which carries only the five global preloads (`test-runner-guard`, `logger-mock`, `ensure-env`, `graphql-interop`, `apollo-dev-flag`) — **no Happy DOM**.
- The four UI preloads (`test-env`, `happydom-preload`, `translation-preload`, `next-dynamic-mock`) are supplied **only** by the `test:ui:components` package script (`--preload` flags on the bun CLI), which is why sibling component suites are green under that script but a bare `run-test.ts` invocation of a DOM suite needs the suite to self-provision.

Resolution (test-file inline setup, following the stack the package script passes, in the same order): the suite replicates the four-preload stack as its **first module-body statements**, expressed as **top-level awaited dynamic imports**:

```tsx
await import("@/test/ui/test-env");
await import("@/test/ui/components/happydom-preload");
await import("@/test/ui/components/translation-preload");
await import("@/test/ui/components/next-dynamic-mock");
```

Design constraints that shaped this exact form:

1. **Lint:** bare side-effect static imports (`import "@/test/ui/...";`) fail oxlint `import/no-unassigned-import` (the rule's allow-list covers css/scss/mutation/query/type/enum/pothos globs + `@/backend/graphql/**` — `@/test/**` is not exempt), and oxlint-disable comments are forbidden repo-wide. Dynamic `import()` expressions are not import declarations, so the rule does not fire.
2. **Load order:** static imports evaluate before the module body regardless of source position, so everything in the static graph must be DOM-free at eval time — true here (the view imports only MUI / Apollo / locale, all call-time DOM readers; SSR modules must be). The preloads therefore run body-ordered, first, before `RTL` / `TestWrapper` are dynamically imported — preserving the established post-DOM `screen` binding contract (`@testing-library/dom` binds `screen` to `document.body` at module-eval time).
3. **Re-entry safety:** all four preload modules are re-entry safe (`GlobalRegistrator.isRegistered` guard, module-singleton registrations), so the suite also stays green under `bun run test:ui:components`, where the same stack arrives via CLI preloads.
4. **test-runner-guard untouched** — no runner flag was added; the guard's approved-runner list is exactly as before.

Exact contract the server route (Task 4.3) consumes:

```ts
export interface AdminAuditTrailFiltersSubmitInput {
  readonly actionType?: AuditActionType; // exact generated-enum value
  readonly actorId?: number;
  readonly entityId?: number;
  readonly entityType?: string;
  readonly from?: string; // inclusive range start, calendar day "YYYY-MM-DD"
  readonly to?: string;   // inclusive range end, calendar day "YYYY-MM-DD"
}

interface AuditTrailViewProps {
  /** Sanitized deep-link filter seed; undefined renders the unfiltered first page. */

```

Re-exported from the view module (`export type { AdminAuditTrailFiltersSubmitInput }`) so the route imports the seed type from the component it mounts. Wire semantics for 4.3: the view parses `from` to its own UTC midnight (inclusive) and `to` to the midnight AFTER the selected day (exclusive end), so a calendar-day range rides the wire as a half-open instant interval; values that fail the calendar parse are dropped view-side too (defense in depth behind the route's sanitize).
