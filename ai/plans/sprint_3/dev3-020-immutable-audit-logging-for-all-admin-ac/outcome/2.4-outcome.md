### 1.2 Pipeline (fixed, load-bearing order)

1. **`await assertActorAdmin(actorId, locale, outerTx)` FIRST** — the shared Task 2.1 gate (imported from `@/backend/services/admin/admin-gate.helpers`): `actorId === 0` → one bounded `logDomainError` (`{code:"UNAUTHORIZED", entity:"user", entityId}`) + `UnauthorizedError`; unresolvable or non-admin actor → one bounded `logDomainError` (`{code:"FORBIDDEN", …}`) + `ForbiddenError`. Zero writes, zero audit rows, no PII/filter payloads in logs.
2. **Pre-DB filter validation** (decomposed into four single-purpose module-scope validators, composed in source order so the sequential evaluation IS the REQ-053 precedence): `normalizeIdFilter` (positive-safe-integer guard on `actorId`/`entityId`, absent → dropped); `normalizeEntityTypeFilter` (trim → drop-if-empty → `varchar(100)` ceiling); `normalizeActionTypeFilter` (fail-closed membership re-assertion via `Object.values(AuditActionType)`); `normalizeWindowBounds` (valid `Date`s via `Number.isFinite(getTime())`, `from` strictly before `to`). All rejections throw a single localized `ValidationError` (`getServerTranslations(locale).errorsTranslations.validation`) — no hardcoded copy, no field-payload echo.
3. **Pre-DB pagination** — `resolvePageBounds(page ?? 1, pageSize ?? undefined, locale)` (from `user-management.helpers`): defaults 1 / 25, positive integer, pageSize integer in `1..100`, `offset = (page-1)*pageSize`; same localized `ValidationError`.
4. **ONE consistent-snapshot transaction** — `readInSnapshot`: a fresh top-level `db.transaction(fn, { isolationLevel: "repeatable read" })` when no caller transaction (D3-pinned txConfig shape, verified in Task 0.2 against drizzle-orm 1.0.0-rc.4 node-postgres), or a nested `outerTx.transaction(fn)` joined to the caller's transaction otherwise. Inside: `AuditTrailRepository.countEntries(normalized, tx)` + `AuditTrailRepository.listEntries(normalized, resolvedPageSize, offset, tx)` receive the SAME executor and the SAME normalized filter object.
5. **Row mapping** — `mapTrailRow` coerces the raw stored `action_type` string through the shared `toAuditActionType`; `null` → plain `new Error("Unexpected audit action type: …")` (D6 masked-internal precedent — never a domain error code, never an unsafe cast; the transport boundary masks it to a generic internal error). `details`/`entityId` pass through verbatim; `actorName` is the actor's CURRENT display name from the repo's `users` inner join (documented live projection).

Honest envelope: `{ items, totalCount, page: resolvedPage, pageSize: resolvedPageSize }` — out-of-range page → empty `items` with the unchanged honest count (never clamped, never an error). Happy path logs NOTHING; reads never audit (pure read surface, zero writes).

## 2. Part 2 — Test engineering (2-d-te)

### 2.1 Inherited state and root cause

The prior interrupted run left `audit-trail.service.test.ts` at **26 pass / 8 fail**, with all 8 failures TEST-SIDE. A temporary probe (impl part, then deleted) proved the service emits exactly 1 `logDomainError` per gate denial and 0 on validation rejections — the service was never modified in this part. Root cause, confirmed by probe:

- **bun's `spyOn` reuses ONE mock per object+method pair until restored** — `silenceDomainLog()` / `spyTrailReads()` spies were never restored, so `mock.calls` accumulated across tests ("Expected 1, Received 12" on `countEntries`). The two tests that DID restore (finally blocks) passed; every assertion after an unrestored spy's first use was poisoned.
- **TS6133** unused `users` import (line 49) — the project's only `bun tsgo` error.

Probe-verified bun semantics (scratch tests, deleted): reused-until-restored mock identity + call accumulation; `mockRestore()` → next `spyOn` yields a fresh mock with empty calls; double `mockRestore()` is safe; default `spyOn` is call-through; a file-level `afterEach` registered BEFORE the describes fires for every test in the file.

### 2.2 Repairs applied (test file only)

1. **Spy lifecycle discipline:** module-level `trackedSpies` registry + `trackSpy()` helper + a file-level `afterEach` that `mockRestore()`s every spy the finished test created (belt-and-braces `finally` blocks in the two pre-existing spy tests kept — double restore proven safe). `silenceDomainLog()` / `spyTrailReads()` and the four inline spies all route through the registry. Fresh mocks per test ⇒ call-count and `mock.calls[0]` assertions are order-independent.
2. **Removed the unused `users` import** (TS6133).
3. **Fixed one wrong test-side expectation:** "pagination boundaries" asserted `listTx === tx` (the outer rollback tx object). The service's documented semantics join a supplied transaction as a **nested block** (`outerTx.transaction(fn)`), so the repo receives the nested savepoint executor — never the outer object identity, never the global db. Corrected to the same identity oracles the sibling tests use (`toBeDefined()` + `not.toBe(db)`); executor-identity/same-tx oracles live in the snapshot suite.
4. **Added the missing coverage case:** `caller transaction supplied → the paired reads join it; NO new top-level transaction is opened` — spies `db.transaction` INSIDE the rollback wrapper (so only service-invocation calls are observed), asserts the wrapper spy saw zero calls, both reads called once with the SAME defined nested executor, and the live envelope. (The `db.transaction` spy is created inside `runInRollback`'s callback so the wrapper's own transaction open is not recorded.)

Implementation file: **zero diff** (byte-identical to the impl part's final state).
