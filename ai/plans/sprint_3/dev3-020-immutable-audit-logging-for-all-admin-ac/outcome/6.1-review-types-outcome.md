## 2. Findings

### F1 — [HIGH] `frontend/views/admin/audit/audit-trail-filters.ts:38` — duplicate definition of canonical type name `AdminAuditTrailFiltersSubmitInput`

The canonical `AdminAuditTrailFiltersSubmitInput` (plan §2.2, `backend/types/audit/audit-trail.types.ts:4`: nullable members, `Date` window bounds, service submit whitelist) is re-defined — under the **same exported name** — as a frontend view-local interface with a **different shape** (`YYYY-MM-DD` calendar-day strings for `from`/`to`, no `| null` arms). Check 1's bar is "exactly 1 definition + re-exports"; the repo-wide grep yields two definitions.

Why it matters (not a runtime bug today, but a real hazard):
- **Cross-layer identifier collision**: `test/workflows/admin/audit-trail.journey.test.ts:44` and the backend service consume the BACKEND shape while `test/ui/components/admin/AuditTrailView.test.tsx:78` and `app/(dashboard)/audit/page.tsx:5` consume the FRONTEND shape — same name, two contracts, resolved purely by import path. Any future import from the wrong barrel silently picks the wrong shape (`from: Date` vs `from: string` — a one-way door for a wrong-wire bug).
- Violates the plan's canonical-types-only gate (tasks.md 6.1) and the spirit of `.agents/instructions/frontend.instructions.md` ("NO HARDCODED TYPES — never redefine types that should come from codegen"; "Frontend stores must not redefine types that exist in generated types").
- The shape itself is legitimate (a view-layer deep-link seed the codegen genuinely does not emit — calendar-day strings, not wire instants) and plan §5 is silent on its name; the defect is the **name reuse**, not the shape's existence. `4.4-impl-outcome.md` documents the type but never acknowledges or justifies the collision.

Suggested remediation (owner: a Phase-6 fix wave or the 7.3 closing task; mechanical, ~4 files):
1. Rename the view-local interface (e.g. `AuditTrailFiltersSeed` / `AuditTrailFiltersSubmitDraft`) in `audit-trail-filters.ts:38`;
2. Update the re-export in `AuditTrailView.tsx:62` (+ import :53), `AuditTrailFilterBar.tsx:17,36`, `page.tsx:5,89,100,102`, and the UI test :78,:197;
3. Optionally tighten it as a derivative of the generated `AdminAuditLogFiltersInput` if a codegen anchor is wanted. No behavioral change; `bun tsgo` + the component suite (15/0) + route sanitize probes are the regression net.
