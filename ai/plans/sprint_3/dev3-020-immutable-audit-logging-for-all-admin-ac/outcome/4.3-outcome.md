## 2. Deep-link sanitize rules implemented (per value, silently dropped on failure — never error)

| Param | Rule | Drop cases |
|---|---|---|
| `entityType` | trim → keep iff non-empty and ≤ 100 chars | absent, whitespace-only, > 100 chars |
| `entityId`, `actorId` | strict digit shape via reused `parseIdInput` (`/^\d+$/`), then `1 ≤ n ≤ Number.MAX_SAFE_INTEGER` | absent, non-numeric, `0`, negative, fractional, > MAX_SAFE_INTEGER (leading-zero forms like `0042` → `42` are accepted) |
| `actionType` | membership guard `isAuditActionType` over `Object.values(AuditActionType)` (the canonical generated vocabulary, as `readonly string[]` — the repo's `isAppLocale` guard idiom; NO `as` casts, per frontend/AGENTS.md enum-safety rules) | absent, any string that is not an exact generated member (lowercase `create` is dropped — deep links must carry the GraphQL enum NAMES, e.g. `Create`) |
| `from`, `to` | each bound independently: reused `parseUtcDayStart` (strict `YYYY-MM-DD`, impossible dates like `2026-02-30` rejected, no rollover) | malformed bound dropped alone; the surviving partner stays as a one-sided window |
| `from` + `to` pair | zero-padded ISO days compare chronologically as plain strings, so no second parse: inverted pair (start AFTER end) → BOTH dropped | same-day pair KEPT (see decision below) |
| aggregation | only surviving values are passed on; when NOTHING survives the route passes `undefined` → the view renders the unfiltered first page | repeated params take the first value; `?k=` (empty string) counts as absent |

**Decision — same-day pair semantics (documented deviation from the task's literal "from < to" phrasing):** the route operates on CALENDAR-DAY strings, while the wire comparison happens on instants after the view expands `to` to the midnight AFTER the selected day (half-open interval). A same-day pair therefore produces `wire from < wire to` — a valid single-day window, and exactly the documented client convention ("a single picked day selects exactly that day"). Dropping it would contradict the view's own acceptance of same-day drafts and make single-day deep links impossible. The ONLY pair shape that would make the backend throw (an inverted range → empty/degenerate window) is dropped as a whole — dropping just one bound would silently rewrite the user's filter into a different one. The view re-normalizes behind the route anyway (defense in depth: test #12 of the 4.4 suite).

Probe-verified behavior (throwaway bun script against the real view-modules' parsers, 22 URL-shape cases — all pass): canonical `?entityType=user&entityId=42` survives; full six-param shape survives; hostile ids (`-5`, `0`, `3.7`, 20-digit), foreign enum (`create`), impossible dates (`2026-02-30`), wrong date shape (`01/02/2026`), 101-char entityType, empty strings, inverted ranges — all silently dropped; `?from=2026-02-01&to=2026-02-01` survives as the single-day window.

## 4. Carry-forward for the browser-loop agent (4.4.BF) — URL shapes that SURVIVE sanitization

- Seeded rows by entity: `/audit?entityType=user&entityId=<id>` (the per-user "view full audit log" target). Values arrive as `{ entityType: "user", entityId: <n> }` — the bar is pre-filled AND the first wire query carries `filters: { entityType: "user", entityId: <n> }`.
- Action filter: `/audit?actionType=Create` — **GraphQL enum NAME, capitalized**; `actionType=create` is silently dropped and renders unfiltered. All seven members survive: `Create Update Delete Reactivate Override Adjust Suspend`.
- Actor filter: `/audit?actorId=<adminId>`.
- Day range: `/audit?from=2026-02-01&to=2026-02-04` → wire `from=2026-02-01T00:00:00.000Z` (inclusive) / `to=2026-02-05T00:00:00.000Z` (exclusive, view-expanded). Single-day: `/audit?from=D&to=D` → `[D 00:00, D+1 00:00)`. One-sided windows (`?from=D` or `?to=D` alone) survive. Inverted ranges and impossible dates (`2026-02-30`) render UNFILTERED — do not use them to assert errors; there is none, by design.
- Combined example that exercises every dimension: `/audit?entityType=user&entityId=7&actorId=7&actionType=Update&from=2026-02-01&to=2026-02-04`.
- Auth shapes: anonymous → `/login?redirect=%2Faudit` (guard-internal); non-admin → its own role dashboard. Admin-only render otherwise; GraphQL-level denials render the shared `PermissionDeniedFallback` inside the view.
- After mount, ALL filter state is component-owned: editing/apply/clear never rewrites the URL — deep-link params are a one-shot seed.
