## 2. The four query shapes (plan §4.4 → implementation)

Signature: `resolveAudienceIds(selector, tx?)` — **tx branch** (Drizzle builders on the supplied executor) when a `DBTransaction` is passed (runtime-guarded via `"select" in tx`, the `UserRepository` precedent), **raw branch** (`queryDb` + numbered `$n` params) otherwise. Output for every shape: de-duplicated, `ORDER BY id ASC`.

**Governance predicate everywhere (both branches, all shapes):** `coalesce(is_deleted, false) = false AND coalesce(is_blocked, false) = false` — raw text constant on the raw branch; the logically identical `or(eq(col, false), isNull(col))` builder pair on the tx branch. NULL → eligible (legacy rows); suspended users NOT excluded (parked inbox rows self-heal).

### 2.1 Raw branch (queryDb, `$n`-parameterized)

```sql
-- all
SELECT id FROM users
WHERE coalesce(is_deleted, false) = false AND coalesce(is_blocked, false) = false
ORDER BY id ASC

-- role ($1 = selector.role)
SELECT id FROM users
WHERE coalesce(is_deleted, false) = false AND coalesce(is_blocked, false) = false AND role = $1
ORDER BY id ASC

-- country ($1 = selector.country) — EXACT eq; NO LIKE/ILIKE anywhere in the file,
-- so the escapeLikeWildcards sanitizer is N/A by construction (documented in the header)
SELECT id FROM users
WHERE coalesce(is_deleted, false) = false AND coalesce(is_blocked, false) = false AND country = $1
ORDER BY id ASC

-- plan ($1 = selector.planId) — JOIN + DISTINCT; canonical active-window predicate,
-- byte-equivalent to studentHasActiveSubscriptionSubquery (admin-user-query-helpers.ts:134-143,
-- the verified location per outcome/0.2 — the plan's admin-user.repository.ts:337-346 hint is stale);
-- owner FK = subscriptions.user_id (generic owner — a teacher's verification-plan subscription counts)
SELECT DISTINCT u.id
  FROM users u
  JOIN subscriptions s ON s.user_id = u.id
 WHERE s.plan_id = $1
   AND s.status = 'active'
   AND now() >= coalesce(s.start_date, now())
   AND (s.end_date IS NULL OR now() < s.end_date)
   AND coalesce(u.is_deleted, false) = false
   AND coalesce(u.is_blocked, false) = false
 ORDER BY u.id ASC
```

`s.status = 'active'` is a fixed state literal (not caller input), exactly as in the canonical predicate. No `sql.placeholder`, no prepared statements, no `inArray`, no inline `--` comments inside SQL.

### 2.2 Transactional branch (Drizzle builders on the supplied executor)

- `all` / `role` / `country`: `tx.select({ id: users.id }).from(users).where(and([eq(...)], ...governanceConditions())).orderBy(asc(users.id))`
- `plan`: `tx.selectDistinct({ id: users.id }).from(users).innerJoin(subscriptions, eq(subscriptions.userId, users.id)).where(and(eq(subscriptions.planId, planId), eq(subscriptions.status, "active"), sql`now() >= coalesce(${subscriptions.startDate}, now())`, or(isNull(subscriptions.endDate), sql`now() < ${subscriptions.endDate}`), ...governanceConditions())).orderBy(asc(users.id))`

DISTINCT only on the plan shape (single-table PK selects are unique by construction) — matches plan §4.4 verbatim.
