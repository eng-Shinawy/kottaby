
Contract details the journey pins (all from plan §4.1 flow + REQ-019/021/023/024):

1. **Return value** = the number of `notifications` rows persisted for this broadcast (the mutation's `Int!`).
2. **Fresh emission** writes: one `system_broadcast` row per resolved recipient + EXACTLY ONE `audit_logs` row — `actorId` = calling admin, `actionType` create (`AuditActionType.Create`), `entityType: "notification_broadcast"`, **`entityId: null`** (DB-5 widening — journey asserts null), `details` = capped JSON `{ scope, role?, country?, planId?, recipientCount }` and NEVER the copy text (journey parses and asserts: scope match, recipientCount == returned count, companions present, serialized details `not.toContain(title)`).
3. **Publish-after-commit** (fresh only): EXACTLY ONE envelope per fresh broadcast through `options.transport` carrying the FULL recipient id list (`receipt.recipientUserIds`), payload = representative-row realtime payload (`v:1`, `kind:"notification"`, `data.type=system_broadcast`, `data.title`, `data.relatedEntityType=null`). The journey compares the envelope's id set to the DB rows created under the run-unique title (DB oracle, no hardcoded lists).
4. **Replay** (same key + same injected cache): return the PRIOR count; ZERO new rows / audit rows / publishes. Replay is detectable structurally (`receipt.emitClaimKey === undefined` under key+cache per REQ-023) — the journey injects the cache on every call so the replay path is exercisable.
5. **Denials** (all pre-transaction, zero rows/audit/publish):
   - `actorId === 0` → `UnauthorizedError`, `extensions.code = "UNAUTHORIZED"`, message contains `errorsTranslations.unauthorized`;
   - non-admin (teacher/student/parent) or unresolvable actor row → `ForbiddenError`, code `"FORBIDDEN"`, message contains `errorsTranslations.forbidden` (the shared `assertActorAdmin` discipline — `admin-gate.helpers.ts:59`);
   - title empty-after-trim or >255 → `ValidationError("BROADCAST_TITLE_INVALID")`, message contains `errorsTranslations.broadcastTitleInvalid`;
   - audience incoherence (missing/mismatched/on-`all` companions, hostile non-member type string, malformed `planId: 0`) → `ValidationError("BROADCAST_AUDIENCE_INVALID")`, message contains `errorsTranslations.broadcastAudienceInvalid`;
   - cohort resolves empty → `ValidationError("BROADCAST_AUDIENCE_EMPTY")`, message contains `errorsTranslations.broadcastAudienceEmpty`;
   - unknown positive planId → `NotFoundError("PLAN", …)` → code `"PLAN_NOT_FOUND"`, message contains `errorsTranslations.planCatalog.planNotFound` (admin-surface oracle ruling REQ-033).
6. **Cohort semantics** exercised: `all` = every governed-eligible user; `role` exact (`users.role`); `country` EXACT `eq` (seeded users hold country `"Egypt"`, so `"EG"` matches only the fixture); `plan` = canonical active-window predicate on `subscriptions.user_id` (strict `now() < end_date` — the expired-window subscriber with `status='active'` is EXCLUDED); governance filter excludes `is_deleted`/`is_blocked` (the EG-country governed fixture proves exclusion INSIDE a targeted cohort, step 9).
7. `NotificationEngine.listMyNotifications` (existing substrate) must keep returning `{ items, totalCount, hasMore }` pages — step 10 consumes it unchanged.
