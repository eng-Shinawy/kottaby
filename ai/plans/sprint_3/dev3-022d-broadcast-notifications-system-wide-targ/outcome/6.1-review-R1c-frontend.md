[LOW] frontend/views/admin/broadcasts/BroadcastComposeContainer.tsx:64 — `useRef(randomUUID())` eagerly evaluates `randomUUID()` on EVERY render (useRef argument is discarded after first mount). Functionally harmless (first value is kept; rotation-after-success logic at :122 is correct and only-on-success as required), but a discarded UUID per render is impure-render waste — lazy init (`useRef<string | null>(null)` + mint on first use) avoids it.

[LOW] frontend/views/admin/broadcasts/broadcast-compose.helpers.ts:140-149 — the whitelisted per-field VALIDATION projection is currently a dead path on this surface: server rejections are `ValidationError("BROADCAST_TITLE_INVALID" | "BROADCAST_AUDIENCE_INVALID", msg)` with NO `extensions.fields[]` payload (backend/services/notifications/admin-broadcast.service.ts:106-109), and the frontend map table has no row for either code (`mapValidationRow` fires only on the literal `VALIDATION` code — frontend/providers/apollo/error-link.map.ts:243), so `applyBroadcastFieldErrors` always returns 0 and every server-tier failure lands on `t.errorTitle`. Shared-seam usage itself is correct (no bespoke renderer — checklist 5 satisfied); the container doc-comment (:129-131, "per-field mapping REPLACES the global-form fallback") overpromises reachable behavior. Awareness flag for the synthesizer; no code change required unless the server later emits `fields[]`.

[LOW] frontend/views/admin/broadcasts/BroadcastComposeContainer.tsx:89-94 — inline title error persists while the admin retypes the fix (recomputed only on next submit; standard UX is clear-on-change), and a projected `audience` error persists while editing the companion within the same kind (switching kind resets via `changeAudienceKind`, editing e.g. the country value does not).
