## Findings

**[MEDIUM] backend/graphql/test/admin-broadcast.integration.test.ts:263-290 (claim: header :13-19) — vacuous coverage: the wire "replay" leg cannot detect a regression that drops `X-Idempotency-Key` propagation.** Over the lifecycle server's hermetic cache-less default, the key is behaviorally unobservable: every accepted emission fail-open inserts a full cohort regardless of whether the resolver passes `ctx.idempotencyKey` or `undefined`. All assertions (same count, `afterFirst = before + firstCount`, `afterReplay = afterFirst + firstCount`) hold identically if the header is silently discarded at the resolver — the test exercises the header, it does not pin it. The suite header bullet "**Idempotency-key propagation** — the gateway-captured `X-Idempotency-Key` rides the header into the service" overstates the proof; the 3.3 outcome's cache-posture note honestly scopes the *replay* semantics but does not acknowledge that *propagation* is unproven at this tier. The real path is review-verified (R1d: `gqlContextFactory.ts:175-181` → `admin-broadcast.mutation.ts:101`), but no test would fail if that wire regressed. Fence options: assert the resolver→service seam (spawned-server spy on `AdminBroadcastService.broadcast`'s 4th arg), or tighten per the outcome's own noted path once `REDIS_URL` exists in the sandbox.

**[LOW] backend/services/notifications/admin-broadcast.service.test.ts:1060 — tautological assertion.** `expect(await totalNotificationRows(tx)).toBeGreaterThanOrEqual(0)` — `count()` is always ≥ 0, so the assertion itself can never fail. The *intent* (comment: "the outer transaction is still usable" after the savepoint rollback) is only proven by the query resolving rather than throwing, and the test has no `notificationsBefore` captured to make the check meaningful. Capture the pre-call total and assert equality (or assert the known fixture count) so the canary is falsifiable.

**[LOW] test/workflows/notifications/admin-broadcast.journey.test.ts:426-429 — journey audit "metadata only" proof is partial (weaker than it reads).** `expectOneAuditRow` asserts only the EXPECTED keys (`scope`, `recipientCount`, companions) and never that the metadata object has no extra keys (no exact-shape `toEqual` as the service suite uses at :349/:402/:442/:522), and its copy-leak guard is `not.toContain(title)` only (:429) — body copy is not guarded (the service suite checks both, :350-351). A regression that appended a `body`-carrying key to the audit metadata would pass the journey tier. Not a contract hole overall (the service suite pins the exact shape), but the journey's independent verification is the one admins see in the step map.

**[LOW] backend/services/notifications/admin-broadcast.service.test.ts:554,598 (+ journey :835,:860,:886) — "zero audit" oracle on denial paths is scoped to the ADMIN actor only.** The anonymous/non-admin denial tests recount `broadcastAuditRowsFor(tx, cast.admin.id)` — a regression that wrote a denial audit row attributed to the *denied caller* (teacher/student/parent/actor 0) would pass every zero-state assertion. In the journey the same scoping means such a row would also escape teardown tracking (`captureNewAuditRows` registers only `adminA`'s fresh rows, :391-399) and leak into the shared DB past `afterAll`. One-line fix per site: also recount audit rows for one denied actor (expected 0 / unchanged).

**[INFO] backend/services/notifications/admin-broadcast.service.test.ts:1138-1163 — tx-propagation test over-pins internal transaction topology.** `expect(insertTx).not.toBe(emitTx)` pins that the engine opens its own nested savepoint rather than reusing the service's write unit; a harmless engine refactor (reuse the supplied executor when one is already provided) would break the test with zero behavior change. The propagation assertions themselves (`gateSpy[1] === tx`, `emitTx !== tx`, `auditTx === emitTx`) are plan-mandated (2.4.TE "tx propagation to every repo/engine call"), so this is refactor-fragility, not a violation — and the file's comment block at :1157-1161 already documents the topology as intentional.

**[INFO] test/workflows/notifications/admin-broadcast.journey.test.ts:435-441 — dead defensive branch.** In `expectInboxCounts`, `if (count !== expected) throw` is unreachable after `expect(count).toBe(expected)` (the expect fails first). Cosmetic; no assertion-strength impact.

**[INFO] test/workflows/notifications/admin-broadcast.journey.test.ts:688-800 — step 6 zero-state recount covers only `ALL_TITLE` rows.** The validation probes carry `TEACHER_TITLE`/`EG_TITLE`/`PLAN_TITLE` as copy, but the post-denial recount queries rows by `ALL_TITLE` only (:797-798). A hypothetical regression that inserted before rejecting would write under the probe titles and be missed here — it IS backstopped downstream (step 10 pins exact per-actor inbox totals; step 9 pins `adminA`'s audit count at 4), so this is layered-verification redundancy, not a hole.
