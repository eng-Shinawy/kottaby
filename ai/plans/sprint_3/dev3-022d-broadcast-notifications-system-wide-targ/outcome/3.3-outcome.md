## 3. Cache-posture note (honest replay semantics at the wire tier)

The lifecycle server boots WITHOUT a configured `REDIS_URL`, so the service resolves NO claim cache and the engine's DOCUMENTED fail-open posture applies (single degrade warn, emit anyway — "a cache blip never blocks an admin announcement"). Consequently the cache-backed same-key/zero-new-rows replay contract is NOT assertable over this wire (a repeated key is a fresh emission); that contract is proven at the service tier with a scripted claim cache (2.4 journey suite, replay steps). The wire suite asserts what the real stack honestly guarantees without a cache: deterministic cohort ⇒ the SAME count on every accepted emission, and EXACTLY one cohort of rows per accepted emission (never a partial/silent write). If the sandbox later gains a Redis + `REDIS_URL`, rows 4's assertions tighten to same-count/zero-new-rows with no structural change to the suite.
