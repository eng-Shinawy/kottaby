# UI Test Rules (`test/ui/`)

`test/ui/` is **E2E-only** and contains two suites: the live Paymob checkout E2E (`test/ui/e2e/paymob-checkout.e2e.test.ts`) and the admin country-filter round-trip E2E (`test/ui/e2e/admin-country-filter.e2e.test.ts`). There is no static/component UI test layer — UI verification is E2E-only.

## The Paymob Suite

`test/ui/e2e/paymob-checkout.e2e.test.ts` drives the student purchase funnel end-to-end in a REAL browser, through the REAL vendor hosted checkout (`eg.checkout.paymob.com`), settled by the REAL webhook delivered over a REAL ngrok tunnel:

1. A per-run student registers and signs in over the real GraphQL API; a per-run plan is created as a fixture.
2. The student buys the plan from `/student/plans` → confirm dialog → `purchaseSubscription` → the browser redirects to the hosted checkout.
3. The sandbox test card pays on the hosted checkout (the context presents a regular desktop Chrome UA — Paymob's WAF 403s the default headless-Chromium UA).
4. The 3DS/processing step resolves; the vendor redirects through the tunnel's public domain and the processed webhook lands on `POST /api/payments/webhook`.
5. The result page renders the success branch and `mySubscriptions` shows the subscription ACTIVE (polled — the webhook may arrive after the redirect).

The suite requires `PAYMOB_LIVE_TESTS=1` + live sandbox credentials + the reserved tunnel domain. The dedicated runner supplies all three via `.env.paymob.test` (gitignored, generated by `bun run gen:paymob-test-env`); the suite **skips** otherwise.

## Commands

```bash
bun run test:ui:e2e:paymob           # Paymob live checkout E2E (generates .env.paymob.test, then run-server-tests.ts --e2e --port 3100)
bun run test:ui:e2e:country-filter   # Admin country-filter round-trip E2E (run-server-tests.ts --e2e, default port 3066)
bun run gen:paymob-test-env          # (Re)generate .env.paymob.test from the committed plan bundle
bun run build:test                   # Build .next-test-prod (required for production-mode E2E)
bun run test:kill                    # Kill stale test servers on the test port only (never dev:3000 or start:4000)
```

## The Country-Filter Suite

`test/ui/e2e/admin-country-filter.e2e.test.ts` drives the admin directory's country filter as a REAL admin in a REAL browser — the shareable-URL contract of the country-filter family (issue-230 follow-ups):

1. Fixtures are per-run and unique: an ADMIN row inserted through `createTestUser`/`createTestAdmin` (`@/backend/db/test/entity-setup`) with a **REAL bcrypt hash** (the login service verifies hashes — the shared stub hash can never log in), plus two STUDENTS registered through the REAL `registerUser` mutation with country `EG` / `US` (the product write path, so rows carry canonical `(country, country_code)` pairs).
2. The admin signs in over the real wire (Login mutation — the httpOnly cookies land in the API context's jar, shared by every page in the context).
3. DIRECT URL: `?country=EG` renders the applied-filter chip (`${filters.country}: ${flag} ${name}`) and honors the filter — the Egypt fixture visible, the US fixture absent.
4. UI SELECTION: picking مصر in the toolbar's `CountrySelector` rewrites the URL to `?country=EG` (the mirror effect) and paints the chip — the URL → state → URL round-trip closes.
5. CHIP DISMISSAL: deleting the chip drops the URL param; a US seed paints its own chip.

No live gate — the suite runs entirely against the test environment via `TEST_ENV_FILE=.env.test` (the sanctioned test base: `app_db_test`, `AUTH_COOKIE_SECURE=false`, sanctioned markers). Teardown deletes the created users' sessions and rows via `@/test/helpers/db-cleanup` (`deleteSessionsByParticipantUserIds` → `deleteUsersByIds` + residue check). Screenshots archive under the issue-230 plan bundle's `outcome/e2e-screenshots/` directory.

## Runner & Server Lifecycle

`test:ui:e2e:paymob` (see `package.json`) runs `gen:paymob-test-env`, then `test/scripts/run-server-tests.ts --e2e --port 3100 test/ui/e2e/paymob-checkout.e2e.test.ts` with `PAYMOB_LIVE_TESTS=1` and `TEST_ENV_FILE=.env.paymob.test`.

- **The runner owns the server**: `run-server-tests.ts` spawns the dedicated test server (dev mode via `next dev` by default; production mode via `next start` on the `.next-test-prod` build when `TEST_SERVER_MODE=production`), exports `TEST_SERVER_PORT` to the test process, and applies the 5-minute E2E timeout.
- **The runner preloads `test/ui/test-env.ts`** in `--e2e` mode — the sanctioned test-environment gate (fails fast without a sanctioned marker; defaults `TEST_SERVER_MODE=dev`).
- **The test file owns only the browser**: `chromium.launch()` in `beforeAll`, closed in `afterAll`. The base URL is `http://localhost:${process.env.TEST_SERVER_PORT}`. There is no shared E2E lifecycle/helpers file under `test/ui/` — do not invent one.

**Production mode (set `TEST_SERVER_MODE=production`):**

```bash
bun run build:test
```

- Output directory: `.next-test-prod` (override with `TEST_SERVER_DIST_DIR`)
- Tests do **not** run `next build` automatically; missing build fails fast with a clear error
- Rebuild `build:test` after changes to server code, auth/cookies, middleware, API routes, or anything that affects the running Next.js app

**Never stop the dev server (port 3000)** — it is externally managed; `bun run test:kill` only touches the dedicated test-server port.

## Suite Conventions

- Real dependencies only — no mocks anywhere in the funnel: real GraphQL API, real browser, real vendor checkout, real webhook over the tunnel.
- Fixtures: the plan is created per-run via `createTestPlan` from `@/backend/db/test/entity-setup` inside a committing transaction (the shared test database's catalog is impure — the funnel targets the plan the run owns, located by its unique title). The student registers through the real API.
- Tunnel/live gates: `@/test/helpers/paymob-live-env` (`arePaymobLiveTestsEnabled`, `resolveNgrokTunnelConfig`).
- Teardown: `afterAll` deletes everything the run created (notifications → payments → subscriptions → user → plan) via `@/test/helpers/db-cleanup` under `withImmutabilityTriggersSuspended`.
- Screenshots of each stage are archived under the plan bundle's `outcome/e2e-screenshots/` directory.
- No `waitForTimeout` / `networkidle` — use auto-waiting Playwright assertions.
- The test env must carry `AUTH_COOKIE_SECURE=false` so `http://localhost` works in both dev and production modes.

### E2E Translation Rules (CRITICAL — No Hardcoded Strings)

**NEVER hardcode user-facing text strings in E2E test assertions.** All text that appears in the UI must be obtained via the translation system. This is a strict requirement — no exceptions.

E2E tests are **server-side tests** (they run in Node/Bun, not the browser DOM). They use `getDefaultTranslations()` from `@/shared/locale/server` — a **no-parameter** function that returns translations for the app's default locale. The locale is determined by the app's default locale setting, not by the test.

**Never pass a specific locale to `getTranslations("ar")` or `getTranslations("en")` unless the test explicitly tests locale-switching behavior.** The default locale comes from the translation/locale provider — it's not a secret.

```typescript
import { getDefaultTranslations } from "@/shared/locale/server";

function escapeRegExp(str: string): string {
  return str.replace(/[.*+?^${}()|[\]\\]/g, "\\$&");
}
const tr = (s: string): RegExp => new RegExp(escapeRegExp(s), "i");

const T = getDefaultTranslations().dashboardTranslations;
const dashboard = T.studentPortalDashboard;
const NEXT_CLASS = tr(dashboard.nextClass);
```

**For exact match (e.g., button text):**
```typescript
const trExact = (s: string): RegExp => new RegExp(`^${escapeRegExp(s)}$`, "i");
const JOIN_BUTTON = trExact(dashboard.joinNow);
```

**For functional translations (functions that return strings):**
```typescript
const resultsCountPattern = escapeRegExp(sched.resultsCount("\\d+", "\\d+")).replace(/\\\\d\+/g, "\\d+");
const SEARCH_OUTCOME = new RegExp(`${resultsCountPattern}|${escapeRegExp(sched.noResults)}`, "i");
```

**For `selectOption({ label })`:** Use the raw string value (not a regex):
```typescript
await attendanceSelect.selectOption({ label: lr.present });
```

**For `aria-label` selectors:** Use `escapeRegExp` on the translation value:
```typescript
page.locator(`button[aria-label="${escapeRegExp(common.notifications)}"]`)
```

**Access pattern:**
- `getDefaultTranslations()` returns the full `Translations` object
- Access via `.<domain>Translations.<namespace>.<key>` (e.g., `.dashboardTranslations.<namespace>.<key>`)
- Other top-level: `.commonTranslations`, `.uiTranslations.phoneInput`, `.errorsTranslations`

### What Counts as "Hardcoded" in E2E (Prohibited)

- **Arabic/English UI labels** — e.g., `"متصل"`, `"Connected"` — must come from `getDefaultTranslations()`
- **Button text, badge text, headings, descriptions** — any text rendered by the app
- **Alert/error messages** — use translated strings from the appropriate namespace

### What is Acceptable in E2E (NOT "Hardcoded")

- **Technical test data** — URLs, HTTP status codes, error codes
- **Person names in test input** — input data, not rendered translations
- **Provider names** — e.g., `"Zoom"`, `"Google Meet"` are brand names, not translatable UI text

## Agent Browser Login (manual/E2E-style verification)

AI layers redact real email addresses in prompts, so email+password login typed via browser automation fails schema validation. Use `scripts/browser-login.ts` instead:

```bash
bun run scripts/browser-login.ts                       # login + write .browser-auth/ artifacts
bun run scripts/browser-login.ts --inject              # + inject cookies into $AGENT_BROWSER_SESSION
```

### Screenshot & Visual Inspection Context Isolation (CRITICAL)

- **Do NOT call `ReadMediaFile` directly in the main test/orchestrator context** for browser screenshots.
- In multi-step browser verification runs, calling `ReadMediaFile` repeatedly accumulates multiple images into the conversation history, creating multi-megabyte payloads that cause upstream LLM timeouts and stream drops (`Error: Stream ended before producing a non-ping SSE event`).
- **Use DOM/Text verification first**: `agent-browser snapshot -i -c`, `agent-browser eval`, and console/network logs.
- **Isolate Visual Checks**: If an image requires visual LLM inspection, spawn a dedicated short-lived subagent that opens the single image with `ReadMediaFile` and returns a text-only summary. The main session receives only the text summary, keeping context clean and fast.
